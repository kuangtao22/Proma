# 制作精度与自主恢复

本合同用于有严格约束、多轮迭代或中断恢复的任务。目标是使每一次修改有依据、每一次执行有身份、每一个结论有相称的证据。Host 的运行成功与数据覆盖不代替内容验收。

## 先确定什么能够证明交付达标

按用户用途选择制作模式后，把要求与可验证方法对应起来。沿用已有方案或节点，不为简单任务新增一整套文档。

| 要求 | 制作方式 | 验收依据 |
| --- | --- | --- |
| 氛围、风格、角色外观、镜头情绪 | 图片/视频生成及参考素材约束 | 精确版本的原图、实际视频/声音内容 |
| 文案逐字正确、固定数量、严格二维尺寸和位置 | 优先用可编辑布局、矢量或确定性合成；生成模型负责适合生成的素材部分 | 源布局、像素/坐标、文字与数量检查，再做视觉复核 |
| 零件尺寸、装配间隙、卡槽适配等几何要求 | 使用当前真实可用的建模、参数化渲染或可控工作流；生成图可用于外观探索 | 模型几何或已标定的同平面测量，并说明单位、总余量/单侧余量、误差 |
| 多镜头视听连续性 | 导演方案、镜头资产、真实首尾状态、音轨时间线 | 检查实际生成末帧及相邻镜头，不用规划帧代替实拍结果 |

不能因为工具名包含“3D”就推断具备工程精度，也不能因为一次图像失败就断言某模型完全不能做。先查询当前可用工具、模型、工作流与 Skill；缺少精确制作能力时仍完成可做的规划、配置、素材整理，明确剩余能力缺口。主 Agent 可以沿已有文件/Shell权限执行确定性制作，专业子 Agent 不自行扩大工具权限。

精确要求保留用户口径，例如“长边与短边至少20%总余量”不能改成“四周各20%”，空槽不能改成“每槽都有卡片”。只有经明确更正才能改变单位、数量、比例或容差。不要用跨平面的透视估计证明物理装配；无法标定应报告“无法确认”，不能报告确定通过或确定失败。

## 固定一次执行的输入

主 Agent 或专业规划节点先把完整可执行提示词保存到图片配置，再核对实际底图、参考顺序、模型与参数。新原生 API 图片任务由 Host 冻结该配置原文作为最终执行提示词，内部规划不会再次改写，画幅与尺寸沿用任务快照，每任务固定一张；修改目标应更新配置后创建新候选，原任务 retry 继续用原快照。旧任务保持旧合同，ComfyUI 继续使用已绑定的工作流字段。

冻结配置不等于执行器支持所有分辨率。当前 OpenAI Images 执行器按画幅映射请求像素尺寸，`imageSize` 的 1K/2K/4K 选择尚未参与该映射；不能据此承诺 GPT Image 输出 2K 或 4K。Gemini 使用其接口的 `imageSize` 参数；需要精确像素尺寸时检查实际输出，并在现有授权内选择确定性处理或可支持的工作流。

外发前的 prompt/hash/参考审计证明本地准备的实际请求，不能证明服务商收件或结果合格。最终验收要同时检查输入是否正确、产物是否满足要求。提示词超限应在原配置中去除重复措辞并保留约束，不能让系统静默截断。

## 将检查、质量与采用分开

- `existing + inspection`：检查已有候选或正式图，不宣称本轮生成。
- `updated + inspection`：合同先登记，再经运行或合法重试生成新候选，Host 记录创建身份，最后提交该 jobId 的真实检查证据。生成并检查完成不要求采用，也不表示质量通过。
- `created`：新建节点，不能把原输入节点作为新产物；导入已有图片并检查不需要额外生图。
- `adopted`：正式采用事实，与 inspection 是不同证据；用户只要候选时不得为了完成合同强行采用。

对实际候选按原验收项记录“通过 / 不通过 / 无法验证”，列明对应节点、jobId、检查方法、具体缺陷与影响。没有内容分析能力时保留“无法验证”，不凭任务成功、尺寸元数据或图片提示词宣布生产合格。只有所有必需项通过并具备采用授权时，才能采用并推进相关下游。

新一轮恢复先查持久工作流、原任务和已经存在的产物。本轮只登记仍待交付的工作；旧候选的复核用 existing，不把既有结果说成本轮新生成。若原合同缺少来源回执而无法满足 updated 检查，说明记账限制并保留真实检查结论，不为补凭据再生一张图，不伪造证据或降低已登记要求。

## 按失败原因推进，而不是重复同一个操作

| 已证实状态 | 在当前授权内继续做什么 | 继续执行的条件 |
| --- | --- | --- |
| 版本冲突、配置缺失、关系错接 | 读取当前版本，局部修正原节点，再做准备检查 | 不覆盖用户新修改，技术预检通过 |
| 服务连接错误或提交未知 | 查原 job/run 及候选，等待或补收原输出 | 只有 Host 确认失败才考虑重试，未知用量不等于零费用 |
| 已确认执行失败 | 用 failure 的阶段、原因和 nextAction 检查原节点；工作流任务通过原 run 的 resume 定向重试 | 沿用原预算、范围与幂等身份 |
| 输入约束正确但画面不合格 | 比较实际输入与候选，提出可检验的原因，修改对应提示词、参考或制作方式 | 说明本次改了什么、为什么能解决缺陷，授权与预算仍足够 |
| 检验方法不足 | 补读原图、实际视频/声音或源布局；选择精度匹配的工具 | 获得对应证据后才能作确定判断 |
| 预算耗尽或必要权限缺失 | 完成可做的只读诊断、配置准备，汇总一次明确的追加需求 | 用户批准正数扩额或必要能力后继续 |

默认至多两轮有新依据的内容修复；相同缺陷没有新的诊断或输入变化时，应改变制作方法或明确阻碍，不能重复相同提示词付费碰运气。复用原工作流预算，不能通过新建 run、独立重试其图片或换节点重置额度。自动执行设置支持预算内恢复，正数扩额仍需确认；工具的 execute 上限、remainingMediaRuns 或建议文本本身不是额外授权。

主 Agent 汇总一次交付状态，专业节点交付自己的方案或评审即可；不为每次读取、等待和检查重复创建任务清单。只复核改变影响的节点与真实下游，保留未受影响的合格素材。报告应让用户知道已经得到什么、证据能证明到哪里、下一步解决哪项具体缺口。
