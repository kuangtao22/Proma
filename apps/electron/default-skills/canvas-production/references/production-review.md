# 用途判断、制作模式与阶段评审

本参考用于复杂画布生产。核心顺序是：先理解用户要解决的问题，再选择制作模式；随后核对真实模型或工作流能接收什么输入，最后才配置和运行生成。不要根据“视频”“海报”“研究”等单个关键词套模板，也不要把所有任务都拆成多 Agent。

## 一、先判断用途，再决定生产组织

开始前读取本轮明确引用、当前画布中的真实内容和已有正式素材，并从完整语义确认：

- 目标：用户最终要得到什么，成功由什么结果证明。
- 受众与场景：谁会看、在哪里使用、需要什么比例、时长、格式或技术条件。
- 交付：本轮交付单个产物、系列资产、可执行方案、成片、代码工程，还是只做评审。
- 现有资产：哪些文档、图片、音视频或工程文件已经存在，哪些版本已正式采用，哪些只是候选。
- 授权意图：用户只要求读取和建议，还是已要求修复、生成、采用或完成整套制作；媒体授权仍以 Host 返回的真实策略为准。

依据这些事实选择最小够用的制作模式。下表是已授权规划/制作时的组织方式；只读评审用它检查适配性，不直接创建或运行这些分支：

| 用途 | 推荐组织方式 | 重点 |
| --- | --- | --- |
| 单张图、单镜头或一次试验 | 主 Agent 直接规划和执行 | 简短目标、必要输入、单次验收，不强制创建专业 Agent |
| 同主题系列图片或多项资产 | 共享规范文档加独立产物节点 | 先固定共同约束，再逐项生成和评审，避免把全部内容塞入一个节点 |
| 多镜头视频、漫剧或复杂叙事 | 主 Agent 创建或复用导演 Canvas Agent | 先交付可执行导演方案，再展开关键帧、镜头、声音和剪辑 |
| 已有素材剪辑或重编 | 先做素材盘点和时间线 | 优先复用正式素材，只为明确缺口安排生成 |
| 工程、程序规划或真实应用 | 普通 Agent 负责工程工具，画布保存可维护产物 | 区分 WebView 原型、计划文档和真实代码，不把文档节点当执行引擎 |
| 研究、采集或分析 | 先固定来源、范围、字段和验证方式 | 保存可复现证据，区分模拟验证和真实数据结果 |

模式由任务复杂度、产物之间的依赖和专业分工价值决定。一个简单视频不因“视频”二字自动需要导演 Agent；用户已授权规划、制作或修复多镜头任务，且缺少适用于当前目标和素材版本的方案时，即使没有说“导演”，也应创建或复用这一专业分支。只评审时不创建或运行导演；已有当前有效方案时直接读取评审，不重跑导演。创建或运行导演还必须符合本轮工具能力；permissionCeiling=plan 时只读取现有方案并给出规划建议，不调用执行工具，也不声称已保存或运行导演。普通 Agent 始终是唯一总编排者，导演 Canvas Agent 负责导演方案，不递归创建或运行其它 Agent。

“多镜头视频”只是生产规模，不是最终用途。导演和主 Agent 还要针对真实传播目标调整镜头与评审标准：

- 产品推广重视卖点出现顺序、产品可识别性、品牌一致性、节奏和 CTA，不能让运镜遮挡核心信息。
- 操作教程重视步骤完整、界面或手部动作可读、前后状态连续、旁白与操作同步；观众能否照做比画面炫技更重要。
- 叙事漫剧重视人物动机、表演、视线与动作连续、场景调度、对白节奏和情绪递进。
- 氛围展示重视视觉主题、构图变化、音乐节拍、空间和色彩连贯；不必强加产品片 CTA 或教程式说明。

因此，同样是十个镜头，不能共用一份只按镜头数量生成的通用评审表。应从用途推导信息优先级、节奏、连续性、声音与最终验收。

## 二、再判断真实生成模式

业务上的制作模式不能替代技术选型。进入生成前，用当前可用工具核对 API 模型或 ComfyUI 工作流的真实输入、输出、模型资源和参数，判断它支持文生图、图生图、单图生视频、首尾帧视频、音频驱动或其它模式。只按素材数量匹配不够，还要确认每项素材在工作流中的语义角色。

首尾帧不是所有视频的默认方案：

- 连续动作被拆成相邻视频段时，可以把上一段经过检查的实际末帧作为下一段输入，并记录精确资产与版本。规划中的“尾帧图片”和生成视频的实际末帧不是同一事实，仍要检查真实输出。
- 硬切、换机位、换场景、时间跳跃或蒙太奇不应强制首尾像素一致。导演应规定构图、动作方向、视线、光线、节奏或声音如何衔接，再选择匹配的生成工作流。
- 工作流只支持单图驱动时，不要虚构尾帧控制能力；工作流支持首尾帧也不表示结果必然精确落在给定尾帧，验收必须基于真实媒体。

## 三、多镜头视频的导演规划

在上一节的授权和方案缺失条件满足时，由普通 Agent 创建或复用导演 Canvas Agent，配置清楚长期职责和真实可用的专业 Skill。规划阶段使用一次 `canvas_run_agent`，任务要求导演读取直接输入及明确审核范围内的已有节点，产出正式、可读取的导演方案。不要在此阶段调用 `canvas_run_workflow`，否则可达的图片、音频或视频下游可能在方案未核对前提前运行。只读评审发现没有导演方案时，报告缺口和建议，不擅自补建。

### 导演位置、审核范围和执行依赖

导演应处于本视频制作的规划起点：需求/脚本/参考资产 → 导演方案 → 主 Agent 评审 → 资产/镜头/声音/后期 → 成片验收。这是阶段顺序，不要求全部节点都直接连到导演；不为审核添加执行依赖。

首次创建或接管导演时，主 Agent 先用 `canvas_list_nodes` 不带 `kind` 分页枚举，在同一图版本上读取真实内容，划定本任务的制作节点与审核范围。范围应包括漏连和孤立节点，不能只取导演的直接输入或可达下游。整图都属于本视频时用 `reviewScope: {mode: "canvas"}`；混合任务或后续局部复核用 `reviewScope: {mode: "nodes", nodeIds: [...]}`。显式范围每次最多128个节点，超出时分批复核并汇总所有范围，不能悄悄截断。Host排除导演自身，范围只用于读取覆盖，不扩大执行权限。

首次前置使用 `canvas_run_agent.positionBeforeNodeIds` 指定本任务制作节点（1至128个、不重复、不含导演自身）。Host只把当前导演移到所选制作节点左侧并避让其它卡片，已有合法位置保持；需求和参考资产仍可位于导演之前。空画布没有制作节点时省略此参数，先规划再创建下游。后续局部复核通常省略位置参数，尊重既有布局。位置提交使用当前revision，冲突后重读，不自动覆盖用户新布局。

### 首次读取覆盖与逐节点报告

导演通过 `canvas_get_context.review` 取得范围和 `coverage.scopeRevision`。先完成读取，再写方案，避免自己的方案写入改变基线：

1. `mode=canvas` 时分页枚举全部类型，排除自身；`mode=nodes` 时使用明确的 `nodeIds`，不能把它误作整图。
2. 按 `scopeRevision` 分批调用 `canvas_read(expectedRevision)`，检查当前正文、配置、采用版本和关系。每批最多32个节点，图片另用 `canvas_inspect_images` 每批最多4张读取真实图像；只取标题或列表不会增加覆盖。
3. 用 `canvas_get_context` 查看覆盖状态。`unreadNodeIds`、`failedNodeIds`、`incompleteNodeIds` 和 `missingEdgeSamples` 每类最多32项，是待处理样本；总数才是剩余规模。缺边按其两个端点成对补读，允许跨批累计，不能因单批 `omittedEdgeCount` 就补造业务连线。读取失败有界重读，仍失败则标记未复核；超预算正文无法完整读取时也明确阻塞，不把片段当全文。
4. 逐节点记录 nodeId、用途/镜头、实际正文或配置版本、正式素材版本、判断依据、通过/需修复/信息不足、用户影响、具体修改和复核方法。图片视觉、连续动作、真实视频末帧、音画同步等各按实际能力检查；技术可执行和内容质量分别记录。
5. 返回 `reviewCoverage` 后，主 Agent 核对总数、失败与缺失项，再读取导演方案全文和真实版本进行评审。`complete` 仅证明当前数据与关系送达，历史目录、视觉/试听与语义质量仍需各自证据。配置版本可能独立于图版本变化，生成前必须复验实际 `configRevision`、采用素材和方案引用，不能用 `scopeRevision` 代替所有版本。

图版本中途改变时，不把新旧读取合并为同一基线。报告已读范围及未复核项，由主 Agent 在当前版本补读；不能为了获得完整覆盖反复运行导演、重新生成素材或重建节点。已有有效导演方案只缺审核覆盖时，主 Agent 直接补读并更新评审即可。

后续局部复核从变更节点、真实依赖和镜头连续性确定受影响集合；例如替换产品母版检查引用该版本的镜头，改旁白检查对应片段时长与口型/字幕，独立切镜不随意扩散。沿已有授权复用导演更新必要方案时，用 `reviewScope.mode=nodes` 明确本轮范围；不重跑未变化的全部规划和生成。

导演必须把方案写成真实文档产物或本轮合法的正式文本输出，不能只在聊天里说“已规划”。若方案用于下游制作，优先保存为文档节点并建立准确关系。文档本身没有 Canvas Agent 的 `outputPointer`；只有 Canvas Agent 的正式输出使用 Host 提供的正式指针。普通 Agent 随后用 `canvas_read` 读取方案全文、版本和关系，内容截断时缩小范围重读，不能凭标题或摘要通过评审。

导演方案至少包含：

1. 项目目标、受众、叙事意图、总时长、画幅、发布渠道与交付格式。
2. 逐镜头表：镜头编号、时长、场景、景别、机位、运镜、主体动作、表演节奏、起始状态和结束状态。
3. 镜头衔接：明确连续动作、硬切、叠化、声音桥、匹配剪辑、换场或时间跳跃，并说明需保持和允许变化的内容。
4. 关键帧计划：每镜是否需要首帧或尾帧、来源节点、采用资产和精确版本；标明复用、衍生和新生成项。
5. 资产清单：角色、场景、服装、道具、品牌元素及一致性规则，区分已有正式素材、待验收候选和缺失资产。
6. 分开的提示词：图片提示词负责静态画面与一致性，视频提示词负责动作、运镜、时序和禁止项；旁白、对白、音乐与音效各自说明内容及约束。
7. 音轨时间线：对白和旁白入点、音乐段落、音效落点、静音区间、字幕及口型或节奏要求。
8. 依赖与验收：哪些产物通过后才能开始下游，哪些变化只需局部返工；逐镜说明画面、连续性、时长、声音和技术验收标准。

规划时尚未生成的资产只记录用途、来源计划和验收条件，标记“待生成”；不能编造 assetId、hash 或版本，也不要求先生成才允许完成导演方案。真实资产产生并采用后再补入精确引用，按实际模型接口细化对应提示词。进入每个阶段只检查该阶段的必要输入：资产阶段可生产缺失素材，镜头阶段必须等所需素材验收，后期阶段必须有可用镜头和音轨。

## 四、评审输出与执行边界

评审必须围绕当前用途输出四类结论：判断依据、对最终用户或交付的影响、必须修复的阻塞问题、可提升质量但不阻塞的改进建议。证据不足的事项单列为“未知”，不能猜测为通过或失败。

采用可操作的记录格式：推荐制作模式与生成模式 → 通过/需修复/信息不足 → 依据的节点与版本 → 每项问题的用户影响、局部修改办法和复核方式 → 下一步。已授权执行且需要维护多阶段方案时保存方案及评审文档；记录审查过的方案版本、关键输入版本和适用阶段，评审正文每次原地更新。单项任务无需额外创建规划和评审文档，简短说明与必要检查即可。建议要具体到镜头、节点或时间段，例如“镜头 S3 切镜前产品标识不可读，延长停留并复核标识可读性”，不能只写“优化提示词”或“增加电影感”。

分阶段评审时区分三种事实：

- 计划质量：目标、镜头、资产、时间线、依赖和验收是否完整、一致、可执行。
- 技术可执行性：当前模型或工作流是否真实支持所需输入输出，参数和素材绑定是否完整。
- 媒体内容质量：生成后的真实图片、音频、视频是否符合内容与连续性要求；`metadataOnly`、配置或任务成功不能替代观看、试听或视觉检查。

阻塞问题必须在进入受影响生成阶段前修复，例如缺少关键素材、镜头状态矛盾、工作流不支持声明输入、音画时长无法对齐。改进建议不自动阻止执行。用户已经授权修复或自动媒体生产时，评审通过后沿原授权和预算继续，不新增普遍的人工确认步骤；真实缺少授权、关键决策或可用工作流时，再按现有 Host 合同处理。

用户只要求“评审和建议”时保持只读：读取实际方案、配置、版本和媒体证据，直接在响应中给结论，不为了留下痕迹而创建报告节点，不运行、不采用、不修改。用户已要求“评审并优化”时，可在授权范围内修复有证据的问题，并重新读取受影响内容。

方案版本或上游正式资产变化后，只重审受影响镜头及其可达下游。例如 S2 的首帧资产更新，只检查依赖该版本的 S2 和后续连续段；不自动重做独立切镜。远端任务提交结果未知时查询原任务，不因评审超时或响应丢失重复提交。

`canvas_task` 用于登记和核验声明的交付证据，不等于系统已经实现生成前硬门禁，也不等于完成视觉、试听或成片验收。任务合同开始后不能临时增减要求，所以主 Agent 首次登记时应把规划、评审和已知最终交付放入同一份合同。例如用户要一部成片，可登记导演文档、评审文档的 `content` 和成片节点的 `adopted`；中间素材清单与检查结果记入方案及评审文档，若用户明确要求它们独立交付则一并登记，不能拿一份证据冒充多项交付。每个 Agent 每轮只登记一份与自身职责对应的任务；不要为了计划、技术评审和媒体评审反复启动不同合同。独立导演回合可以登记只交付导演方案的自身合同，这不改变主 Agent 对最终产物的责任。纯文本本身是交付时可使用 `response` 并提交实际正文；规划子任务完成只证明方案已交付，不代表图片、视频或最终成片已经完成。不要要求每个节点都绑定不存在的 `plan.text` 模型输入，也不要为表达评审阶段虚构节点类型、输出 key 或工具能力。

## 五、简短场景

- 单镜头产品试验：主 Agent 核对一张已采用产品图与单图生视频能力，写清动作和验收后运行；无需导演 Agent。
- 连续追逐分段：导演规定 S1 实际末帧经检查后作为 S2 首帧，并固定精确版本；若 S1 重生成，只重审依赖链。
- 对话硬切反打：两镜保持角色、视线轴和声音连续，不强制前镜尾帧与后镜首帧像素相同。
- 只读工作流评审：报告当前工作流适合什么输入、缺少什么、对结果有什么影响，不创建报告节点或启动生成。
- 已有素材剪辑：先列出可用视频、音轨和缺口，建立剪辑时间线，仅对缺失过场或声音安排生成。
- 已授权自动制作：导演方案和技术检查通过后，在原媒体策略和预算内自动推进、检查并按授权采用；不为常规步骤重复询问。
