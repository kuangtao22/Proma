# 专业设计与连续性交接

本参考把美术、服装、场景和动作等专业工作接到真实产物链。适用于人物、产品、空间及连续叙事相关的图片或视频，包括小红书宣传、漫剧和电影；不按平台名称固定角色数量。编排者维护计划和交付，导演统筹创意与叙事，美术指导统一视觉标准，专业分支交付当前职责的设计与评审。

## 一、先判断适用性和工作规模

先读原目标、约束、脚本、现有设计和正式素材，再记录“专业职责 → 适用理由 → 当前缺口 → 负责方式 → 成果位置 → 验收条件”。复杂项目放入现有设计或计划正文；单项任务可以简短记录，不为检查表额外创建 Agent 或空白节点。

每项明确选择：

- 不适用：有具体依据，例如纯产品静物没有人物造型，不需要服装设计；仍需判断布景、道具和光线。
- 复用：读取与当前需求一致的既有设计，注明真实节点、正文/素材版本及适用范围；标题相同不能证明可复用。
- 合并负责：简单操作、少量角色或单一空间可以由导演或同一专业步骤完成多个设计章节，分别给出验收条件。
- 独立分派：多套服装、多场景、复杂产品操作、舞蹈、打斗、多人互动或反复出现一致性问题时，依据专业价值与预算拆分工作。需要独立迭代、验收和复用的成果才拆成独立节点。

不把“需要专业判断”理解为“必须新建专业 Agent”。UI、运营策划、计划及业务流程沿本领域职责和验收；影视专业只在任务实际包含相应内容时适用。预算不足时复用或合并职责，明确尚未完成的工作，不能省略关键验收后宣称完成。

## 二、各专业负责什么、交付什么

| 职责 | 可核对的设计成果 | 关键验收 |
| --- | --- | --- |
| 美术指导 | 世界与时代背景、风格、色彩、材质、角色与环境的视觉关系、固定特征和允许变化 | 各专业与叙事、品牌和用途一致，不只写“电影感” |
| 角色设计 | 角色身份、体型比例、面部与轮廓特征、可区分的标记和当前参考 | 跨镜头身份可识别；候选图不冒充已采用标准 |
| 服装与造型 | 服装款式、层次、颜色材质、发型、妆容、配饰，按剧情场次记录干湿、破损、换装等状态 | 符合人物与时代，支持动作需要，变化有叙事依据 |
| 场景设计 | 空间结构与尺度、出入口、家具陈设、人物和产品可活动区域、时间天气、主光方向 | 机位与动作在同一空间中可实现；关键物体位置不随镜头漂移 |
| 道具设计 | 形制、尺寸、用途、可操作部位、放置/持有者及状态变化 | 产品操作可完成，外观与功能一致，持有和交接可追踪 |
| 动作指导 | 动作段、起始状态、顺序与节奏、左右手、重心、朝向、接触关系、结束状态和衔接 | 动作可读、因果连贯，无无故换手、跳位或物体穿透 |
| 表演指导 | 动机、情绪变化、表情、视线目标、停顿与反应、人物间的互动 | 表演服务叙事或卖点，反应顺序与对白/动作相符 |
| 镜头与摄影灯光 | 镜头编号、时长、景别、机位/运镜、轴线、构图、光位，以及所引用的设计版本 | 拍清动作与信息，维持空间、视线和光线关系，转场有明确意图 |

这些内容可以是文档正文或专业 Agent 的正式输出；视觉参考按任务所需创建或复用真实图片。动作指导描述怎么动，表演指导描述为什么动和如何反应，镜头设计描述怎么拍；三者需要整合，不能互相替代。

## 三、通过现有步骤和产物交接

1. 根据脚本与现有资产列出必要专业工作。创意、脚本、美术、动作、镜头可以按确定的输入迭代草稿，不把相互反馈直接接成执行环；需要回改时修订原步骤，再复核受影响下游。
2. 持久编排用 `canvas_update_plan` 把职责与交付写入 `role`、`instruction`、`criteria`。相关细则直接写入分派任务，不只写“请阅读某 Skill”；专业分支不保证自动加载制作参考。只使用已提供的工具和真实可读的参考，不编造专业 Skill 名称或路径。
3. 专业步骤通过 `inputNodeIds` 引用已有需求、设计和素材，通过 `dependsOn` 引用必须先验收的专业步骤。`canvas_dispatch` 会将依赖步骤的正式输出一并送达；每个镜头只依赖其实际需要的设计。共用资产和审核关系不等于需要把全图全部串成一条链。
4. `outputNodeIds` 仅登记实际产物及真实创建回执。尚无产物时保持空数组，名称、角色或占位卡片不算完成。同一文档只归一个步骤；其它步骤把它作为输入，合并设计用章节标识职责，不能让每个专业同时认领或覆盖同一产物。
5. 专业分支先复读指定输入和已有成果，补齐本职设计，交付时说明依据的节点与版本、设计正文、适用镜头、验收条件及未解决问题。需要其他专业时向编排者提出具体缺口，不自行创建下级 Agent 或启动媒体。
6. 编排者在 `needs-review` 后读取真实正文和所需视觉参考，按内容评审，再用 `canvas_review_step` 通过或退回。步骤状态、产物版本存在、角色名称和运行成功均不证明设计质量。专业设计不替代原合同中的最终成片或其他交付物。

镜头表至少记录：镜头编号 → 角色/服装/场景/道具对应的设计节点、真实版本与章节 → 动作段 → 表演要求 → 连续性固定项和允许变化 → 需要的真实素材 → 生成与验收条件。镜头和动作段编号是设计文档内的语义标识，不是新增工具字段或节点类型。

设计正文引用与模型素材绑定是两层事实。配置图片/视频任务时，还要按真实模型或工作流核对角色图、服装图、场景图、道具图分别作为何种输入；文字中列出设计版本不等于图片已经发给模型。工作流无法接收所需素材组合时，选择实际支持的制作方法或明确阻塞，不混淆参考素材身份。

不能把待生成资产作为设计完成的前置条件。设计阶段可以先明确资产规格、来源计划与验收条件，缺失素材标记待制作；资产阶段依据已评审设计制作并验收参考，镜头生成前再核对该镜头必需设计与正式素材，后期阶段再要求可用镜头和音轨。不为提前凑齐引用编造 nodeId、assetId、hash 或版本。

## 四、动作段与跨镜头连续性

有动作的段落至少写清：人物及动机、起始状态、按顺序的动作节拍、左右手与接触点、道具和空间状态变化、结束状态、表情视线及下一镜如何接续。服装限制、场景通道或道具尺寸影响动作时，反馈给对应专业修订；不能靠提示词让不可能的空间或操作关系自动成立。

例：小红书开包取物，动作段 A1 对应镜头 S1–S2：

- 起始状态：角色穿既定造型，左手握包提手，包放在桌面，拉链闭合，产品在包内右侧。
- 顺序与节奏：右手打开拉链，短暂停顿展示开口，再用右手取出产品；左手持续稳住包，不在镜头间无故换手。
- 接触与状态：拉链头随动作移动，产品从包内移到右手，包保持打开；手指与物体真实接触，衣袖不能遮挡关键操作。
- 结束状态：右手持产品朝向观众，左手仍扶包；视线由包内转到产品，表情与展示意图一致。
- 衔接：S2 切到产品特写，保持持有者、产品朝向和包的开合状态；机位和构图可变，不要求两镜像素相同。

连续动作与硬切、换场、时间跳跃分别处理。连续段核对动作方向、进度、接触、道具状态；剧情换装、破损或物品交接属于允许变化，但须注明发生时点和前后状态。规划尾帧与实际视频末帧分开记录，不能将计划图片当作生成视频已经达到的结束状态。

## 五、生成前后验收与局部修订

生成前检查当前镜头的设计是否可执行、引用是否仍有效、必要素材是否通过验收、真实工具是否支持该输入组合。设计阶段的方案完整不代表媒体已完成，已采用素材也不自动代表质量通过。

生成后检查实际视频或图片：人物与服装是否一致，空间和出入口是否稳定，道具是否跳位或变形，动作顺序与接触是否正确，视线与反应是否连贯，关键动作是否被运镜或衣物遮挡。记录镜头/时间段、所见问题、依据的真实素材与版本、影响、修订责任和复核方式。

静态首尾帧不能证明中间动作、舞蹈节奏或打斗接触正确。当前工具只提供抽帧时，`sampled` 只支持所见样本范围；未看到的动作、完整节奏及未听取音轨写明未验证。最终交付要求 `full` 时保留此要求，能力不足明确阻塞，不用动作指导文档、元数据或抽样通过来代替完整视听验收。

设计变化后先按引用与连续段找影响范围，例如服装变化检查使用该造型的镜头，场景通道变化检查依赖该空间的走位和机位，取物动作变化检查对应手位、道具状态和相邻连续镜头。复用未受影响成果；合并文档当前按整份正文版本失效，章节引用方便定位，但不能声称 Host 已具备章节级版本隔离。需要独立迭代时再拆成真实独立产物，不无故扩散为全片重新生成。

接管旧画布时先审计现有导演稿和设计章节，补缺口与真实输入登记，不因缺少新模板重建。需传递用户后续要求时沿原委托 `followUp`，不改写原目标或重新委托。只读评审保持只读；设计、媒体授权和预算继续使用既有 Host 合同，不因启用专业指导而提升权限。

## 六、按场景选择最小够用的流程

- 小红书人物宣传：根据产品卖点检查服装与品牌关系、布景、产品操作和表演；简单开包可合并负责，复杂穿搭变化或操作再独立分派。
- 漫剧：建立角色、服装、场景和道具的共享设计，按剧情组织动作与表演，镜头引用对应版本；角色在不同集数的状态变化需要明确记录。
- 电影：按场次维护造型、场景、动作与表演连续性；追逐、舞蹈、打斗或多人调度按复杂度分派，明确摄影视角和声音衔接。
- 纯产品静物：人物服装和表演通常不适用，仍检查布景、道具尺度、材质和灯光；产品有开合或运动时补动作设计，不套人物造型节点。
- 单镜头简单展示：在当前方案中写清必要设计和动作验收，直接沿已授权流程执行，不为角色清单启动整队 Agent。
- UI、策划或计划：继续信息结构、交互状态、资源、里程碑等本领域流程，不机械插入导演、美术或动作步骤。
