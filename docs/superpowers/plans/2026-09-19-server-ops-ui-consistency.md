# 运维模块 Proma 风格统一实施计划

**目标：** 保留项目、SSH 能力、MySQL 工作台和 Redis 语义，统一运维模块的视觉层级、密度与响应式布局。

**依据：** Proma 的 SidePanel、SettingsUIConstants、Button、Tabs、Dialog 和 globals.css 主题变量。通用 SaaS 规范的蓝色、4px 圆角、1100px 最小宽度不适用于本项目；不引入新字体、配色或依赖。

**方案：** 仅改颜色无法解决重复层级，重建导航会破坏已经确定的使用路径；采用保留信息架构、统一展示组件样式并合并重复标题的方案。公共样式只作用于运维组件，不改变全局 UI primitives，不修改控制器、IPC、权限、轮询和数据库访问。

## 实施范围

- [x] 建立 server-ops-ui.ts：复用主题 token 的工具栏、页签、分段控制、卡片、表格与底部状态栏 class 常量。注释用中文，不加入运行时订阅。
- [x] 项目入口与抽屉：统一分组层级、连接行、计数、空态；维持项目筛选与点击路由。
- [x] SSH 服务器工作区：统一身份栏、能力页签、审计过滤与行排版；工具栏在窄面板内收缩，长列表内部滚动。
- [x] 服务器能力页：统一概览、服务、日志、文件、传输、Docker、终端的工具栏、表格、状态和卡片；保留终端主题与所有确认路径。
- [x] MySQL/Redis：连接头使用 content-area，诊断移除重复标题，将概览/会话/慢语句/日志导航与刷新合并，实例参数保留作用域说明。表浏览使用一致的目录、表头、分页；MySQL 指标按面板宽度三列/两列，Redis 保留独立诊断语义。
- [x] 连接与信任弹窗：统一分组、字段间距、底部操作；保留测试在左、取消/保存在右、密码显隐、指纹确认与安全提示。

## 验证

- 修改前运行既有运维 renderer 测试作为回归基线；仅在交互语义变化时补行为测试，不为 CSS 字符串写镜像测试。
- 修改后运行相同测试、Electron typecheck、renderer build 与 diff whitespace 检查。
- 隔离 Electron 使用示例数据验证项目/服务器/数据库/Redis 页面和弹窗；检查 320/460/720/1024px 面板、深浅主题、键盘焦点、无横向溢出，以及宽窗口内的窄面板。
- 不连接用户真实服务器或数据库，不读取或输出真实凭据；不重启用户客户端，不提交无关 WIP。

## 风险与性能

公共样式采用显式 import，不用全局 button/table 覆盖；原始日志和终端保持等宽及内部横向滚动。展示层样式不改变请求时机、分页预算或持久化格式。布局通过 CSS 容器查询适配，不增加 ResizeObserver、计时器或请求。
