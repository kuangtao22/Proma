# SQL 输入校验

用户已确认实施。目标是在 SQL 工作台输入停顿后显示可定位的中文诊断，并在执行按钮旁提供独立「校验」入口。

## 实施边界

1. 扩展既有共享 SQL parser 的安全诊断与 UTF-16 位置；前后台共用解析规则，不新增 SQL 语法范围或依赖。
2. 语法、能力范围与查询策略诊断阻止执行；缓存表/字段提示仅作提醒，不作为数据库当前结构或权限的依据。
3. 编辑器原位显示诊断下划线，可点击提示定位；自动校验防抖、避开 IME，修改/切库立即隐藏旧诊断。
4. 校验不访问数据库、不执行 SQL、不保存历史。执行入口同步检查最新草稿，后台仍独立实时验证。
5. 数据库异常只映射已知稳定码，区分权限、表/字段缺失、语法及不支持，不回显驱动原文。

## 影响与性能

- 不改变查询、取消、只读事务、行数/超时预算、Agent 授权与审计边界。
- 复用已有结构快照，不因校验加载全库字段；共享 parser 保留长度与复杂度预算。
- 状态只属于当前 Pane，防抖定时器卸载时清除，不持久化诊断或查询结果。

## 验证

- BDD：错误位置/分类，合法 JOIN/别名，敏感列与跨库保护，缓存缺失/截断/未知字段，以及校验不执行和不写历史。
- 相关单元回归、Electron 类型检查与构建；真实 Electron 组件验证按钮、快捷键、IME、切库与窄宽布局。
- 检查运行中的 Agent 后更新开发构建；不执行用户数据库 SQL。

## 完成证据

- 共享解析器、编辑器校验、查询/历史/补全控制器、MySQL runtime、IPC 与 Agent facade：12 个文件共 232 项测试通过。本机 mysql2 模拟服务验证握手权限失败与非法 SQL 均不发出业务查询。
- Electron 类型检查、完整 `bun run electron:build` 与 `git diff --check` 通过；全仓类型检查仅保留既有 `canvas-media-model-scope.test.ts:46,68` 的两处 readonly 类型错误。
- 隔离 Electron 真实组件通过自动/手动校验、错误位置选择、校验不读取数据库/不写历史、切库、IME、快捷键、补全、查询取消和历史回归；320/460/1024 宽度深浅主题及 360 高度滚动检查通过。
- 独立复审批准。复审发现的握手错误分类、可见表别名与切库 effect 前执行窗口已补回归并修复。
