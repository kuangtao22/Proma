# 运维 Agent 第一批场景扩展实施计划

**目标：** 接通连接草稿、服务发现、有界日志排查，并将数据库变更限定为结合程序与表结构生成脚本/程序。

**设计：** 复用 Proma 现有运维配置表单、SSH 服务、只读授权与审计；连接草稿仅保存于内存，凭据由用户在运维面板填写。数据库工具继续只有受限 SELECT 和结构读取，不增加写入执行能力。

**技术栈：** Bun、TypeScript、Electron IPC、Pi Agent、React、Jotai，沿用现有组件和主题，无新增依赖。

## 范围与影响

- 本批落实此前建议的前三项；部署、备份、后台巡检不在本批。
- 数据库修改产物要基于已授权表结构和实际程序模型、验证规则及迁移约定；未取得程序代码或完整结构时明确缺口，不能声称已完成业务验证。
- 保留当前未提交的运维导航布局；保留用户 `.gitignore` 修改。
- 连接草稿不保存凭据、不自动建连、不自动授权；选择/保存仍由现有表单完成。
- 日志需独立 `readLogs` 授权，历史 SSH 概览授权不自动扩大。日志输出受时间、行数、字节和执行时间限制，不开启长期流。
- 服务发现只访问指定已授权主机，复用 systemd 与 Docker 元数据，不扫描网段。
- 不启动后台轮询、不新增依赖、不在真实数据库或服务器上验证。

## 实施步骤

- [x] 连接草稿：定义严格非敏感字段合同；主进程绑定真实会话身份并维护有界内存草稿；增加 Agent 工具和只允许当前会话接收的面板联动，预填现有 SSH/数据库编辑器。测试额外敏感字段、过期/跨会话、表单草稿覆盖和项目归属。
- [x] 服务发现：增加 Facade 只读入口，聚合有界服务与容器信息，保留各来源的能力与失败状态；复核运行、授权和连接代次，不能把部分结果声称为全量。
- [x] 日志快照：复用固定日志模板实现一次性快照；限制来源、时间与行数；新授权字段、UI 与审计同步接通。测试注入、未授权、取消、撤权、超量、输出脱敏。
- [x] 数据库变更上下文：增加仅组合已有结构读取的工具，提供引擎与表结构证据及脚本产物要求；数据库不执行写操作，不返回凭据。规范模型先核对程序，再生成预检查、迁移/修复、验证与可行的恢复说明。
- [x] 工具集成：Pi 注册、受限模式白名单、宿主工具准入同步更新；普通/受限/自动化/委派会话边界保持清晰。
- [x] 验证：先执行新增 BDD 回归，再执行相关 Agent/运维测试、全仓类型检查和隔离构建；复核 IPC 四层契约及 UI 预填行为。构建不覆盖运行中客户端产物，不中断在途任务。

## 验收标准

1. 用户可让 Agent 生成 SSH/MySQL/SQLite/Redis 连接草稿，在所属会话的运维面板审阅并保存；不存在 Agent 凭据输入或直接配置写入路径。
2. 服务发现与日志仅作用于已授权主机，取消和撤权后不会返回迟到内容；无日志授权不能读取日志。
3. 数据库变更上下文只读取表结构，拒绝越权目标和夹带执行参数；只读模式仍拒绝 Shell、文件写入及任意 MCP。
4. 脚本生成指导要求真实项目代码证据，未审查、未执行、未验证分别准确标记，不能把生成成功描述为数据库修改成功。
5. 正常路径和主要边界测试通过，类型检查及相关构建有新鲜证据。
