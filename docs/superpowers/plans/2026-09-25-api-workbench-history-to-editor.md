# 接口工作台 B9：历史载入编辑器（实施计划）

> 前置：阶段 A 的「尚未交付」清单里明确写着 **历史载入编辑器**；阶段 B6 也留着一条「按历史快照重跑」未交付。
> 本轮做的是这两条的共同解法：不是拿旧快照偷偷重放，而是**把那次运行的真实请求还原成一份可编辑草稿**，让人补回被遮罩的秘密后再发。
> 状态：**已交付**（提交信息 `接口工作台（B9）：历史载入编辑器`，验收记录见第 6 节）。

## 1. 为什么不能直接「按历史快照重跑」

运行记录里保存的是**已解析并脱敏的请求**：敏感 Header 的值是 `[REDACTED]`，URL 里的秘密是 `%5BREDACTED%5D`，正文里的秘密同样被遮罩。拿它重放要么发出一条带着字面量 `[REDACTED]` 的假请求，要么就得把秘密明文落盘——两条路都不能走。所以正确的形态是「载入 + 提示重填 + 人确认发送」。

## 2. 目标行为

1. 运行头部新增「载入编辑器」：把该次运行的**实际生效请求**还原成一份**新的未保存草稿**（不覆盖任何已保存定义）。
2. 还原方法/URL/Query/Headers/正文；鉴权不再作为「auth 配置」恢复（它已经体现在那次请求的 Header 里），草稿里会说明这一点。
3. 任何被遮罩的位置（Header/Query/正文/URL）**不写回字面量 `[REDACTED]`**：保留名称、清空取值，并在提示条列出「需要重新填写」的具体位置。
4. 只做草稿，不自动发送、不自动保存；用例与目标环境标记属于原定义，不随快照复制。

## 3. 分层改动

- 纯函数 `draftFromRun(run, catalog)`（渲染层模型）：解析已解析请求 → 草稿 + 待重填位置列表；可单测，不触碰 IPC、不发网络。
- `ApiWorkbench.tsx`：运行头部按钮 + 新建未保存标签 + 提示条；切到请求区。
- 无需改共享合同、主进程、preload、传输层与打包。

## 4. 明确不做

- 用历史快照自动重放（含「按旧版本定义重发」）——秘密不在记录里，自动重放必然要么发假请求要么落盘秘密。
- 把历史运行「另存为已保存请求」的一键操作（用户可载入后用现有「保存请求」完成，避免自动写入项目资产）。
- 用例、目标环境标记、Cookie、运行时变量的恢复。

## 5. 验收标准

1. 单测：URL/Query/Headers/正文/方法还原正确；被遮罩的位置清空并列入待重填；草稿里绝不出现 `[REDACTED]`；不复制用例；未绑定目录时仍可用。
2. 界面 smoke：打开一次运行 → 点「载入编辑器」→ 出现新的未保存标签，URL 与请求头已还原，提示条列出待重填位置。
3. 定向回归、`bun run typecheck`、`bun run electron:build` 通过。

## 6. 已交付与验收记录（2026-09-25）

已交付行为：

- 运行头部新增「载入编辑器」：把该次运行的**实际生效请求**还原成一份**新的未保存标签**（永不覆盖已保存定义），并立刻切到请求区。
- 还原内容：方法、URL（origin + 路径 + hash）、Query 行（从解析后的 URL 拆回）、Header 行（含 Host 生成的 `Content-Type`）、正文（按 `Content-Type` 推断 json/text）、超时与重定向设置。鉴权不再作为 auth 配置恢复（已体现在那次请求的 Header 里），用例、目标环境标记与自动 Cookie 属于原定义，不复制。
- **被遮罩的位置绝不写回假值**：Header/Query 行留空并**取消勾选**（宁可少发，也不发出空值或假值），URL 与正文里的 `[REDACTED]` / `%5BREDACTED%5D` 换成 `{{REDACTED_SECRET}}` 占位符——这个名字不可能是已声明变量，prepare 会在解析阶段直接拒绝。提示条逐条列出「必须重新填写」的位置。
