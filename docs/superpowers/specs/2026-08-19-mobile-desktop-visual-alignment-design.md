# Proma 手机端与桌面端视觉统一设计

## 目标

在不改变 LAN Bridge 认证、会话、消息和流式传输协议的前提下，让 `apps/mobile` 与 Proma 桌面端使用一致的视觉语言，同时保留手机端适合触控、窄屏和安全区的布局。

成功结果：用户在手机端和桌面端之间切换时，能通过相同的颜色层级、几何、排版、图标和交互状态识别为同一产品；手机端仍然是单列、抽屉式、适合单手使用的界面，而不是桌面布局的缩小版。

## 已确认方向

- 采用“同设计系统，手机原生布局”方案。
- 手机端同时支持浅色和深色，默认通过 `prefers-color-scheme` 跟随手机系统。
- 不同步桌面端当前选中的特殊主题，不新增 WebSocket 协议、IPC 或设置持久化字段。
- 不直接导入桌面 Renderer 的完整 CSS，避免桌面内部重构直接破坏手机端。
- 不改变扫码免 PIN、可信设备长期续签、消息加载、流式输出、模型选择和权限模式行为。

## 设计原则

### 一致的产品语言

手机端使用与桌面端相同的语义层级：`background`、`content-area`、`sidebar-surface`、`input-surface`、`card`、`popover`、`foreground`、`muted-foreground`、`border`、`primary`、`destructive`。组件只引用语义变量，不直接写死页面颜色。

基础圆角使用 6px，弹层和输入容器最多使用 8px；不再使用大量 `rounded-xl`、`rounded-2xl` 或装饰性渐变。阴影只用于抽屉、弹层和浮起输入区，正文区域保持平整。

### 手机优先布局

视觉与桌面统一，空间结构仍按手机设计：固定顶栏、单列消息区、左侧抽屉、底部输入区和底部模型选择弹层。所有主要触控目标的有效区域不小于约 40px，并继续处理 `safe-area-inset-top` 与 `safe-area-inset-bottom`。

### 低耦合维护

主题映射集中在手机端全局样式中，组件不读取桌面端 CSS 文件。桌面端未来更新视觉变量时，只需审阅并更新这一处映射，不影响 LAN 协议或认证实现。现有 fork 兼容检查继续保护移动端构建入口和协议能力，不把桌面组件内部类名纳入跨端契约。

## 主题架构

### 语义变量

`apps/mobile/src/index.css` 定义默认浅色变量，并在 `@media (prefers-color-scheme: dark)` 中覆盖深色变量。变量值以桌面端默认浅色和默认深色主题为基准，同时保留移动端安全区变量。

浅色层级：

- 页面与内容区以接近白色的中性表面为主。
- 抽屉、顶栏和输入区使用略有区分的表面色。
- 边框保持低对比，主要操作使用深色前景。

深色层级：

- 消息内容区使用最深表面。
- 顶栏和抽屉比内容区略亮。
- 输入区、工具块和弹层按浮起层级递增亮度。

浏览器通过 CSS 媒体查询自动响应系统主题变化，不需要 React 状态、localStorage 或服务端请求，因此不存在主题初始化闪烁和跨连接状态竞态。

### 排版与图标

字体沿用桌面端的系统字体回退顺序，以 `-apple-system`、`BlinkMacSystemFont`、`SF Pro Text`、`PingFang SC` 和通用 `sans-serif` 为主，不新增字体资源下载。

手机端声明使用仓库中已经存在的 `lucide-react` 版本，替换手写 SVG、emoji 状态图标和渐变文字头像。常用动作使用 `Menu`、`ChevronDown`、`X`、`RefreshCw`、`LogOut`、`Search`、`Send`、`Square`、`Check` 等图标，并提供可访问名称。

## 页面与组件

### 连接页

- 使用完整视口的安静表面，不放入装饰性大卡片。
- Proma 名称是首屏主标识，副标题说明当前为桌面连接。
- 扫码配对进行中时，优先展示连接状态和加载反馈；手工地址、端口与 PIN 仍作为清晰的回退流程。
- 输入框、主按钮、错误提示和说明文字沿用桌面设置页的语义层级。
- 继续保留现有 label、输入模式、最大长度、禁用和错误行为。

### 顶栏与会话切换

- 顶栏高度约 48px，左侧菜单按钮、中间会话标题与连接状态、右侧下拉提示。
- 标题使用单行截断，连接状态使用小号次级文字，不与标题竞争。
- 会话下拉保持现有数据与行为，只调整为桌面弹层表面、6px 圆角和紧凑行高。

### 抽屉

- 表面、边框、选中态和行密度参考桌面左侧栏。
- Agent/Chat 使用紧凑分段控件；工作区使用横向可滚动筛选项。
- 新建会话、刷新、断开等操作改为图标加必要文字，移除 emoji。
- 会话标题、更新时间和状态标识保持清晰层级；空状态不制造占位数据。

### 消息区

- AI 正文采用接近桌面端的无大气泡排版，使用小型 Proma 标识、模型和时间作为元信息。
- 用户消息保留克制的强调表面和右对齐，圆角不超过 8px。
- 思考过程使用可折叠次级区域，工具调用使用低对比边框块；不使用紫色渐变或 emoji 作为主要语义。
- 流式消息与历史消息使用同一视觉结构，避免流式开始或结束时发生布局跳变。
- Markdown、代码块、长链接和超长单词必须在窄屏内换行或横向滚动，不能撑破页面。

### 输入区与模型选择

- 输入区采用桌面 ChatInput 的移动版：文本区、底部工具栏、模型、权限和发送/停止控制组成一个稳定容器。
- 容器使用 8px 圆角和语义输入表面；发送与停止按钮保持固定尺寸，内容变化不能导致布局移动。
- 键盘弹出时输入区保持可见，文本区高度在既有上限内增长。
- 模型选择器改为底部弹层，包含搜索、渠道分组、选中状态和空结果；最大高度受视口约束。

## 状态与错误处理

- 连接页覆盖扫码验证中、扫码失败、PIN 提交中、连接超时和认证失败。
- 聊天区覆盖未选择会话、历史加载中、历史加载失败但保留旧内容、断线重连和认证撤销。
- 网络暂时不可用时保留长期设备认证材料；只有明确认证失效或桌面撤销时回到连接页。
- 禁用控件仍可识别，加载状态不改变按钮或工具栏尺寸。
- 浅色和深色下错误色、次级文字和边框都保持可读对比度。

## 代码边界

主要修改范围：

- `apps/mobile/src/index.css`：主题变量、基础排版、滚动条和少量跨组件状态样式。
- `apps/mobile/src/components/layout/AuthPage.tsx`：连接页视觉与状态层级。
- `apps/mobile/src/components/layout/AppShell.tsx`：顶栏和主内容表面。
- `apps/mobile/src/components/layout/Drawer.tsx`：抽屉、分段控件、会话列表和底部操作。
- `apps/mobile/src/components/conversation/ChatView.tsx`：消息区空态、加载态和流式消息结构。
- `apps/mobile/src/components/conversation/MessageBubble.tsx`：消息、思考和工具区域视觉。
- `apps/mobile/src/components/conversation/InputBar.tsx`：输入区、模型底部弹层和图标。
- 相关测试文件：锁定主题变量、关键状态、可访问名称和不变行为。

不修改 LAN Bridge 主进程认证、设备仓库、协议版本、IPC、Preload 或桌面 Renderer 业务组件。

## 测试与验收

### 自动化验证

- 为主题变量增加静态契约测试，确认浅色、深色和关键语义变量存在。
- 为连接页、抽屉和输入区增加 BDD 组件测试，覆盖正常、加载、错误、禁用和主要交互。
- 保留并运行现有扫码、认证恢复、会话加载、消息与输入行为测试。
- 运行移动端相关测试、移动端 TypeScript 检查和生产构建。

### 视觉验证

使用真实构建页面在以下视口检查浅色和深色：

- `390 × 844`：主目标手机尺寸。
- `375 × 667`：较矮手机，验证键盘前的垂直空间。
- `320 × 568`：最窄支持尺寸，验证长标题、模型名和按钮。

逐页确认：连接页、抽屉、聊天、工具块、思考区、输入区、模型选择器、空状态和错误状态。检查无文字溢出、无控件重叠、无不可见操作、无横向页面滚动，并确认移动端构建由 `29888` 实际提供。

## 性能与资源影响

- 主题切换由 CSS 媒体查询完成，不增加 React 重渲染、WebSocket 消息或磁盘读写。
- 使用已经存在于仓库依赖树中的 Lucide 图标并由 Vite tree-shaking，只打包实际引用图标。
- 不增加图片、远程字体、动画库或运行时主题同步模块。
- 消息列表和 Markdown 渲染逻辑保持不变，本次改动不扩大数据请求或流式处理开销。

## 上游兼容性

本次改动只位于 fork 自有的 `apps/mobile`，不会修改官方桌面业务链路。移动端主题采用语义映射而非复制桌面完整样式表，减少官方 CSS 类名变化导致的冲突。每次合并官方版本后，通过现有移动端构建、LAN 协议测试和 fork 兼容检查确认移动入口仍完整，再按需要审阅视觉变量差异。

## 非目标

- 不实现桌面特殊主题的实时同步。
- 不把桌面多栏布局压缩到手机。
- 不新增手机端主题设置页。
- 不重写消息、Markdown、会话或认证数据模型。
- 不增加附件、工具审批或其他新业务功能。
