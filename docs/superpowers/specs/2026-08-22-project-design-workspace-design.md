# 项目级设计工作区设计

## 目标

将 `Xiangyu-CAS/codex-canvas` 的无限画布、图片编排、批注和版本关系能力移植为 Proma 原生「设计」工作区。设计工作区以项目为归属单位，与项目内 Agent 会话共享素材和任务上下文，但不依赖 Codex CLI、Codex app-server、独立 MCP 进程或本地 HTTP 服务。

首版形成完整闭环：用户在当前项目中打开设计画布，导入或生成图片，进行编排和局部编辑，查看任务与版本关系，再将素材发送到项目会话或导出原图。

## 产品边界

- 一个 Proma 项目对应一个设计画布；画布不属于单个 Agent 会话。
- 每个素材记录来源会话和来源任务，项目内不同会话可以复用同一素材。
- 设计工作区通过顶部项目标签打开，不占用左侧主导航。左侧继续只负责项目与会话选择。
- AI 生成和编辑通过 Proma 的 Pi Agent runtime 执行，并形成用户可见、可取消、可追踪的项目任务。
- 首版包含图片导入、无限画布编排、选择、多选、缩放、分组、批注、版本关系、AI 生成、局部编辑、失败重试、发送到会话和导出原图。
- 首版不包含 OCR 改字、元素分层、PSD 导出、多人实时协作、PPT 或 draw.io。

## 入口与布局

顶部工作区标签增加项目级 `设计 · <项目名>` 入口，与草稿和当前会话标签并列。该标签绑定稳定 `projectId`，不绑定当前 `sessionId`。

```text
左侧项目/会话列表 | 顶部：草稿 | 当前会话 | 设计 · 项目名
                  |---------------------------------------
                  | 中央设计画布       | 右侧设计面板
                  |                    | 素材 / AI 编辑 / 版本
```

- 用户切换左侧项目时，顶部设计标签和画布自动切换到新项目。
- 用户切换同一项目内的会话时，设计画布保持不变。
- 用户从设计切回会话时，右侧恢复现有项目文件面板；回到设计时，右侧恢复素材、AI 编辑和版本面板。
- 设计与会话切换不终止正在执行的 Agent，也不丢失画布视口、选区或未完成的输入。
- 没有选中项目时不显示设计标签，避免产生无归属画布。

## 画布交互

中央区域使用完整无限画布，不嵌入 BrowserPanel，也不使用 iframe。

- 支持选择、框选、多选、拖动、缩放、画布平移、复制、删除、分组、撤销和重做。
- 图片节点使用稳定尺寸和缩略图；放大检查或导出时才读取原图。
- 选中图片后，右侧显示素材信息、AI 编辑、版本和导出操作。
- 选中空白区域时，右侧显示图片生成入口和项目素材。
- 局部编辑首版提供箭头批注和画笔蒙版；编辑结果作为源素材的子版本放入画布。
- AI 任务在画布中使用固定尺寸占位节点，明确展示排队、运行、成功、失败、取消和重试状态。
- 素材可以发送到项目内任意 Agent 会话；Agent 会话中的图片也可以加入项目画布。

## Renderer 架构

设计模块使用 React、Jotai、现有 Radix/shadcn primitives 和主题变量，不复用 Codex-Canvas 的原生 DOM 状态管理。

建议按职责拆分：

- `DesignWorkspaceView`：项目级页面容器，负责当前项目、加载状态和右侧面板模式。
- `DesignCanvas`：画布视口、节点渲染、选择、缩放和平移。
- `DesignAssetNode`：图片、任务占位和缺失素材节点。
- `DesignToolbar`：选择、批注、撤销、重做和导入操作。
- `DesignInspector`：素材、AI 编辑和版本标签。
- `design-atoms`：按 `projectId` 隔离画布、选择、视口、任务和未保存状态。
- `design-adapter`：Renderer 到 Preload 的唯一接口，不直接读取文件或订阅 Pi runtime。

顶部标签可扩展现有 Tab 模型，但必须把项目级工作区与会话级 Tab 区分开。设计标签持久化时只保存 `projectId` 和激活状态，不伪造 `sessionId`。

## 主进程与 IPC

设计功能遵循 Proma 四层 IPC 契约：

1. `packages/shared` 定义通道、请求响应、画布状态、素材、版本和任务类型；
2. `apps/electron/src/main/ipc.ts` 注册 handler 并验证窗口、项目和路径权限；
3. `apps/electron/src/preload/index.ts` 暴露最小类型安全 bridge；
4. Renderer 通过 `design-adapter` 调用并更新 Jotai 状态。

主进程提供受限能力：

- 加载和保存项目画布；
- 导入、读取、缩略、导出和删除受管素材；
- 创建、查询、取消和重试 Design Job；
- 将素材附加到目标项目会话；
- 从受信任的 Agent 工具结果收集图片。

Renderer 不提交任意数据根或不受限绝对路径。所有文件操作先解析 `projectId`，再由主进程得到项目根和允许目录。

## 数据存储

正式数据随项目迁移：

```text
<project>/.proma/design/
├── canvas.json
├── assets/
└── annotations/
```

缓存和中间结果独立存放：

```text
~/.proma/design-cache/<project-id>/
├── thumbnails/
├── jobs/
└── staging/
```

- `canvas.json` 保存格式版本、修订号、视口、节点、分组、批注、素材引用和版本关系。
- 正式素材使用稳定 ID 和相对路径，不在画布状态中保存依赖旧项目根的绝对路径。
- 素材元数据记录来源会话、来源任务、提示词、父素材、媒体类型、尺寸、校验值和创建时间。
- `canvas.json` 通过 `safe-file.ts` 原子写入；保存前验证数据格式和当前修订号。
- 拖动和缩放只更新内存状态，使用短延迟合并保存；交互过程中不逐帧写盘。
- AI 输出先写入 `staging/`，完成格式、尺寸和完整性校验后再进入正式 `assets/`。
- 缩略图和可重建缓存不随项目迁移，项目重新连接后按稳定 `projectId` 恢复或重建。

## AI 任务流

设计工作区不启动第二套 Agent 运行时。图片生成和编辑由 Design Job Adapter 转换为现有 Pi Agent 请求。

```text
用户提交生成/编辑
  -> 主进程创建 Design Job 与画布占位节点
  -> Pi Agent runtime 执行图片任务
  -> 输出写入项目缓存 staging
  -> 主进程验证输出
  -> 原子移动到 assets
  -> 更新 canvas.json 的素材与版本关系
  -> Renderer 收到任务与画布更新事件
```

- Design Job 必须记录 `projectId`、可选来源 `sessionId`、动作类型、输入素材、提示词和父版本。
- 用户从画布直接创建任务时，Proma 建立可见的项目任务记录，不发送隐藏的 Codex app-server turn。
- 任务排队、并发和取消复用 Proma 现有 Agent 生命周期与 generation guard，项目迁移和应用退出必须纳入准入检查。
- 自动收集只接受当前项目任务或明确绑定会话产生的图片结果，不扫描 `~/.codex/generated_images` 或整个项目目录。

## 保存与冲突

- 每次保存携带上次读取的修订号；旧修订写入不得覆盖较新的画布。
- 同一项目在多个窗口打开时，主进程串行化写入并广播新修订。
- 可合并的视口与节点位置变化重新应用到最新状态；无法无损合并的删除或版本关系冲突返回明确错误并重新加载。
- 崩溃恢复优先读取主文件；主文件损坏时使用 `safe-file` 保留的可验证备份，并向用户提示恢复结果。
- 未完成任务在重启后重新核对运行状态；无法继续的任务标记为中断，允许重试或删除。

## 安全边界

- 所有素材路径必须位于当前项目 `.proma/design/`、对应缓存目录或经过授权的项目文件根。
- IPC handler 验证调用窗口、`projectId`、目标会话归属和规范化路径，拒绝目录穿越、符号链接越界和伪造项目 ID。
- Renderer 不能直接删除项目文件；删除素材先检查引用关系，并通过主进程受管操作执行。
- 导入图片限制支持的媒体类型、文件大小和解析资源上限；不信任文件扩展名。
- 图片处理中的 CPU/内存密集操作放在主进程受控任务或独立 utility process，不阻塞 Renderer。
- 移植 Codex-Canvas 代码时保留 MIT 许可证和版权声明，并记录被修改模块。

## 错误处理

- 项目离线或路径不可访问时进入只读状态，不静默回退到其他目录。
- 素材文件丢失时保留节点、位置、版本和来源，显示缺失状态并支持重新定位。
- AI 任务失败时保留失败占位、错误摘要和重试入口，不把半成品加入正式素材。
- 项目迁移期间阻止新增 Design Job 和画布写入；迁移完成后重新绑定缓存并恢复可继续任务。
- 发送到会话失败只影响发送操作，不删除或回滚画布素材。
- 自动保存失败时保留内存修改，显示未保存状态并在路径恢复后重试。

## 性能与资源

- 画布只加载可视区域和预加载边界内的节点，远离视口的图片不保留完整 DOM 内容。
- 原图与缩略图分离；列表和普通缩放使用缩略图，检查和导出按需读取原图。
- Blob/Object URL 在节点卸载、素材替换和项目切换时主动释放。
- 拖动、缩放和批注使用动画帧批处理；持久化使用防抖和增量脏标记。
- PSD、元素分层和 OCR 不进入首版，避免过早引入 `ag-psd`、Python 图像依赖和额外打包负担。
- 不保留 Codex-Canvas 的常驻 HTTP server、目录 watcher 和 Codex CLI 子进程，减少端口、CPU 和退出清理成本。

## 测试与验收

功能改动使用 BDD 风格的可执行测试，至少覆盖正常路径和主要边界。

### 单元与契约测试

- 项目到设计数据目录的稳定映射和路径越界拒绝；
- 画布状态解析、格式版本、修订冲突和原子保存；
- 素材导入、校验、缺失、删除引用和缓存重建；
- Design Job 创建、成功、失败、取消、重试和恢复；
- 父子版本关系和来源会话追踪；
- 四层 IPC 请求响应类型和错误传播。

### Renderer 测试

- 只有选中项目时才显示顶部设计标签；
- 项目切换改变画布，同项目会话切换不改变画布；
- 会话与设计切换保留各自状态，且不停止运行中的 Agent；
- 选择、框选、多选、缩放、分组、批注、撤销和重做；
- 加载、空、只读、素材缺失、任务失败和未保存状态；
- 键盘操作、深浅主题和窄窗口布局。

### 集成与性能测试

- 图片生成到正式素材、版本节点和会话附件的完整闭环；
- 应用崩溃、重启和损坏状态文件恢复；
- 项目迁移、离线和重新连接；
- 多窗口并发保存和修订冲突；
- 大量图片下的缩略加载、视口虚拟化和对象 URL 回收。

实现完成后先运行最小相关测试，再运行 `bun run typecheck`；修改运行时依赖或打包 external 时额外运行 `bun run electron:build`。

## 实施分期

### 第一阶段：画布闭环

- 顶部项目级设计标签与页面切换；
- 画布状态、受管素材、导入导出和原子保存；
- 基础节点操作、批注、版本关系和右侧设计面板；
- Pi Design Job 生成与局部编辑；
- 素材与项目会话双向传递；
- 安全、恢复和性能基线测试。

### 后续阶段

- OCR 改字；
- 元素分层与背景补全；
- PSD 导出；
- PPT 与 draw.io；
- 多人实时协作。

后续能力必须在第一阶段的数据格式、任务适配和资源基线稳定后单独评估，不预留未经验证的抽象层。

## 非目标

- 不安装或运行 Codex-Canvas Plugin、MCP server 或 HTTP server。
- 不要求用户安装 Codex CLI。
- 不恢复 Claude Agent SDK 或引入其他 Agent runtime。
- 不把设计画布嵌入受管浏览器、文件预览或单个 Agent 会话右侧分栏。
- 不扫描用户全局 Codex 目录或未授权项目路径。
