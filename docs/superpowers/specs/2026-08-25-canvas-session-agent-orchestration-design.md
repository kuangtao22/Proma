# Canvas 会话与 Agent 创作编排设计

## 状态

- 日期：2026-08-25
- 结论：已由用户确认
- 范围：桌面端项目会话、Canvas 图模型、Pi Agent 编排、生图、视觉文档与交互原型

## 结论

Proma 将现有项目级全局 Design 工作区升级为项目下的 `Canvas` 会话类型。一个项目可以同时拥有多个普通会话和多个 Canvas 会话；每个 Canvas 是独立的创作图，可以容纳多个真实 Pi Agent 子会话、生图模块、视觉文档模块和交互原型模块。

Agent 是 Canvas 的语义理解与编排中心。Agent 根据完整对话和显式连接的上下文，通过受控工具按需创建模块并自动连线。连线表达真实、有方向的数据或任务关系；没有连线的节点彼此独立。上游变化只把下游标记为“需要更新”，不会自动触发模型、生图或原型执行。

本规格替代 `2026-08-22-project-design-workspace-design.md` 中以下产品边界：

- 一个项目只有一个 Design 画布；
- Design 通过项目级顶部标签打开；
- Agent 对话固定在画布右侧；
- 单次 Design Job 作为画布一级节点。

既有素材安全校验、revision、journal、恢复、Pi Agent 执行、Design trace、项目创作上下文和原子写机制继续复用。

## 要解决的问题

当前 Design 以项目为单位只有一张画布，权威节点只有 `asset` 和 `job`。`creativeTaskId` 可以聚合同一图片任务的重试和版本，但无法表达：

- 首页、发现、我的等多个页面组成的设计集合；
- 多个 Agent 各自讨论、协作或独立执行；
- 视觉文档被若干 Agent 显式共享；
- 生图、原型和后续视频模块之间的输入输出关系；
- 一个项目内多个互不干扰的创作主题；
- 复杂创作流程的分支、迭代和追溯。

继续向唯一的 Design 画布增加按钮或节点类型，只会扩大项目、会话、任务和素材之间的耦合。问题本质不是缺少模块，而是缺少“Canvas 会话”和“显式创作图”两层模型。

## 产品结构

### 项目会话类型

左侧项目会话列表同时展示两种一等会话：

- `chat`：现有线性 Agent 会话；
- `canvas`：节点化创作会话。

新建入口允许用户选择“常规会话”或“Canvas”。两种类型使用不同图标，但保持同一项目归属、重命名、归档、删除和最近访问习惯。

每个 Canvas 具有稳定 `canvasId`、名称、独立图文档、视口、修订号和运行历史。切换 Canvas 不终止其中正在运行的 Agent 或模块；未打开的 Canvas 不挂载 Renderer 节点、Agent 对话或原型运行环境。

### Canvas 用户路径

用户打开 Canvas 后可以：

1. 在空白画布创建 Agent、视觉文档、生图或原型模块；
2. 与任一 Agent 节点对话；
3. 让 Agent 根据需求自动创建兼容模块和连线；
4. 查看模块状态、输入版本、运行记录和输出；
5. 修改上游后，选择性更新被标记的下游；
6. 将同一视觉文档或图片显式连接给多个 Agent；
7. 在同一项目创建其他 Canvas，保持创作主题隔离。

例如用户向 Agent 提出“设计首页、发现和我的页面”。Agent 可以创建一份视觉文档和三个生图模块，建立所需连线。用户明确要求生成时才执行；仅讨论结构或风格时，模块保持待运行状态。

### 普通会话转交

普通 Agent 识别到视觉或原型需求时，通过受控 `propose_canvas_handoff` 能力提出以下选择：

- 新建 Canvas；
- 发送到已有 Canvas；
- 继续在普通会话实现。

转交保留原始要求、用户选择的附件和项目归属，只创建目标 Agent 节点或预填对话，不自动产生付费调用。语义判断由 Agent 结合完整上下文完成，本地高置信度规则只可作为零延迟入口，不能成为唯一判断层。

## 画布交互

### Agent 节点与对话

Agent 节点在画布中保持固定、紧凑尺寸，展示：

- 名称和目标摘要；
- 当前状态；
- 最近活动摘要；
- 消息数量；
- 快速创建兼容模块的入口。

点击 Agent 节点时，在节点附近打开可移动、可缩放的画布内浮动对话窗。浮窗关闭后，节点恢复摘要状态，不改变画布布局。用户可以同时打开两个 Agent 浮窗进行对照；双击或快捷键可进入单 Agent 专注视图。

不继续使用固定右侧主对话栏，也不让完整聊天直接撑高节点。

### 模块与端口

首版提供四种真实模块：

- `agent`：对话、理解、拆解和图编排；
- `image`：生成、编辑、重试和版本延伸；
- `visual-document`：维护视觉方向、品牌、角色、页面和连续性规范；
- `webview`：生成和运行受限 HTML/CSS/JS 交互原型。

底层节点协议保留注册新模块类型的能力，但首版不展示无法执行的视频、音频等空按钮。后续执行器接入时沿用相同端口、连线、版本和运行合同。

底层节点类型使用用户确认的 `webview`，UI 使用面向用户的“原型模块”名称。运行实现可以使用独立 WebView 能力，但不把 `WebView` 技术名暴露为主要产品概念，也不等同于直接开放 Electron `webviewTag`。

### 连线语义

连线不是装饰，而是有方向、有类型的数据或任务合同。示例：

- `Agent -> 生图`：Agent 提供任务要求并管理模块；
- `图片 -> Agent`：图片作为 Agent 的显式视觉上下文；
- `视觉文档 -> Agent`：Agent 读取指定视觉规范；
- `Agent A -> Agent B`：A 向 B 提供结构化交接；
- `图片 A -> 生图 B`：B 基于 A 编辑或扩展；
- `视觉文档 / 图片 -> 原型`：原型读取明确连接的规范或素材。

端口声明允许的输入和输出类型，Renderer 与主进程均验证兼容性。没有连线的节点不能读取同一 Canvas 中其他节点的数据。

连线允许形成迭代协作环。系统不自动连锁执行，每次运行固化所读取的上游版本，因此不会形成无限执行循环。上游变化使用带访问去重的图遍历，把所有受影响下游标记为 `stale`。

## 权威数据模型

### 会话与图文档

项目会话元数据增加稳定类型字段：

```ts
type ProjectConversationType = 'chat' | 'canvas'
```

Canvas 使用独立图文档，核心身份从唯一 `projectId` 扩展为 `projectId + canvasId`：

```ts
interface CanvasDocument {
  schemaVersion: number
  projectId: string
  canvasId: string
  revision: number
  viewport: DesignViewport
  nodes: CanvasNode[]
  edges: CanvasEdge[]
  groups: DesignGroup[]
  annotations: DesignAnnotation[]
  createdAt: number
  updatedAt: number
}
```

节点只保存布局、模块身份和必要展示摘要。大体积消息、任务 trace、图片和原型文件由对应服务保存，画布通过稳定 ID 引用。

### 稳定模块与运行记录

生图模块是稳定创作单元，单次 Job 不再是画布一级节点。模块内部保存：

- 稳定模块 ID；
- 当前指令；
- 输入端口绑定；
- 当前状态与 stale 原因；
- 多次运行和失败重试；
- 图片版本树；
- 当前采用的输出版本。

现有 `creativeTaskId` 继续作为迁移和图片创作任务聚合依据。单次 `DesignJobRecord.id` 仍表示一次执行尝试。

Agent 节点引用真实 Pi Agent 子会话 ID。Canvas 子会话只在所属 Canvas 内展示，不进入普通会话、搜索、归档、最近记录、托盘、状态岛、会话引用、项目记忆或 LAN/mobile 列表。

视觉文档和项目素材保持项目级单份存储。不同 Canvas 中的节点可以引用同一稳定文档或素材 ID，避免复制大文件；是否可读仍由当前节点的显式连线决定。

### 原型文件

每个原型模块保存受管相对路径、内容版本、预览快照和运行状态。HTML、CSS、JS 使用 Proma 管理目录和 `safe-file.ts` 原子写入，不允许 Renderer 提交任意绝对路径。

原型首版支持按钮、切页、页面内模态层和本地状态等前端交互，不连接真实后端，不默认联网。

## Agent 编排

### 受控工具

Canvas Agent 通过主进程提供的受控工具读取和修改图，不直接写画布 JSON：

- 查看当前节点、端口、连线和版本摘要；
- 创建兼容模块；
- 创建或移除自己本轮创建的连线；
- 更新自己创建模块的指令；
- 提议执行模块；
- 读取显式连接的输入；
- 写入或提议更新视觉文档；
- 生成或修改原型文件。

工具输入必须包含 `projectId`、`canvasId`、发起 Agent 节点 ID 和预期 revision。主进程验证 Canvas 归属、会话归属、端口兼容、引用权限和修订号。

Agent 可以自动创建节点、连接兼容端口和更新自己创建的结构。删除用户节点、断开用户连线、覆盖已采用视觉文档或改变其他 Agent 的目标必须经过确认。

一次 Agent 图变更以原子 mutation batch 提交。任一节点或连线校验失败时整批拒绝，避免留下不完整结构。成功批次形成单个撤销历史项。

### 上下文边界

Agent 节点只能读取：

- 自己的持久化对话；
- 显式连入的模块输出；
- 节点设置中明确允许的项目代码和业务上下文。

`Agent A -> Agent B` 默认传递结构化交接摘要、选定附件和来源引用，不传递 A 的完整聊天。需要完整消息时必须由用户明确选择。

项目上下文权限沿用 `auto / project / none` 思路，但它是 Agent 节点自身设置，不代表可以隐式读取同画布其他节点。

### 执行与付费边界

Agent 是否需要生图、视觉文档或原型，由模型结合完整上下文判断，不依赖固定关键词表。

- 用户明确要求“生成、出图、运行”等执行结果时，Agent 可以创建、连线并启动对应模块；
- 用户处于讨论、规划或修改需求时，Agent 只创建待运行结构；
- 上游变化导致下游 stale 时，Agent 可以说明影响并建议更新，但必须再次获得执行意图；
- 任何隐式转交、打开 Canvas 或自动连线都不能直接产生付费调用。

无依赖 Agent 可以并行运行；存在输入依赖时按当前版本就绪状态执行。同一模块同一时间只有一个活动运行。取消、失败和崩溃只影响对应模块，不回滚画布结构或其他独立分支。

### 透明度

每次运行展示：

- 用户要求和任务摘要；
- 实际读取的上游节点与版本；
- 精确生图提示词或原型修改摘要；
- 工具调用、状态、结果与错误；
- 重试和采用版本。

界面不伪装展示模型私有思考链；以可审计的决策摘要、上下文引用和执行日志满足透明度需求。

## 原型沙箱

原型模块逻辑上提供 WebView 能力，但不得直接开放高权限 Electron `webviewTag` 给生成内容。运行环境必须满足：

- 独立、临时或受管 session partition；
- `nodeIntegration: false`；
- 无可调用业务 IPC 的 preload；
- 禁止任意本地文件和 `file://` 访问；
- 默认阻断 HTTP、HTTPS、WebSocket 和其他网络请求；
- 禁止 `window.open`、浏览器新窗口、下载、权限请求和外部导航；
- 只通过 Proma 受控媒体协议读取显式连入的素材；
- Content Security Policy 只允许原型自身受管资源；
- 导航、崩溃和违规访问产生用户可见错误。

只有当前激活的原型节点挂载交互运行环境。其他原型显示快照；离开 Canvas 后全部休眠。原型崩溃时回退到最近快照并提供重新加载，不影响 Canvas 或其他模块。

## Renderer 结构

现有 Design Renderer 按 `projectId` 隔离状态，需要升级为按 `canvasId` 隔离：

- 会话列表：展示 chat/canvas 类型并提供创建入口；
- `CanvasWorkspaceView`：Canvas 生命周期、恢复、保存和浮窗管理；
- `CanvasGraph`：节点、端口、连线、选择、虚拟化与视口；
- `AgentNode` / `AgentConversationWindow`：紧凑节点与画布内浮动对话；
- `ImageModuleNode`：稳定任务、运行记录和版本选择；
- `VisualDocumentNode`：规范摘要、编辑和引用状态；
- `PrototypeNode`：渲染 `webview` 节点的快照、激活和沙箱状态；
- `canvas-atoms`：按 `canvasId` 保存快照、选区、浮窗、历史、stale 和保存状态；
- `canvas-adapter`：Renderer 到 Preload 的唯一入口。

右侧 Inspector 可以保留为选中节点的属性与运行详情入口，但不再承载主 Agent 对话。主交互始终发生在画布节点和浮动对话窗中。

## 主进程与 IPC

IPC 继续遵守四层合同：

1. `packages/shared` 定义会话类型、Canvas 文档、节点、端口、边、mutation、模块和事件；
2. `apps/electron/src/main/ipc.ts` 注册受权 handler；
3. `apps/electron/src/preload` 暴露最小 bridge；
4. Renderer 只通过 adapter 调用。

主进程新增或扩展的职责：

- Canvas 会话创建、重命名、归档和删除；
- 按 `projectId + canvasId` 加载、保存和恢复图文档；
- 校验节点、端口、边、revision 和 mutation batch；
- 管理 Canvas Agent 子会话生命周期与可见性；
- 管理稳定生图模块和内部 Job；
- 管理视觉文档引用；
- 管理原型文件、快照和沙箱进程；
- 广播按 Canvas 隔离的 graph/module/recovery 事件。

Renderer 不直接读写图文件、Agent 会话、图片或原型目录。

## 迁移

现有项目 Design 数据首次打开时迁移为项目下的“默认设计画布”。迁移规则：

- 使用确定性 `canvasId`，重复迁移不会创建多个默认 Canvas；
- 同一 `creativeTaskId` 的 Job、重试、trace 和输出素材合并为一个生图模块；
- 本地导入或 Agent 导入且不属于生成任务的图片转换为独立图片模块；
- 原有节点位置、分组、批注、素材父子版本和当前任务状态保留；
- 运行中任务在迁移准入阶段阻断，或在启动恢复后先收敛为可迁移终态；
- 使用可恢复 migration journal 记录计划、阶段和校验摘要；
- 新 Canvas 文档、模块索引和引用全部原子写成功并校验后，才更新会话索引；
- 迁移失败时保留原文件，并以旧画布只读方式打开，提供重试；
- 迁移过程不重新生成图片、不复制已有项目素材、不创建付费任务。

普通 chat 会话不迁移。现有 Design 内部执行会话继续遵守 trace 转存和隐藏规则。

## 错误与恢复

- 图 mutation batch 部分无效时整批拒绝，返回具体节点、端口或 revision 错误；
- 模块运行失败只更新模块状态，保留结构、输入版本、提示词、trace 和重试入口；
- 引用素材或文档缺失时，下游显示“输入缺失”并禁止静默使用旧缓存执行；
- Agent 子会话中断后节点保留，可恢复或重新运行；
- 原型沙箱崩溃或违规访问后回退快照，不影响画布；
- stale 传播使用访问去重，循环图不会无限遍历；
- recovery 继续沿用权威 LOAD、revision 代次和在途 SAVE 隔离，普通模块事件不得取消恢复；
- Canvas 删除前停止或取消其活动 Agent、Job 和原型运行，并按可恢复删除事务清理专属数据；项目级共享素材和视觉文档只有引用归零后才可删除。

## 性能与资源

- 只加载当前 Canvas 的轻量图元数据；其他 Canvas 保持磁盘状态；
- 继续使用 XYFlow 节点虚拟化，1000 节点基线不回退；
- Agent 对话、任务 trace、图片原图和视觉文档正文按需读取；
- 原型仅在激活时运行，失焦显示快照并释放运行资源；
- 图片和视觉文档使用稳定 ID 共享，不复制大文件；
- stale 计算为当前 Canvas 的图遍历，复杂度与节点和边数量线性相关；
- 项目级限制 Agent 并发，超出进入队列；生图和原型运行分别隔离；
- 关闭 Canvas 后释放 Jotai 临时状态、对象 URL、对话浮窗和原型进程；
- 拖动、缩放和节点布局继续在自动保存边界压缩 mutation，不逐帧写盘。

## 关联业务影响

### 普通 Agent

普通 Agent 增加语义 Canvas 转交工具，但不会默认改变代码实现行为。现有高置信度本地视觉意图判断可保留为过渡兜底，长期由 Agent 工具触发原生转交 UI。

### 会话列表与可见性

项目列表需要认识 canvas 顶层会话和 Canvas 内部 Agent 子会话。顶层 Canvas 可见；子会话、Design 执行会话继续在所有普通会话消费者中排除。

### 项目迁移与路径管理

Canvas 图文档、原型文件和专属运行记录随项目迁移；项目级素材和视觉文档沿用现有 verified copier 与路径重写。活动 Agent、Job 或原型运行纳入迁移准入。

### LAN 与移动端

首版不在 LAN/mobile 展示或编辑 Canvas。协议必须明确过滤 Canvas 子会话，并允许未来通过独立 capability 增加只读 Canvas 摘要，不能把 Canvas 伪装为普通 chat。

### Automation 与 Collaboration

首版 Canvas 不作为 Automation 目标。Canvas Agent 子会话仍使用 Pi runtime，但不能被普通 Collaboration 发现或引用；未来需要显式 Canvas 节点协议后再开放。

## 测试与验收

### 共享类型与存储

- chat/canvas 会话类型解析、旧元数据兼容和非法类型拒绝；
- `projectId + canvasId` 路径映射、目录穿越和伪造归属拒绝；
- Canvas schema、节点、端口、边、循环和 mutation batch 校验；
- revision 冲突、原子保存、recovery 和多窗口广播；
- stable module 与运行记录聚合；
- 原型相对路径、版本和快照持久化。

### Agent 与执行

- 未连线 Agent 无法读取彼此内容；
- 连线后只传递声明的素材、文档或结构化交接；
- Agent 通过受控工具创建节点和兼容连线；
- 无效批次不产生部分结构；
- 讨论只创建待运行模块；明确执行意图才启动；
- 上游变化只标记 stale，不自动运行；
- 多个无依赖 Agent 并行，同一模块执行互斥；
- 运行 trace 固化真实输入版本和精确提示词；
- Canvas 子会话不进入普通会话消费者。

### Renderer

- 同一项目创建、重命名、切换、归档和删除多个 Canvas；
- chat 与 canvas 在左侧列表正确区分；
- Agent 节点保持稳定尺寸，浮动对话可移动、缩放、同时打开和关闭；
- 节点端口只允许兼容连线；
- 自动创建批次可一次撤销；
- stale、输入缺失、运行失败和恢复状态清晰；
- 视觉文档连接多个 Agent 后正确传播 stale；
- 原型激活、快照、休眠和崩溃回退；
- 键盘操作、窄窗口、深浅主题和无障碍状态。

### 原型安全

- 阻断 Node、业务 preload、任意 IPC 和本地文件；
- 阻断 HTTP、HTTPS、WebSocket、下载、浏览器新窗口、权限和外部导航；
- 只允许显式连接的受控素材；
- 非激活原型不运行脚本；
- 沙箱崩溃不影响 Canvas Renderer 和其他模块。

### 迁移与性能

- 旧 Design 数据完整迁移为唯一默认 Canvas；
- `creativeTaskId` 的尝试和版本正确聚合；
- 中断、失败、重试和幂等恢复；
- 迁移失败保持旧文件且不产生付费任务；
- 1000 节点虚拟化基线、拖动、平移和缩放不回退；
- 多个未激活原型不保留活动运行环境；
- Canvas 关闭后 Agent、对象 URL、trace 和原型资源释放。

完成实现后先运行定向测试，再运行 `bun run typecheck` 与 `bun run electron:build`。涉及完整迁移和原型沙箱时需要真实 Electron 窗口验收。

## 实施边界

本规格是一项跨会话、画布、Agent、持久化和沙箱的系统改造，不适合一次性替换。实施计划应按可独立验证的兼容阶段推进：

1. 引入 Canvas 顶层会话身份和多 Canvas 存储，不改变现有 Design 执行；
2. 将现有 asset/job 图迁移为稳定 image module；
3. 引入 Agent 节点、浮动对话和受控图工具；
4. 引入 typed edge、stale 与显式上下文传递；
5. 引入视觉文档节点；
6. 引入沙箱原型节点；
7. 完成普通 Agent 转交、旧数据迁移和全链路验收。

每一阶段必须兼容前一阶段已保存数据，并在新 schema 写入前提供明确迁移和回退路径。

## 非目标

- 首版不实现视频、音频或真实后端原型执行器；
- 首版不允许原型联网或访问项目开发服务器；
- 首版不让 Canvas 进入 LAN/mobile、Automation 或普通 Collaboration；
- 不创建第二套 Agent runtime；
- 不自动连锁执行或隐式产生付费调用；
- 不让无连线节点读取彼此数据；
- 不把完整 Agent 对话塞进固定尺寸节点或固定右栏；
- 不恢复“一项目一张全局 Design 画布”的产品模型。
