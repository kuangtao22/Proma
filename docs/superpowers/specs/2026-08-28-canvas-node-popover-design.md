# Canvas 节点添加悬浮菜单设计

## 目标

把 Canvas 顶部工具栏的节点类型选择从居中模态弹窗改为紧贴“添加节点”按钮下方的小型悬浮菜单，缩短创建路径，并避免遮挡或打断画布操作。

## 交互设计

- 点击顶部“添加节点”按钮，在按钮正下方打开单列悬浮菜单。
- 菜单居中对齐触发按钮，默认宽度为 `12rem`，并受视口宽度限制。
- 菜单按既有顺序显示 `Agent`、`生图`、`文档`、`原型`、`视频`，每项包含图标和类型名称。
- `视频`继续显示“即将支持”并保持禁用；其余类型选择后立即关闭菜单并创建对应节点。
- 点击菜单外部、再次点击“添加节点”按钮或按 `Escape` 关闭菜单。
- 添加入口不可用时，按钮保持禁用且不能打开菜单。

## 技术边界

- 复用现有 Radix `Popover` 基础组件，不新增依赖，也不恢复此前视觉显示不稳定的 `DropdownMenu` 实现。
- 变更仅限 Canvas 顶部工具栏及其测试，不修改 IPC、持久化、节点类型合同和创建事务。
- 继续通过原有 `onAddNode(kind)` 传递选择结果；节点位置沿用当前“保持视口不动，在既有节点之后追加”的工作区逻辑。
- 菜单使用主题变量和既有按钮样式，兼容深浅主题、键盘焦点和窄窗口边界避让。

## 异常与状态

- `writable` 或 `canAdd` 为假时不允许打开菜单。
- 选择禁用类型不触发回调，也不改变画布状态。
- 节点创建失败仍由现有工作区错误处理负责，悬浮菜单不复制业务错误状态。

## 验证

- BDD 测试覆盖悬浮菜单语义、按钮下方定位合同、五种类型顺序、禁用视频、选择回调与添加入口禁用状态。
- 运行 Canvas 工具栏相关测试和 TypeScript 类型检查。
- 在真实 Electron 客户端用鼠标验证菜单位置、外部关闭、各可用类型创建以及画布视口不跳动。

## 影响评估

- 关联业务：不影响 Agent、图片、文档和原型节点内部能力，也不改变 Canvas 保存结构。
- 性能与资源：仅在菜单打开时挂载一个轻量 Portal，资源开销可忽略；不增加网络、磁盘或主进程调用。
