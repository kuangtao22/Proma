# Agent 画布工作区与节点编排设计

## 目标

把现有独立画布会话改造为普通 Agent 会话中的项目工作区能力，使用户能够在同一条 Agent 对话中引用画布节点，并让 Agent 通过受控工具读取、创建、修改、执行和关联节点。

本设计同时降低画布业务对上游 Proma 主视图、左侧会话列表和普通顶部标签栏的侵入。界面统一使用中文“画布”；代码内部继续保留 `Canvas` 类型、目录和协议名称，避免无业务价值的机械重命名。

## 核心结论

- 画布属于项目，不属于某个 Agent。
- 每个 Agent 可以绑定一张默认画布，并可关联多张项目画布。
- 多个 Agent 可以关联同一张画布，共享节点与连线。
- 对话引用节点与画布连线是两种不同关系：引用只影响本轮上下文，连线表示持久化的数据或任务依赖。
- 画布进入当前 Agent 的右侧工作区，不再作为左侧独立会话或独立主视图。
- Agent 通过主进程画布工具操作权威数据，不通过模拟鼠标控制界面。
- 明确规划可以创建待执行结构；只有明确执行要求才调用生图、视频等付费能力。

严格的一对一归属不在本设计中采用。它会阻断一个 Agent 管理多套方案和多个 Agent 协作同一项目资产。

本文未特别说明时，“Agent”指左侧可见的普通顶层 Agent 会话；画布内部的 Agent 节点继续使用既有内部会话归属和隔离规则，不参与普通 Agent 与画布的绑定索引。

## 产品结构

```text
项目
├── Agent A
│   ├── 对话
│   └── 右侧工作区：文件 / 浏览器 / 画布：首页方案
├── Agent B
│   ├── 对话
│   └── 右侧工作区：画布：首页方案 / 画布：活动方案
└── 画布资产
    ├── 首页方案
    └── 活动方案
```

### 导航与展示

- 左侧只展示普通 Agent 会话，不再展示画布顶层会话。
- 当前 Agent 的右侧工作区顶部提供“画布”入口。
- 已关联画布以动态标签展示；内部标签 ID 使用 `canvas:<canvasId>`，用户只看到画布标题。
- 右侧画布提供展开和还原能力。展开时占据主要内容区域，但仍属于当前 Agent，不切换为独立画布会话。
- 一个 Agent 的画布标签、最后活动画布、视口和面板状态不影响其他 Agent。
- 后台 Agent 修改画布只产生标签活动提示，不抢走当前用户焦点。

### 首次使用

- 新建 Agent 时不立即创建空画布。
- Agent 没有关联画布时，用户点击“画布”入口，显示选择现有画布或新建画布的小菜单。
- Agent 收到明确的设计执行要求且没有默认画布时，可以创建并绑定默认画布。
- 普通讨论、分析或歧义表达不创建画布。

### 生命周期

- 删除 Agent 只删除关联与 Agent 独立视图状态，不删除项目画布。
- 删除画布时清理所有 Agent 关联，并继续使用不可恢复确认。
- 有运行中 Agent 节点、生图或未来视频任务的画布禁止删除。
- 旧默认设计画布与现有原生画布保留原 ID、素材、任务、版本和节点内容。

## 数据归属

### 画布本体

画布继续使用现有项目存储，不迁移节点与素材：

```text
<项目>/.proma/design/canvases/
├── index.json
└── <canvasId>/
    ├── canvas.json
    ├── nodes/
    ├── transactions/
    └── trash/
```

画布本体、节点位置、节点内容和连线是项目共享事实。

### Agent 关联

关联属于客户端状态，不进入项目画布文档，也不写入官方 `AgentSessionMeta`：

```ts
interface AgentCanvasBinding {
  projectId: string
  sessionId: string
  defaultCanvasId?: string
  linkedCanvasIds: string[]
  lastActiveCanvasId?: string
  updatedAt: number
}
```

关联索引由画布模块保存在 `~/.proma` 业务配置目录，按项目身份隔离，并使用安全原子写封装。项目画布可随项目移动，客户端会话关联不污染项目资产。

### Agent 独立视图状态

以下状态按 `sessionId + canvasId` 隔离：

- 当前活动画布；
- 视口位置和缩放；
- 当前主选节点与多选集合；
- 节点详情面板尺寸；
- 右侧工作区展开状态。

节点位置、内容和连线不进入该状态，避免同一画布在不同 Agent 中产生数据分叉。

## 节点引用

### 交互

- 单节点菜单提供“引用到对话”。
- 多选状态提供“引用选中节点”。
- 引用后在 Agent 输入框上方显示节点类型、标题和所属画布。
- 同一节点重复引用时去重；用户可以在发送前移除引用。

### 引用合同

```ts
interface CanvasNodeReference {
  projectId: string
  canvasId: string
  nodeId: string
  nodeType: string
  nodeRevision: number
  title: string
}
```

引用作为用户消息的可选结构化元数据随 Agent JSONL 持久化。它不冒充文件附件，也不包含 HTML、图片或文档全文。

发送前由主进程完成以下校验：

1. 当前 Agent 与项目身份有效；
2. 画布属于当前项目；
3. 节点存在且类型匹配；
4. 当前调用可以访问目标画布；
5. 发送时实际节点版本已确定。

节点从选中到发送期间发生变化时，使用发送时的最新版本，并在输入区提示内容已更新。消息发送后固定记录实际使用的版本。节点已删除、项目失效或无权访问时阻止发送并保留用户输入。

节点引用不扩大 Agent 的画布访问范围。引用目标必须是默认画布、已关联画布或用户本轮显式选择并完成关联的画布。历史消息只保留引用身份和实际使用的 revision；若对应历史版本已经不在画布生命周期中，后续重试必须显示引用版本失效，不能用当前内容静默替代。

引用只表示本轮上下文。只有用户要求基于该节点产生持久化结果时，Agent 才创建节点或连线。

## Agent 上下文与工具

每轮 Agent 只接收当前默认画布、已关联画布和显式节点引用的轻量摘要。完整画布不会自动进入模型上下文。

画布模块向 Pi Agent Runtime 提供以下受控工具：

读取和写入默认限制在当前 Agent 的默认画布与已关联画布。`canvas_manage` 只有在用户明确选择画布或任务明确要求创建、关联画布时才能扩大该集合，禁止为了寻找素材扫描并自动关联项目全部画布。

### `canvas_get_context`

读取当前 Agent 的默认画布、已关联画布、当前活动画布和选中节点摘要，不读取整张图。

### `canvas_manage`

创建画布、关联现有画布和设置默认画布。没有默认画布时，只有明确的设计或生成任务才能创建。

### `canvas_read`

按节点 ID 读取节点内容、版本和必要的上下游关系。引用 WebView 节点时只读取目标节点和任务所需邻接关系。

### `canvas_apply_changes`

批量创建、修改和删除节点，并建立或删除连线。一次调用使用同一基础 revision 和同一事务提交，禁止产生半完成图结构。

### `canvas_run_nodes`

执行生图、HTML 渲染和未来的视频节点。调用时使用已经提交的节点配置和版本，并返回可审计的任务身份。

## Agent 行为规则

| 用户表达 | Agent 行为 |
| --- | --- |
| “分析一下这个首页” | 读取引用节点并回复，不修改画布 |
| “规划首页、发现、我的页面” | 可以创建待执行节点与连线，不调用付费生成 |
| “帮我生成这三个页面” | 创建节点、建立连线并执行相应模块 |
| “基于这个首页再做发现和我的” | 读取引用节点，创建两个衍生节点并从原节点建立连线 |
| 明确要求删除或覆盖 | 在目标明确时执行；不得根据模糊意图自行删除 |

Agent 的语义理解负责选择工具和操作；产品层不通过关键词硬编码具体页面类型。产品层只提供权威画布上下文、工具权限和破坏性边界。

## 典型数据流

```text
用户引用首页 WebView 节点
        ↓
Renderer 将结构化引用随消息发送
        ↓
主进程验证项目、画布、节点和版本
        ↓
Agent 使用 canvas_read 读取必要内容
        ↓
Agent 形成页面规划
        ↓
canvas_apply_changes 批量创建“发现”“我的”与两条连线
        ↓
明确要求执行时调用 canvas_run_nodes
        ↓
画布广播权威 revision
        ↓
来源 Agent 的“画布”标签显示活动并定位新节点
```

写操作携带基础 revision。其他 Agent 已修改画布时返回明确版本冲突；Agent 重新读取后最多自动重试一次，禁止无界重试或覆盖远端结果。

每次工具写入记录来源 `sessionId`、运行代次和工具调用 ID，用于恢复、审计和界面活动提示。这些信息不生成额外普通聊天消息。

## 上游兼容边界

本设计不建设通用第三方插件平台。画布采用插件形状的内部适配层：

```text
官方右侧工作区
    ↕ CanvasWorkspaceAdapter
画布 Renderer 模块
    ↕ Canvas IPC / Service
画布存储与节点生命周期
    ↕ CanvasToolProvider
Pi Agent Runtime
```

官方区域只保留以下接缝：

- `AgentSidePanelTab` 接受 `canvas:<canvasId>`；
- 右侧顶部菜单增加画布入口；
- `SidePanel` 通过独立适配器列出、关闭和渲染画布标签；
- Agent 发送合同增加可选画布节点引用；
- Pi 工具构建阶段追加独立画布工具提供器。

迁移完成后移除以下旧侵入：

- `activeView === 'design'` 主视图分支；
- 普通顶部标签栏中的特殊画布标签；
- 左侧项目列表中的画布会话；
- 普通 Agent 导航对全局画布选择的清理逻辑。

这不实现零侵入插件，但把长期合并冲突从主视图、侧栏、普通标签和会话导航收敛到右侧工作区适配与 Agent 工具注册两个稳定边界。

## 错误与恢复

- 画布已删除：清理失效关联并显示明确状态。
- 引用节点失效：发送前阻止运行，保留输入和其他有效引用。
- revision 冲突：返回最新 revision，重新读取后最多重试一次。
- 批量结构写失败：事务整体不提交，不留下部分节点或孤立连线。
- 生图或视频失败：保留节点、配置、错误和连线，支持原地重试。
- 图已提交但 Renderer 未收到事件：不回滚项目事实，下次 LOAD 对账恢复。
- 后台 Agent 写入：更新活动提示，不自动切换前台工作区。
- 项目授权撤销、稳定目录身份变化或路径重链：立即拒绝读写并 fail closed。
- 删除 Agent：只清理关联与视图状态。
- 删除画布：清理全部关联；历史消息保留原引用身份并显示失效。

## 性能与资源影响

- 未打开的画布不挂载 Renderer 工作区。
- Agent 每轮只接收轻量画布摘要，节点正文通过工具按需读取。
- 多节点和连线使用单次批量事务，避免逐节点 IPC 与 revision 风暴。
- 同一项目画布仍复用现有媒体授权和工作区 LOAD 结果，不按节点重复签发预览授权。
- 视口、选区和面板状态与画布文档分离，减少多个 Agent 之间的无意义图 revision。
- 不新增运行时依赖，不引入本地数据库。

## 分阶段迁移

1. 新增 Agent 画布关联索引、独立视图状态和右侧工作区适配层，保留旧入口作为临时回退。
2. 接入右侧“画布”标签、选择或新建菜单、展开与还原。
3. 接入节点引用、发送前校验和历史消息展示。
4. 接入画布工具提供器、批量事务、活动事件与 Agent 自动关联。
5. 完成兼容验证后移除左侧画布会话、独立主视图和特殊顶部标签。
6. 删除只服务旧导航方式的 Renderer 状态与测试；保留旧画布数据读取和 `legacy-design` 兼容。

迁移不得复制画布、修改节点 ID、移动素材或自动把现有画布绑定给任意 Agent。

临时保留新旧入口期间，两者必须读写同一套画布 Store 与节点生命周期；新入口只额外维护 Agent 关联和独立视图状态，不建立第二份画布文档或双写节点数据。

## 测试与验收

### 自动化测试

- 共享类型：画布引用、关联和工具请求的正常路径与边界。
- 存储：关联索引原子写、删除清理、损坏配置降级和项目隔离。
- IPC：shared、main、preload、renderer 四层合同同步。
- Agent 工具：按需读取、批量写、版本冲突、破坏性边界和付费执行准入。
- Renderer：动态标签、Agent 独立视口、多选引用、展开还原和后台活动不抢焦点。
- 恢复：提交后事件丢失、运行中关闭工作区、重启后关联与画布对账。
- 上游兼容：普通 Files、Browser、Terminal、Preview、Delegation 和双 Pane 行为不回退。

### 真实客户端验收

- Agent 首次点击“画布”可以选择现有画布或新建。
- 切换 Agent 后分别恢复自己的画布、视口和右侧标签。
- 两个 Agent 关联同一画布，节点共享但缩放和选区互不影响。
- 引用首页 WebView 后，Agent 创建“发现”“我的”节点并正确连线。
- 明确生成要求可以自动建立默认画布；普通分析不创建或修改节点。
- 批量创建失败时不留下半成品。
- 生图失败时保留配置、错误和重试入口。
- 删除 Agent 后画布仍可被其他 Agent 打开。
- 删除画布后关联被清理，历史消息显示引用失效。
- 宽窄窗口、深浅主题、键盘操作和右侧双 Pane 下均可使用。

## 非目标

- 本阶段不实现可安装的第三方插件系统。
- 不重写现有画布存储、节点生命周期、生图任务或媒体授权。
- 不把所有现有 Agent mention 字段统一重构为新的通用引用框架。
- 不实现完整视频生产链，只保留节点执行工具的扩展边界。
- 不允许 Agent 在没有明确任务时扫描、加载或修改项目全部画布。
