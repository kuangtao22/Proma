# Canvas WebView 设备比例与卡片预览设计

## 状态

- 日期：2026-08-31
- 结论：WebView 节点使用单一响应式 HTML，通过设备预设控制卡片和详情视口，并以离屏截图生成静态卡片预览
- 范围：右侧原生画布、WebView 节点、WebView 详情工作台、Canvas IPC 与受管缩略图

## 问题与目标

当前 WebView 折叠卡片只显示类型、标题、内容版本和状态。用户必须展开工作台才能识别页面内容，多个首页、发现页、我的页同时存在时，画布缺少设计板应有的视觉辨识能力。

直接把可交互 iframe 放进每个节点虽然实现简单，但会让多个网页脚本同时运行，并抢占画布的拖动、框选、缩放和双击事件。当前 WebView 详情按需加载、无同源 sandbox 和离线 CSP 的边界也不能为了卡片截图而放宽。

本次目标：

1. WebView 折叠卡片直接显示页面静态预览，用户无需打开详情即可识别节点。
2. 每个 WebView 节点选择一个设备预设，首版支持网页和手机两种比例。
3. 网页和手机继续使用同一份响应式 HTML，切换设备不调用 Agent、不复制内容。
4. 卡片保持画布交互优先，页面预览本身不可点击或滚动。
5. 缩略图只在需要时生成并缓存，避免大画布常驻多个网页运行时。
6. 详情工作台按设备预设显示真实可交互 HTML，并保留现有离线安全边界。

## 方案比较

### 方案 A：卡片直接运行 iframe

实现路径最短，页面也能实时变化。但每个可见 WebView 节点都会运行脚本，平移和缩放时还会反复挂载；网页事件容易与 XYFlow 交互冲突。该方案违背“卡片识别、详情交互”的职责分离，不采用。

### 方案 B：Renderer 读取 sandbox iframe 后截图

可以避免主进程截图服务，但当前 iframe 不允许同源访问，Renderer 无法安全读取内部 DOM 或画布。为截图增加 `allow-same-origin` 会削弱已经建立的安全边界；引入 DOM 截图库也无法可靠覆盖复杂 CSS、字体和脚本，不采用。

### 方案 C：主进程离屏截图并缓存静态预览（采用）

主进程在受限离屏窗口中加载与详情一致的安全 HTML，根据设备视口截图并保存为 WebP。Renderer 卡片只加载受控缩略图 URL。该方案首次生成有一次 CPU 和磁盘开销，但常规画布交互保持为普通图片渲染，适合多个 WebView 节点并存。

## 设备模型

### 节点字段

`CanvasWebviewNode` 新增必需字段：

```ts
interface CanvasWebviewNode {
  devicePreset: 'desktop' | 'mobile'
}
```

设备预设属于 Canvas 图事实，随节点持久化、引用和 revision 一起传播。它不属于 HTML 正文，也不创建第二份原型内容。

现有 Canvas 文档中的 WebView 节点没有该字段。文档 schema 必须按现有规范化迁移链升级：加载旧 schema 时在严格公开解析之前补为 `desktop`，下一次成功写入后持久化新 schema；已经声明为新 schema 的文档若缺少字段则 fail closed。迁移不修改 HTML、节点位置或 Canvas revision 之外的业务内容。

### 首版尺寸

| 设备 | 渲染视口 | 折叠卡片 | 用途 |
| --- | --- | --- | --- |
| 网页 | `1440 × 900` | 约 `384 × 316` | 桌面网页、后台、宽屏首页 |
| 手机 | `390 × 844` | 约 `232 × 578` | 移动应用、H5、竖屏页面 |

卡片包含约 42px 顶栏、按设备比例展示的预览区和约 34px 底部标题状态区。节点外形直接表达设备类型，不把手机页面压入网页宽卡。

Agent 创建 WebView 时应显式传入设备预设：用户明确要求手机页面时使用 `mobile`，明确要求网页时使用 `desktop`；没有说明时使用 `desktop`。判断由 Agent 语义完成，Renderer 不增加关键词路由。

## 交互设计

### 折叠卡片

- 顶部保留原型类型、节点操作和详情放大入口。
- 增加当前设备图标按钮；点击后在按钮下方打开 `网页`、`手机` 小菜单。
- 设备菜单使用 `Monitor` 与 `Smartphone` 图标，并显示具体视口尺寸。
- 预览使用静态 `<img>`，设置不可拖动、不可聚焦和不可接收指针事件。
- 单击卡片只选中，拖动移动节点，双击或点击放大按钮打开详情，既有行为不变。
- 切换设备后立即改变节点外形，保持节点左上角不变，不自动移动其他节点或重排整张画布。
- 卡片扩大后允许暂时与邻近节点重叠，用户可自行调整，避免不可预测的画布跳动。

### 详情工作台

- 顶部增加 `网页 / 手机` 分段控制，与卡片设备菜单写入同一个节点字段。
- 网页模式尽量使用可用工作台空间；手机模式在工作台中居中展示竖屏设备画幅。
- 详情继续运行同一份 HTML。切换设备只重建对应 viewport 的 iframe，不调用 Agent。
- HTML 响应式效果不正确时忠实显示实际页面，不在 Renderer 中伪造重排。用户可引用该节点继续让 Agent 修改 HTML。

### 加载与错误

- 缓存命中时直接显示预览。
- 缓存缺失时显示与设备比例一致的稳定骨架，并提示正在生成网页或手机预览。
- 新缩略图完成后淡入，不能改变节点外形。
- 缩略图生成失败时保留节点和 HTML，显示“预览生成失败”及重试入口；打开详情仍可正常使用。
- 设备或内容身份已改变时，旧请求的迟到结果必须丢弃。

## 数据流与组件边界

### Shared 合同

- 新增严格 `CanvasWebviewDevicePreset` 联合类型。
- `CanvasWebviewNode` 严格解析 `devicePreset`，拒绝缺失值、未知值和未知字段。
- Canvas 文档 schema 升级并提供旧 WebView 节点到 `desktop` 的确定性迁移；新 schema 不允许继续缺省。
- 新增设备切换 mutation，包含节点 ID、预设和 Canvas revision 语义。
- 新增 WebView 预览目标与快照，目标至少绑定项目、画布、节点、原型、内容 revision 和设备预设。
- 预览快照只暴露受控 URL、像素宽高和完整目标，不暴露本地路径。

### Main

- 新增独立 WebView 预览服务，复用 Electron offscreen `BrowserWindow` 与 `capturePage` 能力，不复用普通应用窗口。
- 服务全局只保留一个可复用离屏窗口，并通过串行队列处理截图，避免并发创建 Chromium 实例。
- HTML 使用与详情一致的前置 CSP；窗口启用 sandbox、关闭 Node integration、拒绝 popup、主 frame 与子 frame 外部导航。
- 截图按目标视口完成后转换为 WebP，使用 Canvas 受管缩略图目录和原子临时文件替换写入。
- 缓存键包含完整预览目标；相同内容和设备直接复用，内容 revision 变化不得继续返回旧图。
- 删除节点、更新内容或清理 Canvas 时回收不再可达的 WebView 缩略图。

### IPC 与 Preload

- WebView 预览请求必须通过共享精确 parser，并先执行主窗口、项目、画布和节点授权校验。
- Main handler 只接受公开目标；Preload 只透传允许字段并把内部错误收敛为固定公开错误。
- Renderer adapter 保留公开错误码和安全文案，并按完整目标缓存同一在途请求。
- 缩略图使用受控媒体 URL，授权随当前窗口和 Canvas 生命周期释放。

### Renderer

- WebView 卡片使用独立预览组件管理 `idle/loading/ready/error`，不把 HTML 放入 XYFlow node data。
- 只有 ReactFlow 实际挂载的可见节点请求预览，继续依赖 `onlyRenderVisibleElements` 控制大画布成本。
- `CanvasNodeCard` 保留四类节点共用外壳；WebView 预览、设备菜单和动态尺寸由 WebView 节点组件注入。
- `native-canvas-model` 从固定节点宽高升级为按节点类型和设备预设计算矩形；碰撞检测、追加位置和子节点位置统一读取同一几何函数。
- 设备切换走现有 Canvas 保存队列与冲突恢复，不维护第二套本地持久化状态。

## 安全边界

1. 卡片永不运行 HTML，只显示受控静态图片。
2. 详情和离屏截图都必须在任何 Agent HTML 字节之前注入 CSP。
3. WebView 不获得 Node、Electron、项目文件、Cookie 或普通网络访问能力。
4. `window.open`、表单提交、刷新、meta 跳转、主 frame 和 `about:srcdoc` 子 frame 外部导航全部拒绝。
5. Renderer 不接收 HTML 文件路径或缩略图文件路径。
6. 快照必须与当前完整身份和内容 revision 一致后才能展示。

## 关联业务影响

- Agent 节点、文档节点和生图节点的数据合同与交互保持不变。
- 生图节点已有的动态高度逻辑继续使用统一节点几何函数，不再由 WebView 另建一套碰撞算法。
- Canvas 引用携带 WebView 当前设备预设，使 Agent 能理解用户引用的是网页还是手机视图，但 HTML 仍只有一份。
- 批量删除、回收区、恢复、revision 冲突和权威 recovery 必须同时保持设备字段和缩略图失效规则。
- 普通 Agent 对话不因手动设备切换新增消息或工具记录。

## 性能与资源开销

- 平移、缩放和框选时 WebView 卡片只绘制 WebP，不执行页面脚本。
- 离屏窗口复用且截图串行，峰值 Chromium 实例数固定为 1。
- 预览仅由可见节点按需触发；同一完整目标在主进程和 Renderer 都进行请求合并。
- 缓存命中不重新渲染 HTML。预览文件按 revision 可达性清理，避免长期积累。
- 设备切换和内容更新是主要 CPU 峰值；其余时间增加的内存只来自当前可见缩略图。

## 测试策略

### BDD 合同与单元测试

1. 合法和非法设备预设、预览目标、预览快照的严格解析。
2. 旧 schema WebView 确定性迁移为网页模式，新 schema 缺失字段时 fail closed。
3. 网页和手机预设分别得到准确视口和卡片几何尺寸。
4. 节点设备 mutation 只修改目标 WebView，非 WebView 节点和未知节点 fail closed。
5. 离屏队列严格串行，相同目标合并，缓存命中不重复截图。
6. 内容或设备切换后旧快照不能覆盖新状态。
7. popup、网络、主 frame 和子 frame 导航全部被阻断。
8. IPC 四层只透传公开字段，未授权窗口、错误项目和伪造节点被拒绝。
9. 卡片加载、成功、失败、重试和设备菜单均保持画布点击、拖动与双击语义。
10. 动态节点矩形用于碰撞、全局追加和子节点扩展，现有生图比例测试继续通过。

### 集成与真实客户端验证

- 在同一画布创建网页与手机 WebView，确认外形、预览和标题状态可辨识。
- 切换设备后节点位置不变、尺寸改变、预览刷新且不产生 Agent 消息。
- 多节点情况下验证平移、缩放、框选、批量删除和从节点扩展。
- 双击与放大按钮打开详情，网页和手机视口均可运行原交互。
- 断网环境下生成预览并验证页面不能发起外部访问。
- 运行相关测试、`bun run typecheck` 和 `bun run electron:build`。

## 验收标准

1. WebView 卡片不展开详情也能显示页面静态缩略图。
2. 网页卡片为宽横向布局，手机卡片为窄纵向布局，尺寸符合本设计。
3. 用户可以从卡片和详情切换设备，两处状态保持一致。
4. 切换设备不调用 Agent、不复制 HTML、不新增普通对话记录。
5. 卡片预览不抢占画布交互，多节点画布不会常驻多个 iframe。
6. 预览失败不影响节点、HTML 和详情使用，并提供可恢复入口。
7. 旧 revision 或旧设备的迟到缩略图不能覆盖当前预览。
8. 详情与离屏截图均保持现有离线 CSP、sandbox 和 Electron 导航限制。

## 非目标

- 同一节点同时维护两份网页与手机 HTML。
- 同一节点并排显示两个设备预览。
- 平板、自定义尺寸、横竖屏旋转和自由输入 viewport。
- 在折叠卡片中直接操作网页。
- 设备切换后自动调用 Agent 重做设计。
- 自动重排或移动画布中的其他节点。
- 修改 README、教程或发布说明。
