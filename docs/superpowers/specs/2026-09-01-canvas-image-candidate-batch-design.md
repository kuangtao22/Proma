# Canvas 图片候选版本与批次验收设计

## 目标

图片修改不得覆盖旧资产，也不得因批量任务部分成功而让整套画布无提示地进入新旧混合状态。每个图片节点代表一个稳定业务对象，历次生成结果作为该节点下的不可变资产版本；只有明确采用后，候选版本才成为节点的当前正式资产。

本期聚焦 Canvas 图片节点。文档和 WebView 已有不可变 revision，可在后续复用批次验收协议，但不在本期扩展范围内。

## 当前问题

现有图片链路已经具备两项基础能力：

- 编辑任务以当前 `adoptedAssetId` 为来源，并通过 `parentAssetId` 保存版本血缘。
- 图片工作台保留 `imageVersions`，用户可以预览历史结果并重新设为当前。

但每个成功任务会立即采用自己的输出。批量重绘 14 个节点时，如果只有 2 个成功，画布会直接变成“2 个新版 + 12 个旧版”的混合正式状态。Agent 只能在对话中列出资产 ID，缺少可验收、可恢复的整批产品状态。

## 核心规则

### 节点与资产

- Canvas 图片节点身份保持稳定，不因修改而创建重复节点。
- 每次生成或编辑产生一个新的不可变 Asset；旧 Asset 不覆盖、不改写。
- 编辑输出继续保存 `parentAssetId`，形成可追踪的版本血缘。
- `adoptedAssetId` 只表示当前正式版本；候选结果不得提前写入该字段。
- 回退历史版本只切换当前采用指针，不复制 Asset，也不删除之后的版本。

### 候选版本

- 单节点生成和批量生成统一创建候选版本；单节点任务视为只有一个条目的批次。
- 成功输出首先登记为候选 Asset，图片工作台自动预览最新候选。
- 折叠卡片继续展示当前正式版本，并显示“有新版本”状态，避免候选内容被误认为已经生效。
- 用户可以在详情中对比当前正式版与候选版，并执行采用、保留旧版或放弃候选。

### 批次验收

同一次 Agent 规划或用户批量操作产生一个稳定的图片版本批次。批次保存每个目标节点的开始基线和候选结果，至少包含：

- 批次身份、Canvas 身份、创建来源和创建时间；
- 节点 ID、开始时的正式 Asset ID 与配置 revision；
- 对应 Job ID、候选 Asset ID 和条目状态；
- 批次状态与最终采用结果。

批次状态按事实推进：`running`、`partial`、`ready`、`adopted`、`abandoned`。失败条目保留错误和重试入口，不改变旧正式资产。

默认操作为：

1. `全部采用`：只有全部目标都有有效候选且基线未冲突时启用，一次性采用整批。
2. `继续补齐`：只重试未完成或失败条目，已成功候选保持不变，不重复付费生成。
3. `采用已成功项`：允许用户明确接受混合版本，并在操作前提示未成功节点仍保留旧版。
4. `放弃本批次`：正式版本不变；候选仍作为可审计历史保留，但不再显示为待验收。

## 一致性边界

### 采用事务

整批采用必须通过主进程的 Canvas 串行器和 workspace write lease 执行，并使用可恢复 intent 固化：

- 每个节点的旧 Asset、候选 Asset、配置 revision 和 Canvas revision；
- 全部目标验证结果；
- 每个模块配置与 Canvas 节点投影的提交进度；
- 最终批次状态。

提交前先验证所有候选仍归属于对应节点、Job 已成功、Asset 文件存在且血缘闭合。任何基线变化都进入显式冲突，不覆盖用户在批次运行期间完成的其它采用操作。

多文件提交采用逻辑原子语义：提交期间 Renderer 继续展示提交前的正式版本；成功后一次刷新整批；进程中断时由 intent 对账并继续完成或保持旧版，不能向用户暴露半批正式状态。

### 历史与下游

- 历史 Agent 消息和历史 Run 继续引用运行当时固化的 Asset ID，不随当前版本切换而改写。
- 新任务只读取节点当前已采用 Asset，候选版本不能作为隐式输入。
- 正式采用后，`reference`、`depends-on` 和 `derives` 关系的下游节点标记为“上游已更新”；`association` 不产生待更新状态。
- 下游只提示重新规划或重新运行，不自动触发付费任务。

## 用户界面

### 画布卡片

- 缩略图始终代表当前正式版本。
- 存在候选时显示紧凑的“新版本”标记；批次失败时显示“部分完成”。
- 标记可进入详情，但不在卡片内堆叠版本操作。

### 图片详情

- 顶部明确区分“当前版本”和“候选版本”。
- 默认预览最新候选，提供当前/候选切换与并排比较。
- 历史版本继续保留，当前正式版、当前候选和普通历史版使用不同文字状态，不只依赖颜色。
- 单节点采用只处理当前节点；属于批次的候选同时提供“查看批次”入口。

### 批次面板

- 显示 `已完成数量 / 总数量`、失败数量和仍在运行数量。
- 每个条目展示节点标题、旧版缩略图、候选缩略图和任务状态。
- 主操作根据状态显示“全部采用”或“继续补齐”；“采用已成功项”作为次级操作。
- Agent 对话只显示结构化批次摘要和“打开画布验收”入口，不再要求用户依赖裸 Asset ID 判断结果。

## Agent 行为

- Agent 创建批量重绘时必须复用同一批次身份，重试只补齐失败条目。
- Agent 可以检查批次进度和候选质量，但不得把候选描述为已经正式替换。
- Agent 未获得采用授权时，只能汇报“候选已生成”。
- 用户明确要求整批采用后，Agent 调用批次采用能力；部分采用必须再次明确说明会产生新旧混合版本。
- 采用完成后，Agent 汇报采用数量、保留旧版数量和受影响的待更新下游节点。

## 异常处理

- 部分任务失败：批次进入 `partial`，旧正式版本保持不变，允许只重试失败项。
- 候选 Asset 丢失或校验失败：对应条目标记不可采用，不影响其它候选和旧版。
- 节点已删除：条目失效，批次采用不得重建节点；候选留在历史审计范围。
- 基线 revision 或正式 Asset 已变化：进入冲突，要求用户重新基于当前版本生成或放弃该条候选。
- 采用提交不确定：阻断重复采用，先通过 intent 和权威 LOAD 对账。
- 批次放弃后迟到的 Job 完成：结果只登记为已放弃批次的历史候选，不恢复待验收状态。

## 删除规则

本期不提供自动清理旧版本。旧 Asset、候选 Asset 和被回退版本默认保留，以保证历史 Run、Agent 引用和回退能力可靠。

后续若增加清理，只有同时满足“非当前、非候选、无历史引用、无子版本依赖”的 Asset 才允许删除，并必须经过明确确认。

## 关联影响

- 图片生成成功不再立即改变卡片正式缩略图，现有依赖“成功即采用”的任务终态需要拆分为“输出登记”和“采用提交”。
- Canvas 图片工作台、Agent Canvas 工具、批量运行、通知和活动摘要都要识别候选批次状态。
- 现有单图片 `adoptAsset` 能力继续作为底层校验参考，但整批采用不能由 Renderer 循环调用单节点 IPC，否则会重新暴露半批状态。
- 普通 Agent 会话、非图片节点、旧 Design 兼容画布和历史消息读取不改变。

## 性能与资源

- Asset 文件不复制，版本和批次只新增有界 JSON 元数据与指针切换。
- Canvas 初始加载只读取活跃批次摘要；条目详情和候选缩略图按需加载。
- 批次列表和单节点版本列表都设置数量上限与稳定排序，避免长期项目无界渲染。
- 采用事务为 O(n) 节点校验和提交，不扫描项目全部 Asset；使用节点、Job 和 Asset 索引完成归属检查。
- 候选默认保留会增加磁盘占用，后续独立提供可审计清理策略，不在生成路径同步清理。

## 验证

- BDD：单节点生成成功后旧 `adoptedAssetId` 不变，新 Asset 出现在候选与版本历史。
- BDD：14 节点只有 2 个成功时，批次为 `partial`，14 个节点正式版本全部不变。
- BDD：全部成功后整批采用一次刷新全部节点和模块配置，无中间混合投影。
- BDD：采用已成功项时只更新成功条目，并明确保留失败条目的旧版。
- BDD：基线变化、节点删除、候选丢失和 revision 冲突均拒绝覆盖。
- BDD：中断后的 intent 对账不会重复采用或暴露半批状态。
- BDD：采用后只标记数据关系下游待更新，不自动运行任务。
- 性能测试：千节点 Canvas 只加载活跃批次摘要，折叠卡片不读取候选原图。

## 完成标准

- 生成、修改、重试、采用和回退都不会覆盖或丢失旧 Asset。
- 批量任务部分完成时，画布正式版本保持一致且状态清晰。
- 用户能在画布内完成旧版/候选对比、补齐失败项和整批采用，不需要依赖 Agent 输出的 Asset ID。
- Agent、Renderer 和主进程对“候选”和“当前正式版本”的含义一致。
