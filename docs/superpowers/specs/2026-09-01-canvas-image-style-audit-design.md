# Canvas 全量图片风格核对设计

## 目标

让普通 Agent 能在已关联画布中可靠发现全部图片节点，并基于每个节点当前正式采用的缩略图完成真实视觉核对，而不是只比较提示词或依赖画布截图。

用户只要求“核对”“检查”或“评审”时，流程必须保持只读。发现不统一图片后，Agent 只输出差异清单和修改建议；只有用户明确要求修正提示词、立即重新生成或采用候选版本时，才进入对应写入、付费审批和验收流程。

## 方案选择

采用两个职责独立的只读工具：

- `canvas_list_nodes`：分页枚举当前会话已关联画布的节点摘要。
- `canvas_inspect_images`：按节点 ID 读取当前正式采用资产的受限缩略图，并把图片内容交给当前 Agent 视觉模型。

不扩展 `canvas_read` 承载全量枚举与图片内容。`canvas_read` 继续负责已知节点的正文、配置、版本与邻接关系，避免普通文本读取承担图片上下文成本。

不使用 Computer Use 截取画布作为正式核对链路。画布截图受缩放、遮挡、虚拟化和当前视口影响，不能证明已经检查全部节点。

## 用户语义

### 只读核对

以下表达只授权读取和分析：

- “核对所有图片是否统一风格。”
- “检查这些分镜有没有人物或色调不一致。”
- “评审整套宣传图的视觉一致性。”

Agent 必须完成节点枚举、分批看图和结果汇总，但不得调用 `canvas_update_artifact`、`canvas_run_nodes` 或候选采用能力。

报告至少区分：

- 一致：没有发现需要处理的明显偏差。
- 异常：指出节点、偏差维度和建议修正方向。
- 无法判断：缺少正式采用图片、缩略图损坏、读取失败或模型不支持视觉输入。

### 修改提示词

用户明确要求“统一提示词”时，Agent 只更新视觉异常节点的图片提示词，保留稳定节点 ID、当前正式资产和历史版本，不自动调用生图。

### 重新生成

用户明确要求“把不统一的图片重新生成”或等价立即执行意图时，Agent 可以先更新异常节点提示词，再把这些节点一次提交给 `canvas_run_nodes`。该工具继续要求单次付费审批，未通过审批不得启动任务。

成功图片先进入候选批次。未获得采用授权前，当前正式资产、卡片缩略图和下游读取仍保持旧版本；Agent 不得把候选描述为已经替换。

## `canvas_list_nodes`

### 输入

- `canvasId`：当前 Agent 已关联的画布 ID。
- `kind`：可选节点类型过滤；风格核对使用 `image`。
- `cursor`：可选的不透明分页游标。
- `limit`：可选页大小，默认 50，最大 100。

### 输出

- 当前 `canvasId` 和权威画布 `revision`。
- 节点摘要：`nodeId`、`kind`、`title`、内容或配置 revision。
- 图片节点额外返回 `hasAdoptedAsset`，不返回 Asset ID、媒体 URL 或本地路径。
- `nextCursor` 和 `hasMore`。

节点按权威文档顺序稳定分页。游标必须绑定 `projectId + canvasId + revision + kind + offset`；画布 revision 改变后旧游标失效，Agent 重新从第一页读取，禁止把不同 revision 的页面拼成一次全量结论。

工具每次调用都重新执行当前会话、项目和画布关联授权，不因为上一页成功而缓存或扩大权限。

## `canvas_inspect_images`

### 输入

- `canvasId`：当前 Agent 已关联的画布 ID。
- `nodeIds`：一到四个图片节点 ID，稳定去重。
- `expectedRevision`：来自 `canvas_list_nodes` 的权威画布 revision。

### 权威校验

工具在读取媒体前完成：

1. 复核当前会话仍可读取项目且画布仍有关联。
2. 复核画布 revision 等于 `expectedRevision`。
3. 复核每个节点存在且类型为 `image`。
4. 从图片模块配置与画布节点共同确认当前 `adoptedAssetId` 一致。
5. 只通过 Design Asset Service 的受控读取能力取得该资产缩略图，禁止按模型提供的路径重新打开文件。

任一节点缺少正式采用资产时，返回结构化 `missing-adopted-asset` 状态，不读取候选或历史版本替代。身份不一致、资产归属异常或文件安全校验失败时 fail closed，返回稳定公开错误，不暴露磁盘路径。

### 图片输出

每张图片前放置一个短文本标记，包含 `nodeId`、标题和状态，随后紧邻一个 Pi `ImageContent`，保证模型可以把视觉内容与节点身份对应。

- 只返回现有受控缩略图，不读取原始大图。
- 单批最多四张。
- 单张解码后最大 512 KiB，单次合计最大 2 MiB。
- 仅允许通过既有图片签名校验的 PNG、JPEG、GIF 或 WebP。
- 不在 `details` 或文本中复制 base64、媒体 URL、本地路径和 Asset ID。
- 图片块继续经过 Pi Agent Adapter 的统一图片内容清洗边界。

缩略图超出单张预算时由现有 `sharp` 依赖在内存中等比缩放和压缩，不写临时文件、不修改正式缩略图。无法压入预算时将该节点标记为 `image-too-large`，Agent 不得据此判断风格。

图片内容会进入当前 Agent 工具结果和会话记录，因此限制四张一批和 2 MiB 总量；Agent 完成一批判断后再读取下一批，不把同一节点重复加入上下文。

## Agent 核对流程

1. 调用 `canvas_get_context`，确定当前关联或活动画布。
2. 使用 `canvas_list_nodes(kind: image)` 分页取得同一 revision 下的全部图片节点。
3. 将存在正式采用资产的节点按四张一批调用 `canvas_inspect_images`。
4. 按统一维度记录每张图片的观察结果：表现媒介、人物身份与年龄外观、服装道具、场景时间、色调光线、镜头与构图、文字与品牌元素。
5. 汇总一致、异常和无法判断节点，给出只读报告。
6. 只有用户明确要求后，才对异常节点更新提示词或启动候选生成。

同一画布超过一页或一批时，Agent 必须完成全部页面和批次后再声称“已核对所有图片”。中途失败时报告已检查数量、未检查数量和原因，不得以局部结果冒充全量结论。

## Skill 约束

`canvas-production` 默认 Skill 升级一个 patch 版本，并新增图片一致性核对工作流：

- “核对”与“修改”是不同意图。
- 全量视觉核对必须先枚举，再分批读取当前采用缩略图。
- 不能只比较提示词后声称已经看过图片。
- 不能通过画布截图或当前可见节点推断全量结论。
- 用户未明确要求修改时，不更新提示词、不运行图片节点、不创建报告文档节点。
- 用户要求保存报告时，才创建或更新文档节点。

主进程最小系统提示同步保留相同安全边界，避免 Skill 被停用时出现自动生图或自动覆盖。

## 架构边界

改动限定在主进程 Agent Canvas 工具与默认 Skill：

- `canvas-tool-provider.ts`：新增两个只读工具、分页游标和图片结果构造。
- `canvas-document-ipc.ts`：向工具 Provider 注入缩略图安全读取能力。
- Design Asset Service：增加按项目和 Asset 身份读取受控缩略图字节的窄接口，复用现有普通文件、归属和图片签名校验。
- `canvas-production/SKILL.md`：增加意图与核对流程并递增 patch 版本。

不新增 Renderer IPC、Preload API、Jotai 状态或画布文档字段。Agent 工具在 Electron 主进程内部直接复用现有权威服务，不建立第二套素材索引。

## 关联影响

- `CANVAS_TOOL_NAMES` 从七个扩展为九个；普通 Agent 原有工具继续以 `extend` 模式保留。
- 两个新工具只读且不进入 `singleApprovalToolNames`。
- `canvas_run_nodes`、候选批次、批量采用和历史版本合同保持不变。
- 现有 `canvas_read` 的 32 节点和 32 KiB 文本预算保持不变。
- 画布节点、素材或图片配置在核对期间发生变化时，revision 校验使当前批次失效，Agent 重新枚举，避免混合新旧正式状态。
- 当前模型无法消费图片工具结果时，Agent 明确降级为“只能检查提示词与配置”，不得声称完成视觉核对。

## 性能与资源

- 只有用户发起视觉核对时才读取缩略图，不增加轮询或后台扫描。
- 节点枚举只遍历权威文档摘要，单页最多 100 条。
- 图片每批最多四张、合计最多 2 MiB，避免一次工具结果撑爆上下文或 JSONL。
- 优先复用已有缩略图；只有超限时在内存中压缩，不复制正式资产、不写缓存或临时文件。
- 全流程不加载原始图片，不触发生图模型，也不产生新的 Design Job。

## 错误处理

- 未关联画布：`CANVAS_ACCESS_DENIED`。
- 分页或检查期间 revision 改变：`CANVAS_REVISION_CONFLICT`，重新枚举。
- 节点不存在或类型错误：返回稳定节点级状态；调用整体不伪造图片。
- 当前采用身份不一致、路径越界、符号链接替换、文件签名错误：fail closed 并记录中文主进程日志，对 Agent 只暴露稳定公开状态。
- 图片模型不支持视觉输入：停止视觉批次，输出能力限制和未检查数量。
- 部分图片不可读：继续检查其它合法节点，并在报告中单独列出。

## BDD 验证

- Given 已关联画布包含多种节点，When 按 `image` 分页枚举，Then 只返回图片摘要且不泄露 Asset ID 或路径。
- Given 枚举后画布 revision 改变，When 使用旧游标或旧 revision 检查，Then 明确冲突且不读取媒体。
- Given 四个图片节点都有当前采用资产，When 视觉检查，Then 文本身份与四个有效图片块按顺序对应。
- Given 图片节点只有候选或历史资产，When 视觉检查，Then 返回缺少当前采用资产且不使用候选替代。
- Given 画布节点与图片配置的采用 Asset 不一致，When 视觉检查，Then fail closed 且不返回任一磁盘路径。
- Given 缩略图损坏、越界或被链接替换，When 视觉检查，Then 只返回公开失败状态。
- Given 图片超出预算，When 视觉检查，Then 在内存中压缩或标记无法检查，单批图片总量不超过 2 MiB。
- Given 用户只要求核对，When Agent 遵循默认 Skill，Then 只使用读取工具，不调用更新、运行或采用能力。
- Given 用户明确要求重做异常图片，When Agent 完成核对，Then 只更新和运行异常节点，运行仍经过单次审批且结果保持候选。
- Given 默认 Skill 发布，When 校验发布合同，Then 版本递增且九个 Canvas 工具与只读边界全部出现。

## 完成标准

- Agent 能证明已经枚举并看过同一画布 revision 下的全部当前采用图片。
- “核对所有图片”不会修改提示词、运行生图或替换正式资产。
- 全量报告能精确引用异常节点，并区分一致、异常和无法判断。
- 明确修正请求只处理异常节点，保留旧资产并沿用审批与候选验收流程。
- 工具响应不泄露路径、媒体令牌或 Asset ID，且图片上下文和持久化体积受硬预算限制。
