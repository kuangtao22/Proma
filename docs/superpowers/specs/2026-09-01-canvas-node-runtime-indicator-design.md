# Canvas 节点运行状态边框设计

## 目标

用户无需打开节点详情即可判断哪些节点正在执行、哪些正在排队或等待审批。实际运行中的节点在卡片外圈显示沿边框流动的虚线；该反馈适用于 Agent、生图、文档和 WebView 等全部 Canvas 节点类型。

## 状态规则

节点活动状态使用结构化枚举，不从用户可见文案反推：

- `idle`：无活动边框。
- `queued`：慢速流动虚线，表示已经排队但尚未执行，并在用户点击运行后立即提供反馈。
- `running`：流动虚线，表示当前正在执行。
- `waiting-approval`：静态强调边框，表示需要用户决策，不表示仍在计算或持续计费。

成功、失败、取消或中断后立即退出 `running`。图片任务生成成功但等待候选版本验收时不继续运行动画，改由“有新版本”状态表达。

节点原有业务状态继续显示在卡片正文中；活动边框只负责跨类型的执行反馈，不能取代错误、候选版本或审批文案。

## 状态来源

Workspace 聚合权威运行事实，向 Graph 传递按节点 ID 隔离的轻量活动状态映射。卡片只消费最终状态，不订阅消息、任务详情或内容正文。

状态来源包括：

- Agent 节点：当前会话的权威 active run 与 Renderer 乐观发送准入状态。
- 生图节点：对应 Job 的 `queued`、`running` 与审批等待状态。
- 文档和 WebView：Agent Canvas Run 或长期节点操作的权威生命周期。
- 批量任务：每个条目独立投影，不能用整个批次状态让未运行节点一起转动。

同一节点同时出现多个事实时，显示优先级固定为：

`running` > `waiting-approval` > `queued` > `idle`。

故障节点仍优先显示故障业务状态，但如果主进程确认该节点仍有可停止的真实运行，运行边框保留，方便用户判断资源尚未释放。

## 视觉表现

### 运行中

- 卡片外侧增加一层不占布局的虚线轮廓。
- 虚线沿卡片四周持续流动，不旋转或缩放卡片本体。
- 动画速度稳定，不随节点尺寸改变明显加快。
- 轮廓位于卡片实线边框外侧，避免覆盖内容和选中态。

### 选中与运行叠加

- 选中态继续使用现有实线边框和 ring。
- 运行虚线作为更外层独立覆盖层，两种状态同时可见。
- Hover、Focus、选中和运行都不得改变节点几何尺寸，避免 XYFlow 重新布局或连线跳动。

### 排队和待审批

- `queued` 使用慢于运行态的流动虚线，既立即反馈提交成功，又不冒充真实执行。
- `waiting-approval` 使用静态强调轮廓，并由卡片正文或审批入口说明需要操作。
- 不使用持续闪烁，避免与错误告警混淆并降低视觉疲劳。

## 实现边界

`CanvasNodeCard` 增加结构化 `activityState` 输入，并在卡片壳外渲染统一活动轮廓。动画层使用 SVG `rect` 与 `stroke-dasharray`，通过 CSS `stroke-dashoffset` 产生沿边框流动效果：

- SVG 使用卡片当前动态宽高，不假设固定 288×144 尺寸。
- 动画层设置 `pointer-events: none` 和 `aria-hidden="true"`。
- 不使用 JavaScript 定时器，不触发节点状态轮询。
- 不通过 `statusLabel` 字符串比较判断运行态。

Renderer 的 Canvas Graph 投影只接收节点活动状态映射。现有 `runningSessionIds` 可作为 Agent 来源，但应在 Workspace 聚合层转换，避免卡片组件理解会话、Job 或批次语义。

## 无障碍

- 卡片 `aria-label` 和现有 `role="status"` 继续包含明确的中文状态文案。
- 动画轮廓本身不进入辅助技术树，避免重复播报。
- `prefers-reduced-motion: reduce` 下停止排队与运行虚线流动，保留静态轮廓和明确状态文字。
- 状态区别同时依赖文字、线型和运动，不只依赖颜色。

## 生命周期与异常

- 排队开始：权威 Job 将目标节点设为 `queued`，立即显示慢速流动反馈。
- 运行开始：权威或受保护的乐观状态将目标节点设为 `running`，切换为更快的流动反馈。
- 运行结束：成功、失败、取消和中断事件只清理匹配 generation 的状态，迟到事件不得关闭新一代运行边框。
- Canvas 切换：活动映射按 Canvas 身份隔离，旧 Canvas 事件不得污染当前画布。
- 节点删除：立即从活动映射移除；后台任务是否停止仍由现有删除和停止合同处理。
- 主进程状态暂不可用：保持最后一次已确认状态的有界短期投影；完成权威 LOAD 后对账，不能永久转动。

## 关联影响

- Agent 节点现有 Loader 图标可以保留，外圈提供远距离可见的统一反馈。
- 生图节点需要把活跃 Job 摘要提升到 Workspace 轻量状态，不能为每张折叠卡片加载完整图片模块。
- 候选图片验收、历史版本和当前正式资产不因活动边框改变。
- 文档/WebView 的本地保存 Spinner 不等同于 Agent 长任务；只有纳入统一节点活动生命周期的操作才显示外圈。
- 画布选择、拖拽、连线、双击详情和节点侧菜单交互保持不变。

## 性能

- 仅活动节点挂载轮廓层；空闲节点不增加 SVG DOM。
- 动画完全由 CSS 驱动，不增加 React 帧更新或全局计时器。
- 活动状态映射按节点 ID O(1) 查询，千节点投影不逐节点扫描任务集合。
- 状态事件只更新发生变化的节点映射，避免每个流式 token 引发整张 Canvas 状态变化。
- 大量节点同时运行时允许降低动画频率，但不牺牲状态准确性。

## 验证

- BDD：`queued` 节点渲染独立慢速流动虚线，`running` 节点渲染更快的流动虚线。
- BDD：`idle` 节点不渲染活动轮廓，`waiting-approval` 渲染静态强调轮廓。
- BDD：选中且运行时同时保留选中 ring 和活动轮廓。
- BDD：图片动态比例、桌面 WebView 和手机 WebView 的轮廓尺寸跟随卡片几何。
- BDD：运行结束、取消、中断和匹配 generation 的失败事件清除动画。
- BDD：迟到旧 generation 事件不清除新的运行状态。
- BDD：减少动态效果模式下轮廓静止且状态文案仍可访问。
- 性能测试：1,000 个空闲节点不挂载活动 SVG，活动映射投影保持线性。

## 完成标准

- 用户点击生成后无需等待 Job 真正启动，就能在缩放后的画布上看到排队反馈，并区分实际运行节点。
- 排队、运行、待审批和候选待验收不会使用同一种动态反馈。
- 动画不造成卡片位移、连线跳动、鼠标事件冲突或额外 I/O。
- 四类节点共享同一活动状态合同，不为单一节点类型硬编码视觉逻辑。
