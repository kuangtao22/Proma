# Canvas 详情浮窗与节点紧凑布局设计

## 目标

解决两类直接影响画布可用性的布局问题：

1. 节点详情第一次打开时可能因画布缩放和剩余空间收敛而过小，内容无法正常阅读。
2. Agent 批量创建节点时沿 X 轴无限追加，用户必须大幅缩小画布才能看到完整产物组。

详情工作台改为不受 Canvas zoom 影响的屏幕空间浮窗；Agent 与用户后续创建的节点统一采用关系优先的紧凑网格。已有节点不自动移动，只有用户显式执行“整理布局”时才重排选定范围。

## 当前问题

### 详情工作台

当前工作台渲染在 ReactFlow 节点内部，会继承画布缩放。首次打开时还会根据节点右下方剩余空间收敛尺寸；当节点位于视口边缘或用户已经缩小画布时，工作台可能被压缩到小于正常阅读所需尺寸。

当前 `workbenchSize` 还是会话级单值。用户调整一类节点后，尺寸可能被另一类节点复用，无法表达图片双栏、文档编辑器和手机 WebView 的不同空间需求。

### Agent 创建位置

Agent 产物创建缺省使用“当前最右节点 X + 固定间距，Y = 0”。连续创建多个产物会形成超长单行；从同一来源衍生时也缺少兄弟节点槽位和真实尺寸避让。

模型可传入绝对坐标，但排版属于 Host 的交互职责。让 Agent 为每个节点计算坐标既不稳定，也浪费上下文，并且无法可靠获知当前视口和动态卡片尺寸。

## 详情工作台

### 屏幕空间浮窗

- 工作台从节点内部的世界坐标覆盖层提升到 Canvas surface 上层。
- 浮窗使用屏幕像素尺寸，不随画布平移和 zoom 缩放。
- 当前节点继续保持选中，浮窗保存完整节点身份，不通过 DOM 相邻关系判断归属。
- 平移或缩放画布时浮窗保持可读；节点离开视口后浮窗仍保持打开，标题继续说明当前节点。
- 浮窗不缩窄主 Canvas，也不恢复右侧固定详情栏。

### 初始尺寸

每类节点使用稳定的首次打开尺寸：

| 节点类型 | 默认宽度 | 默认高度 |
| --- | ---: | ---: |
| Agent | 760px | 640px |
| 生图 | 960px | 700px |
| 文档 | 900px | 700px |
| 桌面 WebView | 960px | 720px |
| 手机 WebView | 520px | 720px |

当 Canvas surface 小于默认尺寸时，浮窗限制为可视区域减去 24px 外边距。正常桌面空间不再因为节点靠近边缘而把工作台压缩到 360×320。

### 浮窗位置

- 首次打开优先放在目标节点屏幕坐标右侧，并保留 12px 间距。
- 右侧空间不足时尝试左侧；两侧都不足时在 Canvas surface 内居中。
- 所有位置都限制在 Canvas 可视边界内，标题栏、关闭按钮和右下角缩放手柄始终可达。
- 浮窗位置不写入共享 Canvas 文档，只属于当前 Agent 会话视图。
- 用户可拖动标题栏移动浮窗；拖动过程只更新局部预览，结束时提交一次会话视图位置。
- 切换节点时复用当前浮窗位置，避免连续查看节点时窗口来回跳动；首次打开新的 Canvas 才重新计算。

### 尺寸持久化

- 用户拖拽后的尺寸按 `nodeId` 保存在当前会话的 Canvas view state 中。
- 节点没有自定义尺寸时使用对应类型默认值。
- 节点删除或 view 卸载时清理对应尺寸；状态集合保持有界。
- WebView 设备预设改变时，已有用户自定义尺寸保留；未自定义时重新使用桌面或手机默认值。
- 缩放拖拽继续只在手势结束时提交一次 view state，过程只更新浮窗局部预览。

## 自动节点布局

### Host 负责布局

- Agent 工具主要表达产物类型、来源节点和关系，不承担普通场景的绝对坐标计算。
- 未显式要求版式时，Host 忽略缺省线性追加规则并计算安全落点。
- Agent 明确提供的位置仍要通过有限数值、重叠和现有图边界扩展带校验；不合理位置回退 Host 自动布局，不直接制造远距离节点。
- Renderer 顶部添加、节点侧扩展和主进程 Agent 产物创建共用同一纯布局引擎，但锚点来自各自可信边界：Renderer 使用当前视口，主进程 Agent 创建使用权威图和来源节点。

### 关系优先的紧凑网格

- 有来源节点时，以来源节点右侧为局部布局锚点，按稳定槽位顺序寻找最近空位。
- 同一来源的兄弟节点优先填充来源右侧的紧凑矩形区域，不把每个新节点继续向全局最右侧追加。
- 无需预先知道批次总数；连续创建使用由近到远的方形环槽位，常见 10～20 个常规节点自然形成接近 3～5 列的紧凑区域。
- `derives` 和 `depends-on` 保持左到右的方向；`reference` 和 `association` 可使用同一紧凑分组，但不为了排版新增不存在的关系。
- Renderer 无来源新增以当前 Canvas viewport 中心为锚点；主进程 Agent 无来源新增以现有图的紧凑边界或空图原点为锚点。

### 真实尺寸与间距

- 碰撞检测使用节点真实宽高：常规节点、生图比例高度、桌面 WebView 和手机 WebView 分别计算。
- 节点之间保持至少 24px 净间距；关系线、选中 ring 和运行虚线不改变持久布局尺寸。
- 自动布局只寻找新节点的落点，不推开已有节点。
- 当前视口附近没有可用空间时，优先在相邻行列扩展，禁止直接跳到全局最右侧数千像素之外。
- 单次批量创建固定布局输入和节点顺序，重试得到同一位置，不因部分完成而重新洗牌。

## 手动整理布局

### 入口与范围

- 顶部工具栏增加“整理布局”图标按钮和菜单，并提供 Tooltip。
- 菜单明确提供“整理选中节点”和“整理当前可见节点”；不可用项直接禁用，不使用隐式范围。
- “整理整个画布”作为独立菜单项，展示影响节点数量并确认，避免误改大型画布。

### 行为

- 整理布局基于当前节点关系、真实尺寸和稳定节点 ID 计算确定性位置。
- 有向关系尽量保持左到右层级；同层节点使用紧凑网格。
- 无关系节点保持独立分组，不为了视觉整齐自动连线。
- 只提交 `move-nodes` 类位置 mutation，不修改节点身份、内容、版本、关系或 viewport。
- 整理操作通过一次原子位置批次提交；失败时保留全部旧位置，不产生局部移动。本期不额外引入通用撤销历史。

## 与运行状态边框的关系

- 运行虚线属于视觉覆盖层，不参与节点真实尺寸和碰撞计算。
- 浮窗打开、调整尺寸或移动不改变节点运行状态。
- 自动布局和整理布局期间，运行中的节点可以保持原位；默认不自动移动正在运行或等待审批的节点。
- 用户显式选择包含运行节点的整理范围时，界面说明这些节点将被跳过，避免任务期间节点位置突变。

## 异常与并发

- 创建期间 Canvas revision 变化：重新读取权威文档并用相同布局意图计算未占用槽位，不复用已经冲突的绝对位置。
- Agent 批次部分成功：已创建节点位置固定，补齐失败项只填充原批次预留槽位。
- 用户手动移动节点：后续自动创建尊重最新位置，不把节点拉回旧网格。
- 整理布局与结构操作冲突：服从现有 Canvas serializer 和结构令牌，失败后不保留局部移动。
- 浮窗目标节点被删除：关闭浮窗并清理该节点尺寸状态。
- Canvas surface 极小：浮窗占满可用区域但保留 12px 边距；不写入小于可操作范围的永久自定义尺寸。

## 关联影响

- `CanvasNodeWorkbenchOverlay` 的内容壳和缩放控制器可复用，但挂载位置从节点内部移到 Workspace surface overlay。
- Agent Canvas view state 从单个 `workbenchSize` 迁移为有界的按节点尺寸映射，并增加当前浮窗位置。
- `canvas_create_artifact` 的默认位置解析、Renderer 手工创建位置和节点侧扩展位置需要共享纯布局 helper。
- `canvas-production` Skill 删除普通场景下主动计算坐标的责任，只在用户明确要求特殊版式时提供布局意图。
- 旧 Canvas 节点坐标不迁移、不自动改写；打开旧画布没有图 revision 变化。
- 图片候选批次、活动状态边框、内容版本和 Agent 历史引用不因布局调整而改变。

## 性能

- 创建落点使用节点矩形空间索引或按批次构建的网格占用索引，避免批量创建逐项对全部节点反复 O(n²) 扫描。
- 一次批量布局在内存中规划全部候选位置，再通过现有批处理事务提交。
- 浮窗尺寸和位置属于单个会话 view state，不触发 Canvas 文档保存和跨会话广播。
- 平移、缩放和浮窗拖拽不读取节点正文或任务详情。
- 千节点画布的“整理可见分组”只处理范围内节点；整图整理为显式重操作。

## 验证

- BDD：不同节点类型首次打开使用对应默认尺寸，Canvas zoom 不改变屏幕尺寸。
- BDD：节点位于视口边缘时浮窗改换方向或居中，不缩成不可读尺寸。
- BDD：用户调整一个节点后只保存该节点尺寸，其他类型仍使用默认值。
- BDD：14 个无来源常规节点围绕对应入口的可信锚点形成约 3～5 列的紧凑网格。
- BDD：同一来源的多个衍生节点换行排列且不重叠。
- BDD：桌面 WebView、手机 WebView 和动态比例图片按真实尺寸避让。
- BDD：Agent 提供极远、重叠或非有限坐标时回退 Host 安全布局。
- BDD：旧画布加载不产生位置 mutation；只有新建或显式整理才移动节点。
- BDD：整理多选只移动选区，运行中节点被跳过且关系不变。
- 性能测试：千节点批量规划使用有界索引，新增 100 个节点不进行节点数乘新增数的全量碰撞扫描。

## 完成标准

- 任意正常桌面视口首次打开详情都能直接阅读核心内容和操作按钮。
- 工作台尺寸不受 Canvas zoom 影响，用户调整不会污染其他节点。
- Agent 创建常见的 10～20 个关联产物时无需极端缩放即可看到完整分组。
- 旧画布布局保持不变，用户可以主动整理选中节点或明确整理整图。
- 自动布局、运行状态边框和候选版本系统使用独立状态边界，不相互覆盖业务事实。
