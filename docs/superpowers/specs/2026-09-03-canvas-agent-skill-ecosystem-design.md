# Canvas、Agent 与第三方 Skill 生态设计

日期：2026-09-03

状态：已完成交互讨论，等待书面规格复核

## 结论

Proma Canvas 采用“合同驱动的人机共创”架构：普通 Agent 理解用户目标并负责跨画布总编排，Canvas Agent 只承担需要长期状态、独立上下文或反复迭代的专业分支，图片、视频等单次模型调用继续使用不可见的执行 Agent。三类 Agent 共享同一份 `CreativeTaskContract`，由原生 Canvas Kernel 校验节点类型、真实输入、正式版本、权限、审批和恢复事实。

Canvas 不把电影、小红书、交互设计等场景写死为产品代码。Proma 内置 `canvas-production` 负责把领域方法编译为通用产物图；网上下载的普通专业 `SKILL.md` 通过通用 Skill-to-Canvas Adapter 生成本地能力画像，再与 `canvas-production` 组合。第三方 Skill 不需要认识 Proma，也不能获得额外权限、注册任意代码或绕过 Host 合同。

节点卡片始终展示正式采用版本，下游也只消费同一正式版本。新生成结果只形成候选并显示“有新版本”徽标；打开详情后才比较、采用或放弃。只有采用成功才原子切换卡片与输入绑定，并把受影响下游标记为待更新。

本设计分四阶段交付：可信数据底座、Agent/Skill 编排、视频音频扩展、小红书视频标杆验证。每阶段都必须独立可用、可测试、可回滚。

## 当前问题

### 节点类型与真实输入脱节

当前 Canvas 只有 `agent`、`image`、`document`、`webview` 四类节点。图片运行解析器只读取直接 `reference` 入边；图片节点必须存在 `adoptedAssetId` 才能提供真实媒体，WebView 只提供安全文本摘要。

因此 Agent 即使把 IP 三视图做成 WebView 并连到分镜节点，图在视觉上有关联，也不能作为真实图片参考进入模型。当前 Host 能证明结构合法，但不能证明用户要求的专业输入合同已经满足。

### 三类 Agent 的产品语义混淆

当前图片生成会创建隐藏 Design/Pi Agent，因此图片节点运行时出现“Agent 正在整理上下文”的文案。该 Agent 不是画布上的 Canvas Agent，也不表示上游存在 Agent 节点。

普通 Agent 已能创建文档、WebView 和图片产物，但不能通过现有 `canvas_create_artifact` 自动创建 Canvas Agent。Canvas Agent 仍主要由用户从画布 UI 创建，导致普通对话与长期画布角色之间存在断层。

### 版本展示与正式依赖需要统一

当前候选批次策略正确地避免新结果静默覆盖正式版本，但首次生成后当前图片区仍跟随 `adoptedAssetId`，用户容易把“候选已生成”理解为“没有生成结果”。若直接改为卡片展示最新候选，又会出现用户看到候选 B、下游实际仍消费正式 A 的认知冲突。

### Skill 只能软约束 Agent

Proma 已能加载工作区 Skill，并向普通 Agent 和 Canvas Agent 提供受控 Canvas 工具。第三方专业 Skill 可以影响模型的方法与步骤，但没有统一的输入、输出、工具依赖、长期角色和验收描述。模型需要临场把 Skill 自然语言映射为节点和关系，结果难以稳定复现。

### 当前没有视频生产闭环

工具栏中的视频节点仍为禁用状态，`CanvasNodeKind` 不包含视频或音频，`canvas_run_nodes` 只执行图片节点。因此当前系统可以完成小红书视频的策划、脚本、参考图、分镜和封面，但不能表达首尾帧到视频、配音、字幕、时间线和成片导出的完整链路。

## 目标

- 用户用普通语言描述目标后，普通 Agent 能自主创建适合本次任务的画布，不复制固定模板。
- 节点与边具备可验证的媒体能力和输入绑定，错误类型在付费运行前阻断。
- 普通 Agent 能按明确条件自动创建长期 Canvas Agent，并保持作用域隔离。
- 网上下载的普通专业 Skill 无需 Proma 专用改造即可参与 Canvas 编排。
- Skill、用户目标、实际输入版本、模型工具调用和产物之间可追溯。
- 卡片展示、正式采用内容和下游消费版本始终一致。
- 上游正式采用后，免费可逆任务可自动重算；付费任务只形成合并审批计划。
- 新增视频、音频等媒介时复用统一 Artifact 与 Executor 合同，不复制 Canvas 系统。
- 以小红书视频创作闭环验证通用底座，而不在 Host 中写入小红书专用逻辑。

## 非目标

- 不把所有画布节点改成 Agent。
- 不依赖更长的 Skill 文案代替原生校验。
- 不允许第三方 Skill 自动执行携带的脚本或自行注册可信执行器；任务确需运行脚本时，仍须经过普通工具权限、路径边界与用户审批。
- 不在首阶段实现全自动计划、运行、评分、重试的自主循环。
- 不让候选版本自动进入正式下游。
- 不自动发布内容到小红书或其它外部平台。
- 不在一个版本中同时完成全部四个阶段。

## 设计原则

### 软蓝图，硬合同

Skill 和模板只提供专业方法、常见步骤、角色建议与验收经验。普通 Agent 可以根据用户已有素材、目标和约束增删、组合、重排节点。

原生 Host 只固定不可协商的不变量：节点能力、输入类型、正式版本、权限、审批、事务、路径和恢复。Skill 被停用、修改或带有恶意指令时，这些边界仍成立。

### 节点类型回答“是什么”

参考图仍是图片节点，不新增“参考节点”。角色参考、风格参考、产品参考和构图参考由输入槽用途与边的业务关系表达。

### 展示版本等于执行版本

折叠卡片始终显示正式采用版本。候选只显示状态徽标；详情提供正式版本与候选版本的比较、采用和放弃。采用是卡片内容与下游输入共同切换的唯一时点。

### 专业方法不等于权限

第三方 Skill 可以影响规划、提示词、角色和质量标准，但不能自行扩大工具 allowlist、文件根、项目范围、付费许可或外部副作用。

## 总体架构

```text
用户目标
  ↓
普通 Proma Agent（理解、跨画布选择、总编排）
  ↓
领域 Skill + canvas-production
  ↓
CreativeTaskContract
  ↓
Canvas Kernel
  ├─ Artifact 能力与输入槽
  ├─ 真实输入绑定
  ├─ 执行与审批策略
  ├─ 候选/采用/待更新传播
  └─ journal、恢复与审计
  ↓
Canvas Agent / Artifact 节点 / 隐藏执行 Agent
```

### 普通 Agent

普通 Agent 是唯一跨画布 Orchestrator。它负责理解模糊目标、选择或创建画布、组合 Skill、生成任务合同、创建低风险结构、汇总审批和向用户解释结果。

普通 Agent 不承担每个专业分支的长期记忆，也不直接绕过 Artifact executor 生成媒体。

### Canvas Agent

只有任务分支满足以下任一条件时，普通 Agent 才自动创建 Canvas Agent：

- 需要跨多轮保留角色目标和工作记忆；
- 需要隔离大量资料、专业规则或不同视角；
- 用户会持续回到该分支评审和修正。

一次性提示词整理、生图、格式转换和短摘要不创建可见 Canvas Agent。Canvas Agent 继续固定到单一 `projectId + canvasId + nodeId`，不能管理或访问其它画布。

### 隐藏执行 Agent

图片、视频或未来其它模型执行可以继续由内部 Agent 完成，但 UI 使用“正在生成”“正在整理生成上下文”等任务文案，不称其为 Canvas Agent。内部会话继续从普通会话、搜索、最近记录、LAN/mobile 和项目记忆中排除。

### Canvas Kernel

Canvas Kernel 是唯一可信规则层，负责验证任务合同、节点能力、输入绑定、正式版本、审批、事务和恢复。Kernel 不理解小红书、电影或交互设计的业务方法。

## CreativeTaskContract

每次需要持续维护的画布任务拥有稳定 `creativeTaskId` 和一份结构化合同。合同至少表达：

- 用户目标与明确排除项；
- 参与的 Skill 及其内容 hash；
- 计划产物及其专业用途；
- 推荐长期角色与创建理由；
- 每个产物的输入槽、输出能力和验收要求；
- 自动、审批、手动三类执行策略；
- 当前合同 revision 和来源用户消息；
- 节点与合同产物之间的稳定映射。

合同不是一次运行日志。单次执行仍使用 Job/Run journal；合同只描述本次创作任务希望长期维持的结构与规则。

Agent 可以局部修改合同，但不能直接修改采用状态、权限事实或运行 journal。合同更新必须在同一 Canvas serializer 与 workspace write lease 下映射为受控图 mutation。

## Artifact 能力与类型化输入

### 输出能力

ArtifactDefinition 声明稳定输出能力，例如：

- `document.markdown`
- `webview.html`
- `webview.screenshot`
- `image.asset`
- `video.asset`
- `audio.asset`
- `timeline.video`

WebView 默认只有 HTML 输出。只有经过 Host 受控截图流程后才出现 `webview.screenshot`，并可显式绑定到接受图片的输入槽；HTML 文本摘要不能冒充视觉媒体。

### 输入槽

目标节点通过命名输入槽声明真实需求，例如：

- `context.text[]`
- `character.reference[]`
- `style.reference[]`
- `video.startFrame`
- `video.endFrame`
- `video.audioTrack`

输入槽声明允许的输出能力、数量、是否必需和稳定排序。运行前 Kernel 解析所有必需槽位；缺失或类型错误时返回明确阻断原因，不创建付费 Job。

### 关系与绑定分离

现有 `association/reference/depends-on/derives` 继续表达用户可理解的业务关系。执行绑定新增：

```text
sourceNode.outputCapability → targetNode.inputSlot
```

`association` 默认不形成执行绑定。其它关系也不能仅凭名称自动成为媒体输入；创建边时由 Agent 或用户选择目标输入槽，Host 复核源输出能力是否兼容。

### 兼容旧图

旧边不批量静默改写：

- 图片节点到图片节点的旧 `reference` 可以在首次运行前建议绑定到通用视觉参考槽；
- 文档、WebView、Agent 到图片的旧 `reference` 只能建议绑定到文本上下文槽；
- 无法唯一判断用途的旧边保持业务关系但不形成执行绑定；
- 用户运行节点前看到待确认或缺失输入，不产生付费调用。

## 版本与传播

### 正式版本

所有执行绑定只解析上游正式采用版本。用户导入的本地参考图属于明确提供的源素材，创建图片节点后可以直接成为正式采用版本。

### 候选版本

Agent 或模型生成的新结果进入候选集合：

- 卡片继续展示正式版本；
- 卡片显示“有新版本”徽标；
- 详情默认聚焦最新候选，并同时显示正式版本；
- 用户可以采用、放弃或继续生成；
- 候选不会触发下游待更新。

### 采用与待更新

采用事务原子更新节点正式版本和相关模块事实。事务成功后才根据执行绑定计算影响：

- 免费且可逆的文档、WebView 或配置任务可以进入自动重算队列；
- 生图、视频、音频等可能付费任务只标记待更新，并合并为一次审批计划；
- `association` 不传播待更新；
- 失败节点继续保留旧正式版本。

活动状态与版本状态保持正交，禁止用中文状态文案反推：

- 活动：`idle/queued/running/waiting-approval`
- 内容：正式版本、候选存在、上游待更新、输入阻断

## 第三方 Skill-to-Canvas Adapter

### 目标

用户从网上下载的普通专业 Skill 不需要包含 Proma API、Canvas Schema 或专用模板。用户在普通 Agent 中明确引用 Skill，或 Agent 根据 Skill description 提议使用后，Proma 才对选中的 Skill 做惰性兼容分析。

### 能力画像

Adapter 在无工具、无副作用的分析边界中读取 Skill 说明，把它作为不可信领域资料生成严格结构化能力画像：

- 专业目标与适用场景；
- 需要的输入资料和媒体；
- 可能产生的阶段性输出；
- 建议的长期角色；
- 方法步骤与验收标准；
- 声明或推断的工具、MCP、命令和外部服务依赖；
- 潜在付费、文件写入、网络或发布副作用；
- 与当前 ArtifactDefinition 和 executor 的兼容状态。

能力画像按 Skill 内容 hash 和 Adapter 版本缓存到 Proma 受管工作区，使用安全原子写。Skill 内容变化后旧画像失效；系统不在后台扫描全部 Skill。

### 兼容状态

- `compatible`：现有节点和受控工具能完整实现；
- `degraded`：可以完成策划、文档或静态素材，但缺少部分执行器；
- `blocked`：依赖未知执行器、越权操作、不安全脚本或无法证明的输入。

兼容报告在创建付费任务前可见。降级运行必须明确列出不会完成的阶段，不能把方案文档描述为最终媒体产物。

### Skill 组合

`canvas-production` 是通用编译与安全工作流 Skill；第三方 Skill 提供领域方法。多个 Skill 可以组合，例如：

```text
account-positioning
  + content-planning
  + copywriting-skills
  + product-film-shot-design
  + 已安装的视频执行器
  → 小红书视频任务合同
```

冲突优先级为：Host 安全合同 > 用户当前明确要求 > 用户明确引用的 Skill 顺序 > Agent 自动建议的 Skill > `canvas-production` 默认建议。只有冲突会改变交付物、费用或外部副作用时才询问用户一次。

### 绑定与追溯

CreativeTaskContract 记录实际参与的 Skill 名称、来源、内容 hash 和激活方式。Canvas Agent 可以绑定一组专业 Skill；每次运行仍记录本轮实际加载的版本。

Skill 更新不会静默重写既有任务合同。详情显示“Skill 已变化”，用户选择刷新后由普通 Agent 生成差异计划。

### 安全边界

第三方 Skill：

- 不扩大 Canvas 工具 allowlist；
- 不授予项目、文件、网络、账号或外部发布权限；
- 兼容分析阶段不执行随 Skill 下载的脚本；实际任务只有通过普通工具权限、路径边界和用户审批后才能运行；
- 不注册 Artifact executor；
- 不跳过付费、覆盖、删除或发布审批；
- 不读写 Canvas 内部 JSON、journal 或受管素材目录。

受信任 Artifact executor 是独立扩展面，需要独立安装、能力声明和权限审查。Skill 只能选择当前已安装且 Host 认可的 executor。

## 自由创建与场景蓝图

场景蓝图是 Skill 提供的可裁剪建议，不是固定流程。普通 Agent 可以：

- 复用用户已有素材和节点；
- 删除不适合当前目标的阶段；
- 增加新的角色、产物和分支；
- 把多个 Skill 的方法组合到同一合同；
- 只完成策划、静态素材或某一阶段；
- 从任意已采用节点继续衍生。

Host 不包含“小红书流程”“电影流程”或“交互流程”的硬编码判断。新增领域优先通过安装 Skill 获得专业方法；只有新增媒体能力时才扩展 ArtifactDefinition 与 executor。

## 小红书视频标杆模板

小红书视频是首个验收模板，不是首个硬编码场景。

### 共享账号与 IP 资产

- 账号定位与目标用户文档；
- IP 三视图、产品图和品牌视觉参考图片；
- 语言风格、禁用表达和平台约束；
- 用户明确导入的参考图片直接采用。

### 长期专业角色

- 内容策划 Canvas Agent：维护选题池、内容日历和发布复盘；
- 视觉导演 Canvas Agent：持续维护镜头语言、IP 一致性和分镜迭代。

任务规模较小或用户只需要一次性方案时，普通 Agent 可以不创建上述角色，直接生成文档和图片节点。

### 单条视频生产分支

```text
选题
  → 标题、前三秒钩子、口播与 CTA
  → 分镜与拍摄清单
  → IP/产品/风格正式参考
  → 镜头首帧与尾帧候选
  → 视频片段候选
  → 配音、BGM 与字幕
  → 时间线与成片候选
```

用户可以复制单条视频任务合同形成新分支，但共享账号和 IP 资产继续按正式版本引用。发布数据可以作为新文档或数据产物回流内容策划 Agent，系统不自动登录或发布到外部平台。

### 当前能力降级

在视频、音频和时间线 executor 尚未实现时，小红书 Skill 兼容报告为 `degraded`。当前版本可以交付策划、脚本、分镜、参考图、封面和首尾帧，不得声称已生成视频成片。

## 用户界面

### 卡片

卡片只显示正式采用内容，并使用独立轻量状态：

- 缺少输入；
- 待审批；
- 排队或运行；
- 有新版本；
- 上游已变化、待更新。

状态不改变卡片尺寸，不加载候选原图，不依赖轮询。

### 节点详情

详情需要回答：

1. 为什么存在：来源目标、任务合同和参与 Skill；
2. 使用什么：输入节点、输入槽、正式版本和媒体类型；
3. 做了什么：执行 Agent、模型、提示词、工具参数和日志；
4. 影响哪里：采用后会使哪些下游待更新。

图片、视频等有候选的节点同时展示正式版本与最新候选，并提供采用、放弃和继续生成入口。

### 任务级入口

普通 Agent 消息中可以明确引用一个或多个 Skill。画布顶部显示本任务使用的 Skill、兼容状态和待审批任务摘要。用户可以要求 Agent 重新规划、增加 Skill、移除 Skill 或从空白任务开始。

## 审批、错误与恢复

### 预检

创建付费 Job 前一次性验证目标节点、必需输入槽、正式版本、模型/executor 可用性、工作区写权限和任务合同 revision。任何失败都不创建部分 Job 或扣费动作。

### 合并审批

同一任务合同下可并行执行的同类付费节点合并展示 executor、数量、预计费用范围和使用的正式输入版本。审批只对本批次有效，不授予未来自动运行权限。

### 部分失败

批次中成功结果进入候选，失败项保留明确错误和可重试身份。正式版本不变。用户可以只重试失败项，或修改输入后创建新尝试。

### 恢复

任务合同、图 mutation、候选登记和采用继续复用项目级 serializer、workspace write lease、journal 与可证明事实恢复。重启恢复不能重复提交已经开始的付费调用；无法证明时进入显式恢复阻断。

### Skill 不兼容

Skill 解析失败、工具依赖缺失或存在不安全要求时显示兼容报告。用户仍可把 Skill 当普通只读参考交给 Agent，但自动编排不得把未知能力描述为可执行节点。

## 性能与资源影响

- Skill 能力分析只对本次明确引用或 Agent 已选择的 Skill 惰性执行，并按内容 hash 缓存。
- 图与绑定校验保持 `O(nodes + edges)`，不递归扫描无关画布。
- 下游影响只在正式采用事件后计算；候选生成不触发传播。
- Renderer 卡片继续只消费聚合后的轻量状态和缩略图，不加载全部版本原图。
- 新的合同和能力画像是有界 JSON，不引入本地数据库。
- 第三方 Skill 内容不复制进 Canvas 文档；合同只记录稳定身份、hash、能力摘要和节点映射。
- 视频、音频大文件继续由 Asset Service 管理，图文档只保存稳定引用。

## 关联模块影响

### 必须同步检查

- `packages/shared`：节点、输入槽、绑定、任务合同和公开状态类型；
- 主进程 Canvas Store、Artifact Registry、Job Manager、Skill loader 与安全原子写；
- IPC、Preload 与 Renderer exact-key parser；
- 普通 Agent 与 Canvas Agent 工具注入、会话恢复和内部会话隔离；
- 候选批次、采用事务和下游待更新传播；
- 工作区 Skill 安装、启停、升级和内容变化事件；
- Windows/macOS/Linux 打包中的默认 Skill 与未来 executor 资源。

### 不应受影响

- 普通 Chat 不自动获得 Canvas 写能力；
- LAN/mobile 不暴露内部 Design 或 Canvas Agent 会话；
- Automation 与 Collaboration 不因 Skill-to-Canvas Adapter 获得跨项目访问；
- 现有文档、WebView 和图片历史继续可加载；
- Skill 停用不删除既有任务、节点或正式素材。

## 分阶段交付

### 阶段一：可信数据底座

- 修正内部执行 Agent 文案；
- 卡片严格展示正式版本并增加候选徽标；
- 引入 Artifact 输出能力、目标输入槽和执行绑定；
- 运行前阻断缺失或错误媒体输入；
- 采用后再传播待更新；
- 为旧边提供保守兼容和显式确认。

阶段一不新增视频、音频或第三方 Skill 分析。

### 阶段二：Agent 与 Skill 编排

- 引入 CreativeTaskContract；
- 普通 Agent 可以按规则创建 Canvas Agent；
- 增加第三方 Skill 能力画像、兼容报告、组合和追溯；
- 支持 Canvas Agent 的稳定 Skill 绑定与变更提示；
- 保持 Host 安全合同优先。

### 阶段三：新媒体执行器

- 建立通用 ArtifactDefinition 与 executor 注册合同；
- 增加视频、音频和时间线 Artifact；
- 实现首尾帧、音轨、字幕等类型化输入；
- 扩展候选、采用、导出和恢复到新媒体。

阶段三不允许 Skill 直接注册任意执行代码。

### 阶段四：小红书标杆验证

- 使用网上可获得的账号定位、内容策划、文案和分镜 Skill 组合生成动态任务合同；
- 验证共享 IP 资产和多条视频分支；
- 验证降级模式与完整 executor 模式；
- 验证发布数据回流，但不自动发布。

## 测试设计

### Skill 与编排

1. Given 用户明确引用普通第三方 Skill，When 首次用于 Canvas，Then 只分析该 Skill 并生成带内容 hash 的能力画像。
2. Given Skill 只输出专业方法，When 与 `canvas-production` 组合，Then Agent 能生成动态任务合同而无需 Skill 包含 Proma API。
3. Given Skill 要求未知命令或越权操作，When 生成兼容报告，Then 标记降级或阻断且不扩大工具权限。
4. Given 多个 Skill 对交付物存在冲突，When 冲突影响费用或外部副作用，Then 只询问一次并记录最终决策。
5. Given Skill 内容变化，When 打开既有任务，Then 提示变化且不静默重写合同。

### 节点与输入

1. Given 用户导入 IP 三视图，When 创建参考图片节点，Then 图片直接成为正式采用版本并能绑定 `character.reference`。
2. Given WebView 只有 HTML 输出，When 绑定图片参考槽，Then Host 在 Job 创建前拒绝。
3. Given WebView 已生成受控截图输出，When 绑定图片参考槽，Then 下游收到真实截图媒体而不是 HTML 摘要。
4. Given 必需输入槽为空，When 用户运行付费节点，Then 显示具体缺失输入且不创建 Job。
5. Given 旧边无法唯一映射输入槽，When 加载或运行，Then 保留关系并要求确认，不静默猜测。

### 版本与传播

1. Given 正式 A 和新候选 B，When B 生成成功，Then 卡片仍显示 A、下游仍消费 A，并显示“有新版本”。
2. Given 候选 B 未采用，When 查询下游状态，Then 不出现由 B 引起的待更新。
3. Given 用户采用 B，When 事务成功，Then 卡片与执行绑定同时切换 B，并按关系标记下游待更新。
4. Given 采用事务恢复状态不确定，When 重启，Then fail closed 且不出现卡片版本与下游版本分裂。

### Agent 生命周期

1. Given 一次性生图任务，When 普通 Agent 规划，Then 不创建可见 Canvas Agent。
2. Given 需要长期内容策划和多轮复盘，When 普通 Agent 规划，Then 创建固定作用域 Canvas Agent 并记录创建理由。
3. Given 图片内部 Agent 运行，When Renderer 展示状态，Then 使用生成任务文案且不暗示上游 Agent 节点。
4. Given Canvas Agent 绑定专业 Skill，When 运行，Then 只访问自身画布和直接输入，并记录实际 Skill hash。

### 付费、失败与恢复

1. Given 多个可运行图片或视频节点，When 用户提交，Then 完整预检后形成单次合并审批。
2. Given 批次部分失败，When 任务终止，Then 成功项成为候选、失败项可独立重试、正式版本不变。
3. Given 应用在候选登记或采用中断，When 重启恢复，Then 不重复付费调用且按 journal 收敛。
4. Given executor 缺失，When 第三方 Skill 请求视频成片，Then 明确降级到策划/静态素材且不宣称生成视频。

### 性能与平台

1. 大画布绑定校验保持线性，不为候选生成扫描全部下游或原始媒体。
2. 多个 Skill 安装时只分析本次选中项，未使用 Skill 不触发模型请求或磁盘全量读取。
3. macOS、Windows、Linux 对能力画像、合同、journal 和 Asset 引用使用相同路径与安全原子写合同。
4. Renderer 在大量候选与待更新节点下只挂载可见卡片，并以 O(1) 聚合状态渲染。

## 验收标准

1. 用户可以安装并引用不认识 Proma 的普通专业 Skill，系统给出可解释的 Canvas 兼容报告。
2. Agent 根据用户目标和多个 Skill 自主生成画布，而不是复制硬编码流程。
3. 普通 Agent 只在长期状态、独立上下文或反复迭代场景创建 Canvas Agent。
4. 参考图必须以真实图片能力绑定；WebView 摘要不能进入图片参考槽。
5. 卡片展示、正式采用版本和下游输入完全一致。
6. 候选只提示“有新版本”，采用后才传播待更新。
7. 免费可逆任务可自动重算；付费任务合并审批且不会因上游变化自动扣费。
8. 缺少视频执行器时小红书任务明确降级；具备执行器后可扩展到视频、音频和时间线。
9. 第三方 Skill 不能扩大权限、绕过审批或执行任意随包代码。
10. 四个阶段分别具备 BDD 测试、类型检查、构建和目标平台回归证据。
