# Canvas 工作区画布抽屉与标题管理设计

日期：2026-09-03

状态：已完成交互与架构讨论，等待书面规格复核

## 结论

Canvas 工作区采用默认收起的左侧覆盖式抽屉，集中承载当前项目的画布新建、切换、默认、归档、恢复和删除操作。抽屉只在用户需要管理画布时出现，不挤压节点工作区；切换、新建或恢复成功后自动收起。

当前画布标题改为原地编辑。工作区右上角增加“删除当前画布”按钮，并继续复用现有永久删除确认、运行任务阻断和 Renderer 索引更新链路。顶部加号菜单不再展示画布列表或画布管理操作，避免两个入口呈现不同状态。

本次只重组 Renderer 界面与操作归属，不新增 IPC、持久化字段或画布数据模型。

## 问题

当前项目画布列表藏在右侧工作区顶部的加号菜单中，存在四个问题：

1. 加号同时承担“新增工作区标签”和“管理项目画布”，入口语义混杂。
2. 用户进入画布后无法直接看到当前项目还有哪些画布，切换路径较深。
3. 重命名、归档、默认和删除依附在多级菜单中，操作反馈与当前画布内容分离。
4. 当前画布缺少直接删除入口，用户需要重新在列表中定位同一画布。

用户平时以节点创作为主，不需要画布列表长期占据宽度。因此固定侧栏会持续压缩画布，图标轨道又无法直接扫读画布名称；默认收起的覆盖式抽屉更符合当前使用频率。

## 目标

- 在当前画布内直接访问项目全部画布，并支持新建、切换和管理。
- 画布列表默认不占用工作区宽度。
- 当前画布名称、默认状态、新版本状态和归档状态清晰可见。
- 画布操作只有一个主要入口，避免顶部菜单与内容区状态漂移。
- 重命名和删除当前画布所需操作更少。
- 复用现有业务动作和安全守卫，不扩大修改范围。
- 分屏、全屏画布、深浅主题和键盘操作保持可用。

## 非目标

- 不修改 Canvas registry、Agent-Canvas binding 或活动版本的数据合同。
- 不新增画布排序、文件夹、搜索、拖拽排序或批量管理。
- 不改变“候选版本需要用户采用后才传播”的版本语义。
- 不改变 legacy Design 的永久删除限制。
- 不新增主进程 IPC、Preload bridge 或本地持久化字段。
- 不修改 README、教程或发布说明。

## 方案比较

### 方案 A：固定侧栏

展开时长期占据约 220px，收起后保留约 40px 图标栏。画布关系最容易扫读，但右侧工作区本身已经可能处于窄宽度或分屏状态，持续压缩节点区域与用户的主要工作冲突。

### 方案 B：覆盖式抽屉（采用）

列表默认收起，打开时覆盖当前 Canvas Pane 左侧。节点工作区平时保持最大宽度，管理画布时仍能展示完整名称和操作。代价是抽屉打开期间遮挡局部节点，因此所有成功导航动作必须自动收起，并提供遮罩点击和 `Esc` 关闭。

### 方案 C：图标轨道与浮层

常驻宽度最小，但画布名称和状态不可直接扫读。项目画布增多时需要频繁打开浮层确认，不适合承担归档、默认和新版本提示等管理信息。

## 界面结构

### 画布标题栏

画布内容区顶部提供一条紧凑标题栏：

- 左侧为“画布列表”图标按钮和当前画布标题。
- 标题使用单行截断，悬停时显示可编辑反馈。
- 右侧依次为“删除当前画布”和现有“展开/还原画布”按钮。
- legacy Design 不显示永久删除按钮。
- 图标按钮复用现有尺寸、主题变量、Tooltip、focus 和 disabled 规范。

删除按钮不使用常驻红色填充，只在悬停和聚焦时表达危险语义，避免与主创作操作争夺注意力。

### 覆盖式抽屉

抽屉位于当前 Canvas Pane 内部，宽度约 240px；窄 Pane 下最大不超过所在 Pane 宽度的 80%。它不能覆盖另一个分屏 Pane，也不能挂载到整个应用窗口的全局层级。

抽屉结构：

1. 顶部标题“项目画布”和关闭按钮。
2. “新建画布”命令。
3. 未归档画布列表。
4. 默认折叠的“已归档”分组与数量。

未归档画布行包含：

- 画布图标与标题；
- 当前项选中态；
- 默认画布星标；
- 活动代次未读时的新版本圆点；
- 行尾更多菜单。

更多菜单提供“设为默认、归档、删除”。当前已是默认画布时不重复提供“设为默认”。legacy Design 不提供永久删除。

归档画布行提供“恢复”和“删除”。点击归档画布标题等同于恢复并打开，成功后自动收起抽屉。

## 交互规则

### 打开与关闭

- 抽屉默认收起，不跨组件卸载持久化。
- 点击画布列表按钮打开。
- 点击 Pane 内遮罩、关闭按钮或按 `Esc` 收起。
- 切换、新建、恢复成功后自动收起。
- 异步操作失败时保持展开，让用户保留当前定位并可重试。
- 抽屉展开期间，背景画布不接收点击或拖拽，避免误操作；另一个分屏 Pane 不受影响。

### 切换画布

点击未归档画布后复用现有 Agent-Canvas 关联与工作区标签打开流程。当前项点击只收起抽屉，不发起重复关联请求。

成功切换后继续沿用现有最近画布与活动已读更新；不主动改变默认画布。

### 标题原地编辑

- 单击标题进入编辑态并选中原文字。
- `Enter` 保存，`Esc` 取消，点击编辑区外保存。
- 保存前去除首尾空白；空标题不提交并恢复原值。
- 内容未变化时直接退出编辑，不发起 IPC。
- 保存期间禁用重复提交。
- 保存失败时保留编辑态与草稿，并使用现有错误 Toast 提示。

标题编辑只作用于当前 Canvas，不在列表行内提供第二个重命名入口。

### 归档当前画布

归档当前画布成功后，从当前 Agent 已关联且未归档的画布中选择下一张可用画布打开。优先使用默认画布，其次使用最近关联顺序中的可用画布；若不存在可用画布，则关闭当前 Canvas 工作区标签并返回先前标签。

这样处理是为了避免用户停留在“画布已归档”的无操作页面。归档失败时保持当前画布与抽屉状态不变。

### 删除当前画布

右上角按钮和列表行删除共用同一删除请求入口：

- 继续展示永久删除确认；
- 继续由主进程阻断仍有运行任务的画布；
- 成功后更新 Renderer 画布索引；
- 现有 binding 事件负责清理失效关联；
- 当前工作区在目标消失后沿用现有返回上一标签逻辑；
- legacy Design 禁止进入删除流程。

不得为右上角按钮复制第二套删除状态机。

## 组件边界

### `SidePanel`

继续作为当前普通 Agent 的画布数据与动作所有者：

- 持有 `useAgentCanvasWorkspaceRegistry`；
- 持有新建、打开、设为默认、重命名、归档和删除回调；
- 持有永久删除确认对话框和删除生命周期；
- 为每个 Canvas Pane 注入相同项目索引和受控动作。

`SidePanel` 不新增第二个 registry hook，也不把业务状态复制到新组件。

### `CanvasWorkspaceAdapter`

负责组合当前 Canvas 工作区、标题栏、抽屉与全屏状态。它接收当前项目画布视图模型和动作，不直接调用主进程服务。

全屏时抽屉仍限定在全屏 Canvas 容器内部；`Esc` 优先关闭抽屉或标题编辑，再执行现有退出全屏行为，避免一个按键同时触发两级状态变化。

### `CanvasWorkspaceSidebar`

新增独立展示组件，职责限制为：

- 根据画布元数据分组并渲染列表；
- 管理抽屉开关、归档分组展开和当前 pending 操作；
- 提供键盘、focus、遮罩和菜单交互；
- 成功动作后通知宿主收起。

它不拥有 Canvas registry、Toast、确认对话框或 IPC adapter。

### `DiffPanelTabBar`

移除画布列表、画布重命名、默认、归档和删除菜单 UI，以及只为这些菜单服务的局部状态。顶部加号继续负责浏览器、文件、终端和其它工作区标签入口。

## 数据流

```text
SidePanel 中的 Canvas registry 与动作
  ↓ props
CanvasWorkspaceAdapter
  ├─ 当前标题原地编辑
  ├─ 当前画布删除按钮
  └─ CanvasWorkspaceSidebar
       ├─ 新建 / 切换
       ├─ 设为默认
       ├─ 归档 / 恢复
       └─ 请求删除

动作成功
  ↓
既有 Canvas metadata / binding 事件
  ↓
SidePanel registry 更新
  ↓
所有 Canvas Pane 使用同一权威列表重新渲染
```

抽屉不维护画布元数据副本。异步回调返回后必须校验组件仍属于原 `sessionId + projectId + canvasId`，避免切换 Agent 或项目后迟到结果关闭新宿主的抽屉或覆盖标题草稿。

## 状态与错误处理

- metadata 加载中：标题栏保持稳定，列表按钮 disabled，继续显示现有画布加载态。
- registry 加载失败：继续使用现有错误页，不展示不可用的管理入口。
- 空项目：抽屉显示明确空状态和“新建画布”，不渲染空列表框。
- 单项 pending：只禁用冲突操作，画布列表仍可阅读。
- 新建、打开、重命名、默认或归档失败：复用现有固定错误文案和 Toast。
- 删除失败：确认框和删除生命周期继续由现有实现收口。
- 画布被其它窗口删除：沿用 metadata 对账解除关联和返回上一标签逻辑。
- 新版本圆点只表示活动未读，不改变正式采用版本和卡片内容。

## 关联业务影响

- 普通 Agent 对话、Canvas Agent、节点运行和候选采用语义不变。
- 顶部工作区加号菜单减少 Canvas 专属状态，但其它工作区入口不变。
- 分屏可在两个 Pane 显示不同 Canvas；每个 Pane 只管理自己的抽屉与标题编辑状态，共享项目画布事实。
- 删除仍经过主进程任务守卫，不因新增快捷按钮降低安全边界。
- 归档当前画布新增明确回退行为，需要验证默认、最近与无可用画布三条路径。
- 全局画布活动监听和新版本圆点继续复用现有 activity revision，不新增订阅。

## 性能与资源开销

- 不增加后台 IPC、文件读取或 Canvas 文档加载。
- 抽屉关闭时不挂载列表内容；打开时对现有项目索引进行一次 `O(n)` 未归档/归档分组。
- 列表项只渲染元数据，不挂载 Canvas 内容或节点预览。
- 抽屉开关使用 transform/opacity 过渡，不触发布局宽度变化，不要求 XYFlow 重算节点画布尺寸。
- 画布索引变化会更新打开的 Canvas Pane，但不应重建 `NativeCanvasWorkspace`；组件边界需保持 workspace identity 稳定。

## 测试策略

### 组件与行为测试

1. Given 抽屉默认关闭，When 点击列表按钮，Then 在当前 Pane 内展示项目画布且画布宽度不变。
2. Given 抽屉打开，When 点击遮罩、关闭按钮或按 `Esc`，Then 只关闭抽屉。
3. Given 用户切换、新建或恢复成功，Then 抽屉自动关闭；失败时保持打开。
4. Given 当前、默认和活动未读画布，Then 分别展示选中态、星标和新版本圆点。
5. Given 已归档画布，Then 默认位于折叠分组，展开后可恢复或删除。
6. Given legacy Design，Then 标题栏和行菜单均不存在永久删除入口。
7. Given 标题编辑，Then 单击进入，`Enter`/失焦保存，`Esc` 取消，空值和未变化值不提交。
8. Given 标题保存失败，Then 草稿与编辑态保留且不会产生未处理 rejection。
9. Given 管理动作 pending，Then 重复或冲突提交被阻断。

### SidePanel 集成测试

1. 顶部加号菜单不再渲染画布列表和管理操作，其它标签入口保持不变。
2. 每个 Canvas Pane 收到同一项目索引、默认 ID、活动状态和既有动作。
3. 归档当前画布时按“默认画布、其它可用画布、返回上一标签”顺序回退。
4. 右上角删除与列表删除打开同一确认流程。
5. 删除成功后索引更新、关联清理和标签回退不回归。
6. 分屏中的抽屉只覆盖目标 Pane，另一个 Pane 仍可见。
7. 全屏状态下抽屉、标题编辑与退出全屏的 `Esc` 优先级正确。

### 验证

- 运行 `CanvasWorkspaceSidebar`、`CanvasWorkspaceAdapter`、`SidePanel.canvas` 和 `DiffPanelTabBar` 定向测试。
- 运行 `bun run typecheck`。
- 启动 Electron 开发客户端，验证普通宽度、窄 Pane、分屏、全屏、light/dark 主题。
- 视觉检查标题与按钮不重叠、抽屉不越过 Pane、长标题正确截断、归档列表可滚动。

## 验收标准

1. 进入任意 Canvas 时列表默认不占用画布宽度。
2. 用户可从左侧抽屉新建、切换、设为默认、归档、恢复和删除项目画布。
3. 成功切换、新建或恢复后抽屉自动收起。
4. 归档画布默认折叠，当前、默认和新版本状态可区分。
5. 当前标题可直接编辑，并具备完整键盘保存与取消行为。
6. 当前非 legacy Canvas 可从右上角进入既有永久删除流程。
7. 顶部加号菜单不再重复展示画布管理入口。
8. 删除运行中画布仍被主进程阻断，legacy Design 仍不可永久删除。
9. 分屏和全屏下抽屉作用域、焦点与 `Esc` 行为正确。
10. 不新增 IPC、持久化字段或后台查询，Canvas 节点渲染性能不回退。
