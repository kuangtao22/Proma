# Canvas 首次打开行为设计

## 目标

用户从右侧工作区“添加 -> 打开画布”进入 Canvas 时，应直接到达可工作的画布，而不是停留在空白 launcher。

## 行为规则

1. 入口只有在当前项目、项目画布元数据和 Agent-Canvas 绑定均已就绪时才可点击。
2. 当前 Agent 的默认画布存在且未归档时，直接打开默认画布。
3. 默认画布不可用时，打开项目列表中的第一个未归档画布。
4. 目标画布尚未关联当前 Agent 时，先复用现有关联流程，再打开对应动态标签。
5. 项目没有未归档画布时，新建一个画布，将其设为当前 Agent 默认画布并打开。
6. 归档画布不参与首次选择；用户仍可从画布列表显式恢复。
7. 顶部入口不再主动打开空 launcher。launcher 继续保留为异常状态和旧打开状态的恢复入口。

## 实现边界

- 初始打开决策由 `SidePanel` 持有，因为它属于明确的用户导航意图。
- 画布创建、关联、默认设置和错误提示继续复用现有 registry 与 action helper，不新增 IPC 或持久化字段。
- 把“选择初始画布”提取为纯函数，输入项目画布列表与默认 ID，输出目标画布或 `null`，便于覆盖默认、首项和空列表边界。
- 点击入口时执行一次异步动作；进行中阻止重复触发，避免空项目被连续创建多个画布。

## 数据流

`点击打开画布 -> 校验 metadata/binding 就绪 -> 选择默认或首个未归档画布 -> 关联并打开`

若没有目标，则走：

`点击打开画布 -> 新建画布 -> 建立默认关联 -> 打开动态标签`

## 错误与竞态

- metadata 未就绪时禁用入口，避免把“尚未加载”误判为“没有画布”。
- 异步动作完成前若会话或项目已切换，沿用 registry 的代次校验，不向新宿主写入标签状态。
- 打开或创建失败时复用固定中文错误提示；失败后允许用户重试。
- 同一入口动作在途时忽略重复点击，动作结束后释放锁。

## 影响评估

- 关联模块：仅影响 Agent 右侧工作区的 Canvas 打开入口；画布列表、归档恢复、删除、Agent 后台产物和普通标签导航保持现状。
- 性能：不增加后台监听、轮询或持久化；只在用户点击时遍历当前项目画布列表，复杂度为 `O(n)`。

## 测试

- 默认画布存在且未归档时选择默认画布，不再优先最近画布。
- 默认画布缺失或已归档时选择第一个未归档画布。
- 无未归档画布时调用创建流程，不打开 launcher。
- metadata 或 binding 未就绪时入口保持禁用。
- 快速重复触发只执行一次打开或创建动作。
