# Server Ops 剩余能力设计草案

日期：2026-09-07

状态：规划草案；用户已要求在分支先规划，尚未实施下述能力。

## 结论与交付范围

按“指纹恢复 -> 远程文件 -> Docker -> 数据服务”逐阶段交付。每阶段同时完成用户入口、Shared/Main/Preload/Renderer 合同、运行时生命周期、审批、审计和验证；不能仅把占位页替换为静态内容。

分支为 `codex/server-ops-completion`，起点为 `feed23c4dd6512cae0680dddd60d2f1276f38df2`。工作目录为 `.worktrees/server-ops-completion`，主工作区的 Canvas、Agent Runtime 与 Windows 打包未提交改动不属于本分支输入。实现前重新对齐已合入的修复，尤其数据根启动、原生 helper 和运行时打包规则。

已实现的主机管理、三种 SSH 认证、PTY、概览、systemd、journal 日志及基础审计继续作为底座。上一轮可观测性规格明确排除了文件、Docker、数据服务和新增结构化 Agent 工具；本草案是新的增量范围，不回写旧阶段为“未完成”。

## 方案比较

| 方案 | 用户收益 | 代价与判断 |
| --- | --- | --- |
| 分阶段复用 SSH 领域服务 | 每阶段即可完成一种真实排障流程 | 推荐；依赖顺序明确，失败范围和官方合并冲突较小 |
| 所有页签一次性交付 | 一次拿到完整控制台 | 文件、容器和数据库三套资源与权限语义同时变化，验收和回归过大 |
| 全部通过通用 Shell/Agent 命令完成 | 初期接入成本较低 | 难形成可靠传输、结构化状态、数据库认证和结果限制；保留现有 `server_exec`，不作为新页签后端 |

## 共用架构与所有权

- UI 继续位于普通 Agent 的右侧 Server Ops Pane，复用服务器抽屉与现有主题；不新增独立运维模式、运维 Agent 或 Canvas 节点。
- 复用唯一 `ServerOpsServiceContext`、`ServerOpsConnectionService`、`ServerOpsRuntimeClient` 和 `server-ops-runtime.cjs`。SFTP、Docker channel 和数据转发 channel 共享已验证的 SSH 连接；不重新登录或复制凭据。
- 领域服务各自维护文件传输、Docker、数据查询身份；不把所有操作塞入一个接受任意命令的公共 IPC。新增 Preload 组合留在各领域文件，根注册文件只负责装配。
- 普通 Agent 的新结构化能力与 UI 共用主进程领域服务。两者各自验证调用者，权限不相互继承；现有显式 `sessionId + hostId` 授权、普通顶层会话和用户来源限制继续生效。Canvas、Automation、Delegation、LAN/外部桥接不因此获得服务器操作能力。
- 每个异步请求绑定 Main 派生的窗口 owner、主机、连接代次、资源身份及操作 ID。Renderer 只提交意图，不能自行授予权限、指定本地任意路径或复用过期连接。
- 用户或 Agent 发起的结构化变更需要逐次批准；批准后再次检查连接、目标及权限。取消、断线、超时和应用重启均不得自动重放远程写入。已提交但响应丢失必须显示“结果未知”，通过只读回查恢复事实。
- 主配置、信任和审计继续位于 `getConfigDir()/server-ops`；业务数据可迁移，秘密仅保存为 `safeStorage` 密文。新服务构造必须晚于数据根 normal gate。

## P0：先完成指纹恢复与共享写入约束

### 用户流程

服务器指纹变化后继续阻断认证，阻断页提供“管理服务器信任”。管理对话框展示服务器地址、端口、旧指纹、新指纹和受影响的其他主机配置。用户独立核实后输入当前服务器显示名，选择“替换指纹”；成功后返回未连接态，由用户显式重新连接。管理界面也支持撤销当前 endpoint 的信任，撤销后下次连接重新走首次确认。

指纹操作只允许已授权主窗口的直接用户操作，Agent 不得自行信任、替换或撤销。删除主机资产不自动删除同 endpoint 的信任，以免影响其他配置。

### 身份、并发和提交

当前信任按规范化的 `address + port` 共享，并非按 `hostId` 独占。继续保留此合同；别名不会通过 DNS 自动合并为同一 endpoint。

替换候选由 Main 建立，绑定 endpoint、旧信任摘要、新观测指纹、窗口 owner、连接尝试代次和期限。候选最多有效五分钟，单 owner/endpoint 仅保留最新一条；仅在候选存在时安排到期清理。用户取消、endpoint 变化、窗口销毁或提交成功后失效。不能接受 Renderer 自带的新指纹作为授权事实。

提交顺序固定为：fresh 校验 -> 持久化开始审计 -> 标记 endpoint 正在变更并撤销相关 Agent 授权 -> 失效候选和旧连接 -> 在受保护的短事务内重新校验并提交信任 -> 发布结果审计与事件。运行中的远程写操作不得因为换指纹被静默中断；存在不能证明安全停止的变更时，信任操作返回 busy，用户先完成或处理该操作。失败后保持断开或阻断，不恢复旧运行授权。

`safe-file.ts` 的 `writeJsonFileAtomicSecure(expectedDestination)` 可检测旧文件状态，但“校验 + rename”本身不是操作系统的跨进程原子 compare-and-swap。实现前必须通过 P0 的双进程测试确定写入互斥策略：优先复用仓库原生 helper 已有的 POSIX/Windows 锁机制，增加仅服务固定 Server Ops 配置目录的窄锁协议，锁由进程退出/EOF 自动释放；禁止复制 Canvas 事务系统、依赖锁文件时间强行抢锁或引入常驻轮询。锁覆盖 fresh-read、校验及原子提交；远程网络和用户审批不占用配置锁。

所有会写入相同主机、凭据、信任、审计文件的 Server Ops 路径须遵守同一互斥协议。`expectedDestination` 保留作非协作替换与损坏检测。旧版实例不遵守该锁，不能宣称新旧版混跑安全；迁移前需要通过既有实例 registry 的窄能力检查阻断已存活旧实例，并在交付说明中明确升级后重启所有 Proma 实例。无法验证的实例/共享文件系统保持受限，不静默覆盖。

跨实例信任变化需在连接建立与每次新的远程动作前 fresh-check。活跃 PTY/日志/传输通过受限文件变化通知对账并失效；暂停或丢失通知后的显式动作仍须 fresh-check，不能仅依靠 watcher。不声称可以撤回已经送达远端的命令。

### 审计兼容

在现有唯一 AuditStore 中升级 schema，增加 `operationId`、信任操作、资源类别与 `unknown` 结果；开始事件用开始态表示，不能显示为执行成功。旧 v1/v2 经严格迁移保留原始 actor、命令摘要和退出语义。人工作用域从 sender 生成，不虚构普通 Agent session ID；`sessionId` 仅在真实会话存在时记录。

保留最近 5000 条上限和脱敏合同，新增字段使用显式判别联合，避免宽泛 `metadata`。每次低频变更仍允许有界快照提交；进度、日志正文、PTY 原始输入输出和查询结果不写入审计。开始记录失败阻断变更，结果记录失败保留已提交事实并公开 warning。提交可见而耐久未确认时进入显式对账，不能当作未提交直接重试。

## P1：远程文件工作流

- 展示当前目录、父目录、文件/目录/符号链接、大小、修改时间和权限；目录按页读取，支持搜索当前已加载列表。只读预览与文本编辑区独立于传输队列。
- 使用现有 `ssh2@1.17.0` SFTP API。首次进入时探测 SFTP 与所需扩展；目录不足权限和服务端不支持属于明确能力状态，不能生成假空列表。
- 支持下载、上传、新建目录、重命名、删除单文件/空目录和文本保存。首版不支持递归删除/递归上传、chmod/chown、远程提权或后台自动同步。
- 上传由 Main 文件选择器产生一次性本地文件 lease，固定打开的 fd；按块转给 utility。下载写入用户选定目录中的受管临时文件，校验后以 no-clobber 方式发布，已存在目标返回冲突。本地路径不进入 Agent 工具结果。
- 文本读取建立不透明 edit token，绑定 canonical path、元数据和正文 hash；保存前重读比较，并在 Main 生成的同目录临时文件写完后提交。只有验证了所需 rename/fsync 扩展的服务器才开启替换式保存，否则保留只读/另存能力。
- 标准 SFTP 没有跨任意外部写者的原子条件替换，也没有本项目本地 native helper 的目录相对安全合同。不能把保存前检查宣传为无竞态 CAS，或把路径前缀校验宣传为远端沙箱。SSH 账户权限是硬边界；符号链接不自动跟随写入。对并发外部修改要求强保证的文件使用另存新文件，显式替换保留乐观冲突限制。
- 取消/断线只清理本操作拥有的临时资源，已提交输出保留；不能证明远程临时路径仍归本操作时不执行删除，给出可定位的恢复状态。传输操作先持久化不含秘密的最小恢复意图，启动后只对账/清理，不自动续传写入。
- 普通 Agent 增加当前主机内的有界 list/read 能力，以及复用逐次审批的文件变更入口。下载/导入模型上下文均需显式用户意图；文件内容是数据，不作为项目指令或系统提示。

## P2：Docker 工作流

- 通过 SSH 运行固定 Docker CLI 模板，不开放 Docker daemon TCP，不自行切换 Docker context。固定使用当前主机本地 daemon 目标，探测缺 CLI、daemon 不可达、权限不足分别展示。
- 容器列表、详情、端口、挂载、镜像/网络/卷摘要使用结构化输出和有界解析；过滤在当前列表中完成，详情按需读取。
- 容器日志复用现有流式 ACK、UTF-8 增量解码、owner 和缓存限制。独立容器终端不得抢占主机 PTY；使用专属 channel 与退出清理。
- start/stop/restart 绑定完整容器 ID 和连接代次；确认卡显示真实主机与容器，执行后 inspect 验证实际状态。目标删除或替换后拒绝旧请求，超时结果未知时只读回查，不自动重启第二次。
- UI 与普通 Agent 调用同一 Docker 领域服务；Agent 只获取脱敏、有界结果。容器详情不默认返回 `Env` 全量值、registry 凭据或可能含秘密的完整启动参数。
- 首版不做镜像 build/push、registry、Compose/Swarm、容器 remove、volume prune、Kubernetes 或自动部署。

## P3：数据服务，拆成可单独验收的子阶段

### 连接与认证

数据源元数据单独保存在 `data-sources.json`，包含 `hostId`、引擎、服务器视角目标地址/端口、数据库、用户名、TLS 配置和 `credentialRef`。数据库密码与 SSH 密码属于不同凭据合同；加密材料单独保存，复用已有 safeStorage 能力而不复制密钥或加密逻辑。不得扩宽 SSH credential 的 kind 使两者混用。

推荐通过已连接 SSH 的 `forwardOut` 获取 utility 内部 Duplex channel，直接交给数据库驱动，避免暴露本机监听端口。若被选驱动不能在已验明的 API 下消费该 stream，则该引擎阻断，先完成适配验证，不用无鉴权 loopback 代理兜底。TLS 主机名取数据库真实身份，不能因 SSH 跳板改为无条件跳过验证。

仓库目前没有直接依赖数据库驱动。本轮不安装新依赖或指定未经核实的版本。P3 开工入口为依赖选型验收：分别对 PostgreSQL/MySQL/Redis 驱动确认精确版本、维护/许可证、custom stream、认证与 TLS、取消语义、分页/流读取、Electron 打包和 optional native 闭包，并取得新增依赖的明确授权。每个引擎通过此门槛后独立实施，不要求三个同时落地。

### 功能边界

| 子阶段 | 用户可完成的流程 | 写操作边界 |
| --- | --- | --- |
| P3a PostgreSQL | 连接测试、库/表与容量、活跃连接、复制、受权限控制的慢查询统计 | 扩展未安装时明确显示不可用；不自动安装扩展 |
| P3b MySQL | 连接测试、schema/容量、进程列表、复制、可用的 performance_schema 诊断 | 统计未开启时明确降级，不自动改服务器配置 |
| P3c Redis | INFO、内存、复制、Keyspace、Slowlog、按 cursor 的键浏览与有界值预览 | 只读诊断；不使用 KEYS 全量枚举，不自动读取全部值 |
| P3d 查询与受控变更 | PostgreSQL/MySQL SQL 编辑器、有界结果与取消、精确 DDL/DML/终止连接；Redis 受控单 Key 命令入口 | SQL 采用数据库权限、引擎只读会话和可信解析共同约束；Redis 单 Key 修改/删除逐次审批，不提供任意命令透传 |

P3a-c 先交付固定诊断模板。P3d 才开放自由查询；参数值与查询正文不默认进入审计或模型。只读默认角色必须缺少写权限，并验证引擎 read-only 机制的实际边界；存储过程、函数副作用、注释、多语句和语法不明情况不能自动放行。只读身份无法完成写入时，明确要求配置具备对应权限的独立写身份，不能把审批当成数据库权限。

事务仅在该引擎支持的情况下使用。DDL 隐式提交、取消是否终止远端查询、超时后实际写入结果必须如实呈现；不能统一承诺可回滚。Redis `FLUSHALL`、`FLUSHDB`、`DEBUG`、复制拓扑变更和批量删 Key 不作为首轮默认能力；后续开放时须有独立的高风险合同与逐次审批，不能从通用查询直接穿透。

## 资源预算与用户影响

以下是实施验收目标，不代表已有性能测量结果。

| 资源 | 初始预算 | 用户影响 |
| --- | --- | --- |
| 概览/容器指标 | 可见时至多每 10 秒一次，同身份单飞 | 关闭页签后不持续采样 |
| 目录列表 | 每页 200 项，最多累计 2000 项，单次操作 15 秒 | 大目录继续分页，达到上限明确提示缩小范围 |
| 文本预览/编辑 | UTF-8 文本至多 1 MiB，二进制仅下载 | 防止超大配置/日志冻结编辑器 |
| 文件传输 | 全局最多 2 项活动；队列最多 20 项；64 KiB chunk、单 in-flight ACK | 无整文件 Buffer，进度至多 10Hz，默认总量上限 1 GiB/文件 |
| SSH 日志 | 复用 2 MiB/5000 行；最多一个可见日志源 | 数据按上限淘汰，有明确截断状态 |
| 数据查询 | 每数据源 1 个活动查询、全局最多 3 个；默认 15 秒截止 | 同时查询有界，取消后不启动替代查询直至旧查询收口 |
| 数据结果 | 每页 200 行、单次 1000 行/2 MiB；单值预览 64 KiB | 上限在驱动消费层生效，不在全量读完后截断 |
| Redis 扫描 | 每次至多 10 个 SCAN 回合、最多公开 200 Key、总回复 1 MiB | SCAN COUNT 只是提示；以实际字节/数量和非空 cursor 表达未扫描完 |
| 普通 Agent 输出 | 每次文本至多 64 KiB；媒体/文件另按授权读取 | 页面内容不会自动灌入模型，减少上下文和计费 |

首版传输在切换页签时可继续，但队列保留在当前 Pane；切换主机、关闭 Pane/窗口、显式断线时提示活动传输并提供继续停留/取消后离开，不默认升级为后台传输管理器。崩溃与连接消失时按恢复意图收口。数据库离开数据服务页即取消查询、关闭引擎连接与 SSH channel，保留非敏感 UI 筛选；SSH 主机连接和普通 Agent 本身不随之停止。

## 回归与交付证据

- 每阶段先补 BDD 正常路径及主要边界，再运行定向测试、全仓 typecheck、涉及 runtime/native 变化时的 Electron build。
- 正常连接、指纹变化、同 endpoint 多 Host、旧请求、双进程并发、退出中断、结果未知、审计故障和数据根不可用是跨模块验收项。
- UI 在真实 Electron 中验证窄/宽 Pane、深浅主题、键盘、空态、加载、失败和切换后首帧身份；测试不能仅依赖静态 JSX。
- Linux 固定测试主机覆盖普通账户、无 sudo、无 systemd、SFTP 扩展缺失、Docker 权限不足和数据库权限不足；实际操作只在独立 fixture 上执行。
- 30 分钟日志与传输压力验收记录 RSS、主进程事件循环延迟、打开的 socket/channel/fd 数量；目标为额外 RSS 不超过 120 MiB，释放后两分钟回到基线 +30 MiB，事件循环 p95 小于 50ms。超限必须记录原因并修复或重新评审预算，不能只以用例通过结案。
- 安装包单独确认 macOS arm64/x64、Windows x64、Linux x64 的 utility 启动、SSH fixture 和依赖完整性。构建成功不等于安装后可用。
- 本轮只写计划。上轮主工作区已有 389 项运维相关测试通过，其中两项 loopback 测试在解除本地监听限制后通过；这不是本轮新 worktree 的完整测试或三平台实机证据。
