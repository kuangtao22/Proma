# 数据库工作台布局设计

日期：2026-09-19。状态：用户已批准，客户端实施完成；实际改动与验证见 `../plans/2026-09-19-database-workbench-implementation.md`。下文保留方案形成时的现状评估，交互预览全部使用示例数据。

## 结论

保留现有「项目抽屉 → 项目连接 → 连接工作台」路径，在 MySQL 连接内使用三个一级入口：**数据浏览 / 运行诊断 / 实例参数**。默认进入数据浏览，先确定数据库，再选择表；宽工作区始终保留左侧表列表，右侧默认展示数据，并可切换结构、索引、属性。慢语句、会话和日志分别在运行诊断内提供独立页面。

为什么：用户的高频任务是找表、看数据、核对字段，当前「统计 / 表 / 诊断表」按返回结果形状分类，且点击表会替换整个目录，不能支持连续浏览。数据库运行参数、表属性和连接凭据分别属于实例、表、连接，必须有明确归属。

## 现状依据与方案取舍

- 参考图的持续表目录、数据网格、Data / Structure 和按需详情值得采用。固定第三栏会挤占 Proma 的 Agent 对话与数据网格，因此表属性放入当前表的「属性」页。
- 推荐方案：保留当前 Agent 右栏，工作区够宽时左右分栏，窄时把表目录收进可打开的覆盖层。上下文和选中表在布局变化时保留。
- 固定三栏方案适合独立数据库客户端，需要明显更大窗口；独立全屏数据库模块会改变当前聊天协作路径。两者均不作为此次默认布局。
- 当前右栏缺省 460px，实际可拖宽；当前运维连接头未提供自己的专注展开入口。方案新增的「展开工作台」是待实现能力，不能声称现有代码已经支持。

## 信息层级与动作归属

```text
项目抽屉（项目名 + 服务器 / 数据库 / Redis 计数）
└─ 项目连接列表
   └─ MySQL 连接
      ├─ 数据浏览（数据库范围）
      │  ├─ 选择数据库
      │  ├─ 表目录：搜索、数量、选中状态
      │  └─ 当前表：数据 / 结构 / 索引 / 属性
      ├─ 运行诊断（明确标记实例范围）
      │  ├─ 概览：现有指标、库容量、复制摘要
      │  ├─ 会话：当前可见连接及执行状态
      │  ├─ 慢语句：累计模板摘要
      │  └─ 日志：MySQL 原始日志，待接入
      └─ 实例参数：变量名、值、作用域，待接入完整读取
```

连接头仅显示一次「项目 › 连接」及地址，保留 MySQL 与内网明文等必要状态；详细用户名、凭据状态、跳板和 TLS 信息在连接设置中查看。右侧提供「展开/还原」及更多菜单，菜单收纳测试连接、连接设置、删除连接。测试和当前页面刷新语义独立：测试验证认证与可达性；刷新只刷新当前页面。测试按钮在连接设置弹窗底部靠左，取消、保存靠右，延续用户已确认的规则；密码沿用已有眼睛按钮能力。

「数据服务」不重新加入 SSH 页签。数据库连接不出现终端、文件、Docker 等 SSH 能力。项目抽屉保持项目层级，不塞库和表。

## 数据浏览

1. 进入连接只读取可见数据库目录。配置中的初始库仍可见时预选该库；否则显示「选择数据库」，不自动猜另一库。再次进入同一连接时，可恢复本会话内最后有效的库和表。
2. 库选择器放在数据浏览工具栏左侧；切库清空旧表身份、页码和旧结果，再读取所选库的表目录。失败时仍保留库选择器和重试入口。
3. 左侧只有该库的表目录、名称搜索、数量与目录刷新。表名搜索筛选已取得的目录，必须标注截断，不能把「已加载的 500 张」说成数据库总共 500 张。视图与普通表可用小图标区分，不虚构未接入的函数、过程等树节点。
4. 选择表后左侧列表继续存在，右侧标题显示表名，默认打开「数据」；结构、索引和属性都留在同一内容位置，切换不返回表列表。
5. 数据：网格、可横向滚动、固定列头、50 行/页和上一页/下一页。明确区分 SQL NULL、空字符串、二进制与文本截断；空表仍显示列头和「暂无记录」。估算行数写「约」，无主键时提示排序不保证稳定，不承诺分页一致快照。
6. 结构：字段名、类型、是否为空、主键、默认值、额外属性、注释。索引：名称、唯一性、按顺序排列的字段。属性：引擎、估算行数、已知容量、更新时间、注释；未知值显示「未知」，不能拿零代替。
7. 结构与索引复用同一份已有描述结果；属性优先复用表目录已有元数据。数据行读取独立，不能为了显示网格列名强制先加载完整索引。

本次先完成只读浏览。自由 SQL、行编辑、DDL、导出和服务端数据筛选各自需要真实执行合同，界面不放看似可用的空按钮。表目录搜索与全库记录查询须明确区分。

## 诊断、日志与参数

| 页面 | 展示与范围 | 当前能力与后续接入 |
| --- | --- | --- |
| 概览 | 实例快照、容量、复制摘要、采样时间 | 已有指标与表格可重组；当前为单次快照，不绘制无历史来源的趋势图 |
| 会话 | ID、用户、来源、库、命令、耗时、状态；按权限可见 | 已有，最多 50 条；当前不返回执行 SQL，也没有终止会话功能 |
| 慢语句 | 模板、执行次数、平均耗时、平均扫描行；累计摘要 | 已有 performance_schema digest，最多 20 条；不是原始慢日志，不能增加没有时间来源的「最近 24 小时」筛选 |
| 日志 | MySQL 慢日志、错误日志等原始记录 | 尚未接入。首期如保留入口，展示明确的未接入状态；后续只有已配置可信日志来源才读取，直连不等于有主机文件权限 |
| 实例参数 | 名称、当前值、作用域、名称搜索；只读 | 当前只为诊断读取 max_connections，不等于支持完整参数页；后续新增有界变量目录读取，兼容 MySQL 5.7 |

诊断默认明确显示「实例范围」，不受数据浏览中的库选择器隐式过滤。部分权限不足只影响对应页面或指标，并给出实际原因；比如复制状态不可读不妨碍数据、结构和慢语句。Redis 继续用自己的 INFO、Keyspace 和 SLOWLOG 语义，不能把 MySQL digest 和 Redis 慢日志混成同一合同，Redis 不出现表结构页。

连接设置与实例参数严格分开：地址、端口、登录账号、密码、TLS、跳板属于连接设置；max_connections、sql_mode 等才属于数据库实例参数。

## 宽窄布局与键盘

- 工作区内容宽度达到 720px：左侧表目录默认 190px（可调整 160–240px），右侧占满余宽，目录与网格独立滚动。
- 小于 720px：表目录收起为工具栏「表目录」按钮；打开覆盖当前工作区，选中表或按 Esc 后关闭并恢复入口焦点，网格保留全部可用宽度。320px、460px 和双 Pane 都必须可用。
- 「展开工作台」临时占用应用可用内容区，退出后恢复原宽度与聊天位置，不重挂载数据控制器、不清空库、表、页码和已加载结果。复用既有 Canvas 展开时的标题栏安全区与层叠规则，动作作用于发起 Pane。
- 行为使用现有 Radix Tabs、Select/Popover、DropdownMenu 和 Dialog；方向键、Enter、Esc 与焦点恢复完整可用。菜单 Portal 的层级高于右栏和展开宿主。
- 应用外壳不整体滚动：身份头、一级导航、目录工具栏、表标题和分页固定在各自容器边界；只有列表和网格滚动。

## 请求生命周期与资源

库表浏览与诊断分别拥有加载、失败、最近成功时间和当前请求身份，页面导航始终可用。首读失败给当前区域错误和重试；同一目标刷新失败保留最近成功结果并标注旧数据；切库、换连接后禁止显示上一目标正文。

现有诊断是一次顺序读取全套数据，不能仅通过拆页面声称已经懒加载。实施分两步：先完成正确的信息层级与表浏览，再增加按诊断类别读取的完整 shared → main → preload → runtime → renderer 合同。切到哪个页面才请求对应数据；不新增全库后台轮询，不预读每张表内容。

读取身份包括连接 ID、有效连接配置版本、数据库、表、页码与模式；纯标题、布局和无关 SSH 状态变化不使请求失效。StrictMode 的 setup / cleanup / setup、快速切换、重复刷新和 BUSY 必须有可验证的收口规则；共享在途请求或等待真实清理后重读，不能恢复一个已失去所有者的 running 状态。关闭连接工作台后回收其请求订阅和缓存，迟到结果不得写回新的目标。

表数据只缓存当前页及少量最近目标，配置身份变化立即失效；不持久化业务行和密码到布局状态。延续现有全局并发预算及超时，补齐结果字节预算与请求终态，不增加新依赖。目录和结构的重复请求可去重，禁止无限自动重试。

## 关联模块影响

- 界面实施重点位于 ServerOpsDataConnectionView、ServerOpsDataServicesPanel、ServerOpsSchemaBrowser；从连接管理容器中分离浏览与诊断职责，避免继续扩充一个大组件。
- 顶层 ServerOpsWorkspace 只负责项目/连接导航与传输离开守卫；SSH 终端、文件、Docker 的生命周期不跟随数据库子页变化。
- 视图选择用 Jotai 保存轻量会话状态，权限与真实连接事实仍由现有主进程服务管理。
- Agent 项目授权迁移、项目 CRUD、跨项目跳板、新建连接归属属于原项目制计划的剩余工作，不借布局调整改变其安全含义。
- 读取审计目前尚未实现，本方案不能把现有 SSH 审计描述为数据库查询审计。
