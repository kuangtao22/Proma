🧱 作用域是什么 回答你的第 1 个问题
工作区级不是"每个接口一份"，而是整个项目共用的那一份：这个 workspace 下所有集合、所有接口都能用，改一次全体生效。适合放公司级固定值。
集合级只在某个集合内生效，例如「后台接口」专用的签名参数。
环境级同一个变量名在不同环境各存一份值，例如 baseUrl 测试是 127.0.0.1，生产是真实域名。
接口级接口本身不存值，只存「用哪套方案」+ 可选的覆盖项；需要时覆盖工作区/集合/环境里的值。

取值顺序：接口覆盖 → 运行时变量 → 环境 → 集合 → 工作区。接口里会显示"这个值最终来自哪一层"。

📋 与 Postman 的对照
  • 照抄：「列表页 + 表格内联编辑 + 批量编辑（粘贴 key=value）+ 作用域分层 + 继承」这套交互，它是被验证过最快的批量维护方式。
  • 照抄：变量、请求头、参数、鉴权、加解密都放在同一个管理入口下，用页签切列表，而不是散落在各个请求里。
  • 不照抄双值：Postman 的 Initial / Current 两列是为了在会话里临时改值，代价是两处都可能明文；我们只保留一个「当前值」，要临时换值用「本次运行覆盖」。
  • 不照抄脚本：Postman 用 Pre-request Script 做签名，灵活但不可审计；我们用声明式步骤，Agent 也改不了方案本身。
  • 改进继承：Postman 的 Globals 与 Environments 是两套；我们统一成「作用域」一列（工作区 / 环境 / 集合），并在接口上显示实际生效来源。

  • 密钥明文可见（你确认）。管理列表与方案里直接显示值，👁 可一键切回遮蔽；不进运行记录、日志与导出快照。代价：截屏、录屏、远程协助会连密钥一起被看到，所以我建议生产环境的秘密默认保持遮蔽（要不要也默认明文，见页脚待确认）。
  • 方案公共、选择私有。算法与模板是系统级约定，按接口复制一定会漂移；接口只保存「用哪一套」，改一处全体生效。
  • 顺序就是语义。签名签明文还是密文取决于它在加密前/后，所以方案里用编号显式排序。
  • 缺密钥绝不阻断（你确认，理由成立）。本地无法判断服务端到底验不验签名——如果生产的服务端本来不需要密钥，阻断就等于"永远发不出去"。所以缺哪一步就跳过哪一步、照常发出去、返回什么显示什么；代价用可见性补，不用阻断补：请求状态条、运行记录、Agent 审批卡三处都标「本次未签名/未加密」，运行历史可按「明文发出」筛选，避免"以为加密了其实发的明文"。
  • 不做任意 JS 脚本。脚本能读凭据、能出网、Agent 也能改，声明式步骤可审计、可 diff。
  • Agent 不越界。Agent 只能选方案；要新建或修改方案，必须单独走一次审批并展示影响面。
